# Qt Quick Test 行为与隔离检查

只读取与被测行为有关的部分。Qt 版本或接口不确定时查 [TestCase 官方文档](https://doc.qt.io/qt-6/qml-qttest-testcase.html)，同时核对项目实际版本。

## 创建和输入

- `createTemporaryObject()` 的父项应是适合当前测试的可见宿主；交互控件还需有效尺寸。测试根项/宿主是否可见应实际确认。
- 对鼠标、焦点或渲染相关测试等待 `windowShown` 及必要的布局完成；纯非视觉行为不机械套用等待窗口。
- Window/ApplicationWindow 作为独立窗口测试，按需显示、关闭并清理，不按普通 Item 假设父子布局。
- 测试输入协议时使用鼠标和键盘事件；测试解析、校验或绑定时可以设置属性。直接设置 text 不等价于完整输入法或键盘流程。
- TapHandler 等事件处理器由其宿主接收输入；直接发射信号只测试监听方，不能证明手势识别正常。
- 真实 focus、有效尺寸、enabled/visible 状态不成立时，先修正测试装配，不单纯增加超时。

## 异步与信号

- 动作前设置 SignalSpy 的 target 和 signalName，确认有效并清空历史计数；之后核实次数与参数。
- 同步信号可能在调用返回前发出；不要事后才开始等待从而漏掉已发生的事件。
- `tryCompare`/`tryVerify` 用于最终状态，超时根据被测操作给定；固定 `wait()` 不能证明操作完成。
- 恰好一次的契约要考虑观察区间与后续重复事件，不在首次命中时就草率认定不会重复。
- 动画、网络替身和排队调用考虑取消、销毁和迟到结果。测试时钟或时间源能注入时优先使用项目既有机制。

## 状态、列表与接口

- 改变输入驱动真实状态机，检查进入、退出和恢复；活动 State 可能覆盖原属性绑定。
- 列表覆盖空数据、删除、排序、复用后的目标一致性，重点验证业务标识，不能只断言某个行号。
- 公开属性和信号可以成为测试契约；`currentIndex` 等状态并非禁测，取决于组件对外承诺。
- QML `id` 不能作为跨文件对象查找入口；`findChild` 使用非空 objectName 并检查结果存在。
- 若必须加入测试入口，优先最小且稳定的接口；先判断现有输入和可观察结果能否完成测试。

## 隔离与有效性

- 单例在同一引擎内跨用例共享，需要恢复状态或使用合适的引擎隔离。
- Settings、数据库和文件服务使用测试专用位置；组织/应用标识和路径应在依赖创建前设定。
- 日期、时区、语言及区域格式用显式条件构造；测试本地化时覆盖目标 locale，不把某一种格式当所有环境的默认。
- 依赖缺失时补测试装配或明确未覆盖范围，不静默删除关键断言以换取通过。
- 不断言“刚赋值的属性等于刚赋的值”来充数；断言派生行为、边界处理和可观察副作用。
- 仅创建成功的冒烟测试不能替代交互或回归测试。
