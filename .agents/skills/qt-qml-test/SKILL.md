# Qt Quick Test 编写与执行

先读取适用的 `AGENTS.md`、相关测试和构建入口。测试目录、无显示环境、持久化隔离与构建目录以项目规则为准。本 skill 合并原 `qt-qml-test-run` 能力。

## 选择任务路径

- 只运行测试：直接发现并使用已有入口，不重写测试，不新增框架。
- 补回归测试：从缺陷的外部可观察行为出发，复用相邻测试的装配方式。
- 新组件测试：选择有业务价值的交互、边界或状态变化，不枚举每个属性生成机械断言。
- 排查失败：先区分构建、导入、测试装配、断言和环境错误，再定位原因。
- 用户要求代码示例时可在回复中给出；要求仓库修改时写入指定或现有测试文件，不机械新建同名副本。

## 写测试的关键边界

- 使用真实模块 URI、路径和依赖，不猜类型名、上下文对象或测试目标名。
- required 属性和服务依赖在创建时提供；使用隔离的替身或项目测试装配，不写入真实用户数据。
- 同步行为可直接断言，异步行为等待可观察条件，不用固定休眠掩盖时序问题。
- `SignalSpy` 在动作前接入有效目标并清理旧计数；验证真实动作产生的信号和载荷。
- 输入测试等待场景就绪，给被测控件可见的父项和有效尺寸；不要直接调用信号来假装用户交互。
- 优先测试公开接口。必须访问子项时使用已有稳定入口；不为测试任意暴露大量内部对象。
- 每个用例恢复状态、销毁临时对象；单例、时间、语言环境和持久化依赖需要显式隔离。

涉及焦点、Window、单例、信号或状态覆盖时，读取 [行为与隔离检查](references/qt-quick-test-patterns.md)。

## 运行与诊断

1. 查找实际测试目标、注册方式和使用的 Qt 安装，优先已有 CTest/测试二进制及其环境设置。
2. 需要构建时仅构建相关目标；构建失败不能继续拿旧二进制声称通过。
3. 没有测试入口时，能解析所有依赖的纯 QML 测试可直接运行 qmltestrunner；否则先分析所需装配。
4. 用户已要求补测试或修复测试基础设施时，在授权范围内做最小接线，不重复询问模板式确认。
5. 单纯“运行测试”不授权为方便运行而重构应用模块。无法运行时报告具体阻碍和最小所需改动。
6. 选择相关用例，执行并保留退出码；同时检查是否确实发现并运行了预期测试。

导入、静态插件、QApplication、命令和 JUnit 解析见 [执行与诊断](references/qt-quick-test-running.md)。

## 输出与停止条件

- 默认在回复中给出通过/失败/跳过数量、相关失败与验证限制；不强制每轮生成 Markdown 报告。
- 需要逐用例结果时保存 JUnit 并调用保留的 [解析脚本](references/scripts/parse-qmltestrunner-output.py)。
- 解析器成功只说明报告已解析，不等于测试通过；以用例结果、实际执行范围和退出状态共同判断。
- 零用例、缺失报告、环境崩溃和部分执行都不能标成全部通过。
- 比较前后结果需要同一测试范围和可比环境。修改时间只能帮助定位文件，不能证明回归或归因。
- 合适的相关检查通过后停止，不为简单改动追加全仓测试或重复验证。
