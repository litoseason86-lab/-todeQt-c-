# Qt C++ 专业检查点

这些是核实方向，不是见到某个语法就判错的规则。扫描器保留上游规则编号，但其样式告警不具有缺陷裁决权。

## 模型与 QML

- 插入、删除、移动、重置使用匹配的模型通知；begin/end 之间实际存储变化与声明区间一致，错误分支也不能破坏配对。
- 空集合避免非法的首尾范围；树模型的 parent、行列数、索引归属和持久索引保持一致。
- 数据实际改变后发出必要的 `dataChanged`。空角色列表表示全部角色变化，是合法行为；精确角色有助于减少刷新。
- `setData()` 对未改变的值如何返回由接口契约决定，不能仅凭返回 true 而未发信号就判错。
- `roleNames()` 与 `data()`、编辑能力及 QML 消费者一致；代理模型正确映射源索引。
- QML 属性有正确的通知或绑定机制，变化只在状态成立后暴露，避免通知触发重入时读取半更新状态。

## 所有权与生命周期

- 明确唯一销毁责任：QObject 父子关系、智能指针或手动管理都可成立，混用时防止双重释放。
- QObject 父对象会销毁其子对象；不要机械要求析构函数再次递归清理。
- 排队 lambda、网络完成回调和延迟任务可能晚于接收方销毁。核实上下文对象、取消机制及悬空捕获。
- `QPointer` 能观察 QObject 销毁，但不能自动保证跨线程访问安全。
- `deleteLater()` 依赖事件循环与线程退出时机。网络回复要覆盖成功、失败和取消路径，并核对是否已有自动删除机制。
- `Q_ASSERT` 在发布构建可能不执行，不能把必要副作用或外部输入验证放进去。

## 线程与重入

- GUI 相关对象以及被 GUI 使用的模型在其所属线程操作；跨线程结果通过合适的投递机制交付。
- 直接连接在发射信号的线程执行。判断接收逻辑是否线程安全，不把所有直接连接一概禁止。
- QObject 有线程归属不等于其成员自动同步；共享容器和状态的所有访问路径必须遵守同一同步协议。
- 检查锁内发信号、阻塞排队连接、析构等待线程形成的死锁和重入。
- 取消后迟到的结果不能覆盖新请求；线程退出前处理对象释放与挂起任务。

## 错误与持久化

- 检查打开、读取、写入、提交和解析结果；区分“有效空值”与失败。
- 数据库迁移和批量操作考虑失败回滚、重复执行及旧格式兼容；不能只检查最后一次调用。
- JSON 等外部输入检查类型、范围、版本和必要字段；使用实际解析错误解释失败。
- 网络超时、取消与错误必须有明确上层语义；是否需要 TLS、大小限制等由数据和协议边界决定。
- 用户可见的成功状态必须与提交结果一致，跨层错误不静默丢失。

## 性能与接口

- 热路径检查重复解析、容器意外复制、缓存失效、重复信号和主线程阻塞；没有频率或规模证据时标为假设。
- 隐式共享容器的非 const 访问可能触发分离；仅把循环元素写成 `const auto &` 不一定避免容器分离。
- 对外接口变化核对调用方和二进制兼容需求；应用内部接口不照搬 Qt 库发布规范。
- 涉及 Qt 框架本体时再读 [框架边界](qt-framework-checklist.md)。涉及废弃 API 时再读 [API 核实](qt-deprecated-classes.md)。
