# Qt 桌面界面设计

读取适用的 `AGENTS.md`，以现有 Theme、组件库、导航和交互为基准。只补充当前任务缺失的设计决策，不为小改动重新调查整套产品需求。

## 工作范围

- 局部样式：只检查相关令牌、布局、状态和可读性。
- 新组件或新页面：确认入口、主要操作、反馈、退出方式和组件职责。
- 界面审查：给出具体触发情境和用户影响，不把个人审美偏好升级为缺陷。
- 当前代码足以确定尺寸、平台和输入方式时直接沿用。只询问会改变实现且无法推断的信息。

## 视觉与组件边界

- 复用 Theme 的语义颜色、间距和字体角色，缺失令牌按项目机制补充。
- 复用现有 Qt Quick Controls 和业务组件；页面编排、通用控件和后端状态分开。
- 字号、密度、圆角和动效应与现有应用协调，不强制套用固定字号、比例或统一动画时长。
- 主操作、危险操作、选中、禁用、加载和错误应有清楚区别；颜色以外还要有文字、图标或形状线索。
- 玻璃效果及技术栈约束以 `AGENTS.md` 为准；涉及光学效果时再读取 `liquid-glass` 的相关原理。

## 交互检查

- 鼠标与键盘都能完成主要操作；焦点可见、顺序合理，弹窗可退出且关闭后焦点回到合理位置。
- 自定义控件保留可访问名称与角色；图标按钮有明确的可访问名称，不能仅靠悬停猜用途。
- 删除、提交和加载反馈应对应真实后端状态，避免乐观提示成功后悄悄失败。
- 防止重复提交；耗时操作提供与任务相称的忙碌状态，按需支持取消或重试。
- 空列表、加载、错误和无结果是不同状态，不共用含混提示。

## 布局与显示检查

- 检查目标窗口范围、长标题、多行内容和系统字体缩放；不要用截断隐藏必要信息。
- 浅色、深色和禁用状态分别确认文字、图标、输入边界与焦点可见。
- 不把触屏尺寸规则直接套到鼠标桌面，但交互目标仍要足够容易命中。
- 若涉及本地化，检查格式化、文本扩展；仅在目标语言需要时检查从右到左布局。
- 动效表达状态关系并支持项目的 `reduceMotion`；不可见页面不持续执行无用效果。

## 验证与交付

- 按修改范围验证交互、主题和布局；沿用项目规定的后台测试环境及人工视觉验收边界。
- 未实际查看运行界面时，明确只完成静态或无显示验证，不声称视觉通过。
- 局部修改简述结果；审查按影响排序，附组件位置、触发方式和修正建议。无需固定报告模板。
