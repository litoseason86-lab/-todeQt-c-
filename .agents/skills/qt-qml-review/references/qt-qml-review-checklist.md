# QML 专业审查检查点

按变更范围选用。扫描器中的 IMP、ORD、BND、LAY、LDR、DEL、STA、PRF 等规则是定位线索，不能仅凭编号定罪。

## 绑定与跨层通知

- 追踪绑定的输入、命令式写入和后续更新；区分有意断开绑定与意外丢失响应。
- 检查父子尺寸、状态守卫、C++ 通知形成的多步循环，说明循环的完整路径。
- 动态对象引用可空，跨组件隐式上下文可能因重构失效；确认实际创建上下文。
- `var`、版本化 import 和普通函数并非自动错误；检查是否真的造成类型或依赖更新问题。

## 布局

- 查父 Layout 管理的子项是否又用冲突的 anchors/尺寸写入争夺几何控制。
- Layout 本身锚定外层容器是正常用法；不能把任何 anchors 与 Layout 同时出现都判错。
- 检查隐式尺寸与父容器尺寸循环、不可见项残留间距、长文本和最小窗口范围。
- 跨层 anchors 是否指向合法的父或兄弟项，不能仅凭字符串模式判断树关系。

## 加载与连接

- Loader inactive/loading/error 时 item 不可用；卸载和替换后旧引用不能继续使用。
- 动态创建检查错误、所有权和销毁；合法的动态组件 API 不应一律禁止。
- 重复创建、目标切换和信号重连可能叠加回调；验证 `Connections` 或手动连接的实际生命周期。
- 回调执行时核实请求版本和目标对象仍有效。

## 委托与数据

- 使用 required 属性时角色和 index 是否明确提供；QML/C++ 模型的角色名字是否一致。
- 复用委托的计时器、编辑状态、动画与加载结果是否重置，数据切换后是否继续使用旧行号。
- 存储选择或编辑目标应依赖稳定业务标识，检查排序、过滤、删除后的行为。
- 委托 parent 可能是视图内部容器；需要视图本身时使用显式引用或附加属性。

## 状态、焦点与性能

- State/Transition 的进入和退出均能恢复绑定与输入；宽泛过渡本身不是缺陷，要指出误触发条件。
- 透明与不可见具有不同交互及执行语义，核对隐藏内容是否仍可操作或继续后台工作。
- 纹理、模糊、图片解码和委托创建是否在真实热路径；普通裁剪不等于必然离屏渲染。
- 不通过静态代码推断具体帧率。用户要查卡顿时才转入性能采集流程。
- 焦点、可访问名称和主题问题按项目界面约束核实，不扩展为全站式设计审计。

## 工具边界

优先使用项目已有 qmllint 目标或已配置的 import 路径。类型缺失可能是扫描环境未配置，须与运行时缺陷区分。
针对局部文件使用 qmllint 前查看当前版本帮助，不盲目复制其他版本命令选项。
