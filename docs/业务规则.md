# 当前业务规则

本文记录当前实现必须保持的业务边界与跨层约定。功能总览见 [README](../README.md)，构建和测试见 [运行命令](运行命令.md)，待办与未采纳决策见 [计划索引](../plans/README.md)。

## 专注、日期与任务

- 专注规则统一定义在 `src/services/FocusSessionRules.h`：单段有效门槛为 3 分钟；`validPomodoroCountExpr` 只计番茄模式自然到点的有效记录，`focusedSecondsExpr` 累计两种模式的有效时长。自由计时不折算番茄数。
- 任务预计用时与今日专注目标以分钟计量；输入共用 `DurationFieldPair.qml`，格式化共用 `qml/Duration.js`。时长输入里空框按 0 算（填了 1 小时就不必再去分钟框补 0），但不能靠留空把总时长变成 0——「0 小时 + 空分钟」「两框全空」一律拦下，归零必须明确输入 0。差别在于用户能不能看出自己干了什么：留空静默存成 0 会把已设好的预计用时抹掉，而他可能只是清空准备重打。任务实际投入从专注记录派生，达到预计用时可自动完成任务。
- 专注与任务归属使用逻辑日，默认从凌晨 4 点开始。日期计算统一走 `LogicalDay`；QML 必须在日界变化时更新可观察的日期状态，不能依赖 `new Date()` 自动触发绑定重算。课表使用自然星期，不套用专注记账日期。
- 今日任务按完成状态、当天 `display_order`、创建时间、编号稳定排序。新建、结转和改期任务追加到目标日末尾；重排必须提交当天完整任务集合，不能重复或漏项。拖动期间保持模型稳定，松手后再写入顺序。
- 每日例行生成必须幂等，不重复生成，不补齐所有历史日期；当天删除过的实例不能因刷新而复活。
- 例行的重复日是一周七天的位掩码，口径统一在 `src/services/RoutineRules.h`（第 0 位周一 … 第 6 位周日，与课表同一套星期编号）。掩码至少要选中一天，`0` 和越界值库层 CHECK 与服务层校验都拒绝；旧库升级按「每天」回落，生成行为与升级前一致。星期按逻辑日取，凌晨日界点前仍算前一天那一档。今天不命中重复日的例行既不生成任务，也不写生成戳——写了的话它真正该出现的那天会被当成已生成而跳过。改重复日只影响之后的生成，不回收也不补发已经生成的任务。
- 例行的「标题/科目」和「重复日」是两个入口、两条独立写入：`updateRoutine` 只写标题与科目，`setRoutineWeekdays` 只写重复日（与 `setRoutineActive` 同形）。合成一条覆盖写的语句时，少传一个参数就会把用户设好的「周一三五」静默改回「每天」。新增表单不设星期控件，一律按「每天」落地，之后在列表行上那七个点（一周，左起周一）里点开改；星期的位掩码与中文文案统一在 `qml/RoutineWeekdays.js`（与 C++ 的 `RoutineRules.h` 同一口径）。
- 任务入口（今日任务、本周计划、仪表盘）的“开始专注”由设置「快速开始」（`focus/quickStartEnabled`）分流：默认关闭（升级用户同样关闭），只进入专注页待机，预选上次的模式，番茄模式展开时长面板，由用户确认后点开始；开启则按上次模式直接启动。专注页的开始按钮与 ⌘↩、全局热键不受这个开关影响。点击正在计时的同一任务只回到当前计时，不看记住的模式。切换活动任务先确认，保存失败不动原计时；超长自由专注仍需核对时长。
- 计时中（含暂停和休息段）在专注页切换模式：确认结束当前计时后停在新模式的待机，番茄模式展开时长面板，必须再点开始；即使开着快速开始也不自动启动。确认框按意图区分文案：「结束并开始」只用于快速开始的任务切换，其余都是「结束并切换」并注明不会自动开始。
- 任务编辑支持 2000–2100 年的任意有效日期；日期输入回查年月日，拒绝 JavaScript 自动进位产生的伪日期。批量改期在一个事务内校验全部编号，失败整批回滚；已在目标日期的任务保持排序。
- 搜索覆盖全部日期的标题、备注和科目，可筛选完成状态；结果分批加载，最多显示 10000 条并提示缩小范围。搜索或筛选变化会清空批量选择，待撤销删除的任务不出现在结果中；任务本身变化时保留勾选，只丢掉已不在结果里的编号。
- 逾期结转只回看最近 7 天（`TaskManager::kOverdueRolloverDays`）：日期在「逻辑今天往前 7 天」到昨天之间、还没做完的任务才出现在今日页的结转提示条里，提示条写明「最近 7 天还有 N 个未完成任务」。更早的视为放弃追踪，但不删、不改：任务原样留在原日期，历史统计照旧，任务工具里仍能搜到并手动改期。不设窗口时实测攒到 41 条，其中 39 条是一个多月前每天一条的背词任务。
- 批量改期的「选择逾期」沿用逾期口径（同样只回看最近 7 天），排除例行生成的实例——它们不参与结转，搬到今天会和当天新生成的实例重复。
- 任务备注上限 `TaskManager::kMaxNotesLength`（2000 字，经 `maxNotesLength` 暴露给 QML）。超长一律拒绝、不截断：服务端新建返回 -1、编辑返回 false 且不留痕迹；新建与编辑弹窗提交前当场拦下并指明是备注，接近上限时显示字数。曾经 `left(2000)` 截断后照常报成功，用户重新打开才发现末尾没了。
- 完成记录（`tasks.completion_note`，schema v16）是做完之后写的「这次具体完成了什么」，与做之前写的备注分两列存，互不覆盖。今日任务页与仪表盘任务面板的任务卡上都有「完成」按钮（仪表盘「已完成」筛选下的只读紧凑行没有），点开完成弹窗，`TaskManager::completeTaskWithNote` 用同一条 UPDATE 标记完成并写入记录，不会出现「完成了但记录没存上」；记录可以不写，长度上限与备注共用 `kMaxNotesLength`，超长拒绝、不截断。左侧复选框仍是一步完成，不弹窗。完成弹窗与复选框共用同一套完成动画延迟刷新和撤销条；写库失败时弹窗留着、草稿不动，行也不会先画成已完成。
- 取消完成（包括撤销条）只改 `completed`，完成记录保留：未完成的卡片不显示它，再次完成时弹窗预填回来，免得一次误触就丢掉刚写的内容。已完成任务的记录在编辑弹窗的「完成记录」栏里改；七参 `updateTask` 只在第 7 个参数是字符串时写入（空串 = 清空），QML 传 `undefined`/`null` 表示保持不变，四个编辑宿主必须把它原样转交、不能用 `String()` 包一层。重命名、六参保存和外部 AI 接入都不碰这一列；外部 AI 接入目前也读不到它。
- 复制任务只复制标题、科目、预计用时和备注，不复制完成状态、完成记录、计时记录或例行生成标记。连续录入保留日期、科目、预计用时，成功后清空本条内容，失败保留草稿。
- 手动补录记为自由计时。新增和修改都拒绝未来时间、重叠区间、低于有效门槛的记录；不能修改正在进行的会话。
- 补录与修改的任务候选按与所选日期的距离排序并限量；被编辑记录的原归属任务始终出现在候选中，否则保存会把它静默改成未关联。

- 专注与休息记录均支持撤销删除和纠正类型；专注记录还可修改任务归属；休息转专注不能伪造已完成番茄。只提交实际改动的字段，不改时间时保留原始秒数、毫秒和暂停跨度。
- 专注与休息记录共同参与区间冲突校验，包含正在进行的计时；两个表的编号独立，编辑和删除必须同时携带记录类型。历史变化由装配层通知任务和目标刷新。
- 休息（含进行中的休息）按「起点 + 实际计时」占用时间线，不按区间两端：暂停和关机时段并没有在休息，按区间算会让一次忘记结束的休息挡住整段时间的补录。
- 只改归属或类型、区间没有变化时不重跑重叠校验；否则历史遗留的重叠会让用户连纠正归属都做不到。休息转专注会把占用放大到整段区间，仍要重新校验。
- 删除暂缓提交并提供撤销。新的删除、替换提示、手动备份、恢复、退出，以及补录或修改记录之前，先提交待删除项：撤销窗口内记录仍在库里，不先落库就写入会撞上用户已经看不见的那条记录的时间段。提前提交后要收起属于这次删除的撤销条（`Toast.dismissAction`，只收起当前挂着的正是这个回调时）：否则用户点「撤销」提示条照常消失，看起来像撤销成功，记录却已永久删除。

### 主动休息与超长自由专注

- 主动休息入口位于今日任务页，仅在计时器空闲时可开始。它与番茄休息是不同阶段，均不写 `focus_sessions`，不增加番茄数与今日专注。
- 主动休息与番茄休息结束后写入独立的 `rest_sessions`，出现在今日专注时间轴，但不进入专注时长和次数统计。结束点按「起点 + 实际计时」写入，暂停与关机时段不算休息。
- 主动休息支持暂停、继续和结束；重启后只恢复为暂停状态，不把离线经过时间补入计时。结束后返回今日任务页。
- 自由专注超过提醒阈值时，结束前确认记录或丢弃，并可向下修正时长。未编辑时保留原始秒数；编辑后按整分钟处理，最少 3 分钟，不能超过实际计时时长。前端与服务层都校验。
- 「结束」在所有入口同口径：专注页按钮、仪表盘面板、菜单栏、快捷键与全局热键都走 `FocusView` 的 `endPomodoro` / `endFreeFocus` / `endManualRest`，不能各自直接调 `stopFocus()`——仪表盘面板曾这样绕过超长确认。需要确认时切到专注页（弹窗在那里）；仪表盘上不需要确认的结束留在仪表盘，失败转成提示条，「结束后回今日页」只针对从专注页结束。
- 修正记录的结束时间必须等于开始时间加修正时长，避免区间与时长矛盾，阻挡后续补录。番茄合盖跨过到点、时长被截成目标时同理：结束时刻取到点那一刻（现在往回推被截掉的超额），不是唤醒时刻。所有专注记录的结束时刻都不早于「开始 + 时长」：时长来自单调时钟，起止是墙钟，计时中把系统时钟往回拨会写出倒置区间。保存失败时保留当前会话供重试。

## 课表

- `schedule_entries` 与 `schedule_periods` 独立于任务和例行任务。课表按星期、时段、周次范围及单双周循环，没有完成状态，不生成任务，不接专注计时，不参与统计与目标进度。
- 服务层负责存储、给定周次的查询和冲突判断；`qml/ScheduleWeeks.js` 负责日期与学期周次换算，避免服务层依赖界面设置。
- 时间轴按真实时长排布，节次模式按等高节次排布，两者共用起止分钟数。冲突必须同时具备时间重叠和实际共同生效周；仅周次范围交叠还不够。
- 周次范围被单双周规则完全排除时拒绝保存。视觉泳道按显示区间分配，短块放大或映射到节次后也不能互相盖住；未落入节次或被周末开关隐藏的条目要明确提示。
- 课表设置先校验全部输入，再保存节次、批量同步学期设置；设置写入失败时补偿回滚旧节次，回滚失败单独报告。这是数据库与设置文件之间的补偿流程，不是跨文件原子事务。
- QSettings 写入失败必须恢复旧缓存及原先不存在的键，不能仅重建对象；成功落盘后才发成功变更信号，失败后允许重试。读取失败不能伪装为空列表。

## 知识缺口

- `knowledge_gaps` 与 `tasks` 的分界只有一条：任务必须有日期（`tasks.date` 是 `NOT NULL`），而知识缺口的常态是「现在还定不了什么时候处理」，所以 `due_date` 允许为空。这条差别是这个实体存在的全部理由，不能为了「统一」把它并回任务。
- 知识缺口不接专注计时，不写 `focus_sessions`、`rest_sessions`，不计番茄数与今日专注，也不进统计页。要专注就先 `convertToTask` 生成任务，再从任务启动——专注口径只有 `FocusSessionRules` 一份。
- 捕获入口必须是非模态、不影响计时的 `Popup`，只收一行标题，不追问日期、优先级和科目。专注页那个入口带来源任务与其科目；今日任务页的入口没有「当前任务」概念，不带来源。捕获一旦需要停计时或多做一次决策，这个功能就等于不存在。
- `source_task_title` 是写入时的快照。外键为 `ON DELETE SET NULL`，任务删除后编号变空，但来源文字必须保留——它属于记录当时的现场，与 `focus_sessions` 存科目快照同理。
- `detail`（当时遇到了什么）与 `resolution`（后来想明白了什么）分列存储，不能合并。三个文本列都是 `NOT NULL`：空 `QString` 绑定会写成 SQL NULL，所有写入路径必须先收敛成空串。
- 状态由到期日派生：有 `due_date` 即「已安排」，没有即「待处理」；`resolveGap` 显式置「已解决」。编辑一条已解决的记录不重新打开它，重新打开必须是显式动作；`reopenGap` 清 `resolved_at`、保留 `resolution`；重复解决不覆盖首次 `resolved_at`。已解决的条目拒绝排期与转任务。
- 逾期不自动顺延。任务有结转，知识缺口没有：把 `due_date` 推到今天会抹掉「这条拖了多久」，而拖了多久正是判断该不该立刻停下来处理它的唯一依据。逾期条目保持原日期，界面显示已逾期天数。转任务同样不能把它清零：`convertToTask` 的到期日取原到期日与任务日期中较早的一个——已逾期的保持原日期，未排期的补成任务日期（状态由到期日派生），排在以后的提前到任务日期。
- 关联任务完成不自动解决缺口。做完任务完全可能还是没搞懂，服务只报 `linkedTaskCompleted` 这个事实，由用户决定是否标记已解决。
- 排序不变量：已解决沉到最后，其余按到期日从早到晚、未排期沉到已排期之后，再按优先级高到低与创建时间兜底。第一个排序项是 `(status = 2)` 而不是 `status ASC`——后者会把全部未排期条目顶到已排期前面。
- 「今天」「逾期」的判定一律走逻辑日，由 `getReminderSummary` 在服务层算好；QML 不自己比日期，并在日界或 `dayStartHour` 变化时重查。提醒摘要区分「读取失败」与「确实没有待办」，失败时提示条保持安静。`dueToday`、`overdue`、`oldestOverdueDays` 不计已有没做完关联任务的条目：它们已经作为任务出现在今日页，再催只会诱导重复转任务；关联任务做完而条目仍未解决时重新计入。
- `convertToTask` 在一个事务内完成查现状、建任务、置已安排、记 `linked_task_id`；任一步失败整体回滚，缺口状态原样不动。已有没做完的关联任务时拒绝再转，不建重复任务、不改写关联——按 JOIN 到的任务行判断，编号悬空视同没有关联；关联任务做完而条目仍未解决时允许再转。列表行的 `linkedTaskOpen` 与这条拒绝条件同一口径：清单页据此禁用「今天做」，今日页批量转任务据此跳过。`display_order` 取当天最大值 +1，与 `TaskManager::addTask` 一致。批量改期同样整批校验、整批回滚。
- 今日页「全部加到今天」的失败条目单独提示数量与原因（`knowledgeGapConvertError`），不能只报成功数量，也不能挂在 `loadError` 上：部分成功会触发任务列表刷新，刷新成功就清掉 `loadError`。提示条安静下来时一并清空。
- 知识缺口弹窗每次打开与收到 `categoriesChanged` 时重查科目；选中的科目已被删除就退回「不指定」，否则保存会撞外键。
- 事务内语句失败后必须先 `finish()` 再 `rollback()`。仍然打开的 statement 会让 SQLite 继续持有表锁，之后的迁移与备份 `VACUUM INTO` 会以「database table is locked」失败，而现场早已离开出错的地方。
- 删除采用二次确认，不接入撤销窗口。撤销窗口带着「备份、恢复、退出、补录之前必须先提交待删除项」这条硬约束，多接一个域就多一处会漏掉的 flush。
- 知识缺口是 schema v14 新增表，走 `user_version` 迁移链而不是 `rest_sessions` 那种「不升版本、每次幂等建表」的做法：后者在恢复不含该表的旧备份时会建出空表，把数据丢失伪装成恢复成功。备份校验只对 v14 及以后的备份要求这张表存在，更早的备份允许缺失，由恢复后的迁移补齐。表存在还不够：启动与备份共用 `DatabaseManager::knowledgeGapForeignKeysAreValid`，外键必须恰好是 `category_id`、`source_task_id`、`linked_task_id` 三条，删除动作一律 `SET NULL`。只校验列和 CHECK 会放过 `ON DELETE CASCADE` 的表——恢复与启动都正常，删掉一条任务却会连带删掉关联它的缺口。

## 备忘录

- 定位：记各科「现在学到哪了」的长期笔记，每天改。只留当前内容和更新时间，不留历史版本；进度只用文字记，不换算成百分比或进度条（与「不记题量」一致）。不接计时、不生成任务、不进统计。
- 数据：`memos` 表（schema v20）。标题可以为空，列表用正文第一行代替；正文是纯文本；科目外键 `ON DELETE SET NULL`，删掉科目后这一科的备忘归入未分类。标题最多 60 字、正文最多 10000 字，按 Unicode 字符计（一个表情算一个字）；超长拒绝保存并说明原因，不截断。
- 保存只发改过的字段（`MemoService::updateMemo` 的 `changes` 只认标题、正文、科目），同步改了别的字段时不会被旧的编辑副本覆盖；内容没变不刷新更新时间。新建或换了科目的备忘排到那一科最后。
- 排序只能在同一科目内拖动，「全部」里也只能在组内拖。`reorderMemos` 必须传这一科的完整编号列表，遗漏、重复、混进别的科目都整批拒绝，在一个事务内完成；只改顺序号，不改更新时间——否则挪一下顺序，被挪的几条都会显示成「刚刚更新」。
- 分类胶囊只给「全部」和写过备忘的科目，「未分类」只在有未分类的备忘时出现；正选着的科目最后一条没了（删掉、移走或另一台删除），筛选回到「全部」，不留一个点不到的筛选。
- 备忘录的分类就是写过备忘的科目，不另存一份分类清单。编辑区的科目下拉只列这些科目（和左边的分类胶囊一致，正在编辑的这条所在的科目也在里面），另有「不选科目」和「新建分类…」；没写过备忘的科目不进下拉，要用它就走「新建分类…」，从还没写过备忘的科目里挑，一个都不剩时直接新建科目。
- 右上角「新建」点开是菜单：「新建备忘录」开一条跟着当前筛选科目的草稿；「新建分类…」挑好科目（或新建科目）后直接在这一科开一条草稿，正筛着别的科目时筛选回到「全部」，存下后列表里看得到它。新分类在写下第一条后才留下，什么都没写就离开，分类也随草稿消失。
- 标题只有一行，按回车到正文开头接着写，标题和正文都不变；输入法还在组合拼音时，回车归输入法（Mac 拼音按回车是把字母原样上屏）。
- 新建只建界面草稿，第一次有内容才写库，免得另一台先收到一条空备忘、再收到删除。什么都没写就离开或点「删除」，草稿直接丢弃，回到新建前那条；写了字的草稿删除和普通备忘一样要确认。
- 停止输入 1 秒自动保存；切换备忘、切页、进后台、退出时立即保存。保存失败时内容留在编辑框并说明原因，切换备忘、关窗和退出都会被拦住（切到别的页面不拦，回来内容还在）。
- 正文改没改按文字本身的变化判断，不用 `textEdited`：Qt 6.10 的 `TextEdit` 只在按键时发它，输入法上屏的文字不发——iPad 软键盘打的每个字、Mac 拼音选字后的中文都走输入法，用 `textEdited` 就等于不保存。装载一条备忘时要屏蔽编辑框发回的变化（取消输入法组合时它会先按旧文字发一次），并把模型对齐到编辑框规范后的文字（不间断空格会变成普通空格），否则只是打开看一眼也会被当成修改写回。
- 停止输入后的自动保存不调用 `Qt.inputMethod.commit()`：在 Mac 和 iPad 上它会把还没选字的拼音原样写进框里。只有切换、切页、进后台、退出这类打断输入的操作才提交输入法的组合。
- 另一台改了正在编辑的这条：编辑框没改过就直接换成新内容，本机有没保存的修改就不覆盖。另一台删掉了它：没改过就选相邻的一条；有修改就保留文字，给「另存为新备忘」和「放弃修改」两个出口，由用户明确选，不悄悄复活记录，也不悄悄丢字；这时不显示「删除」。
- 删除要二次确认，不接撤销窗口（理由同知识缺口）。
- 同步：同步标题、正文、科目、顺序、创建时间。`updated_at` 不作为同步字段，本机触发器、远端增量和快照都从标题、正文、科目的内容版本推出时间（UTC 带毫秒），两台显示一致；排序和输掉的版本不改时间。同一科目撞号时按「顺序号、创建时间、`sync_id`」重新编号。两台同时改了同一条的正文时以后改的为准，输掉的完整正文进同步日志，可以「复制被覆盖的内容」找回；另一台删掉一条、而本机的内容早已发出去时，日志记成「已删除」并保留删除前的内容；空标题、空正文不记。
- 备份：v20 及以后的备份要求有 `memos` 表，结构和外键都要对（缺表、缺列、错主键、错约束、级联删除的外键都拒绝）；更早的备份不要求，恢复后由迁移建一张空表。

## 侧栏顺序

- 侧栏条目顺序可由用户在「设置 → 外观 → 侧栏顺序」重排，存在 `appearance/sidebarOrder`（逗号分隔的视图 id）。`appearance` 已在 `AppSettings::ownedSettingGroups()` 中，备份与恢复自动覆盖。
- 存的只是顺序，不是条目集合。`AppSettings::defaultSidebarOrder()` 是「当前版本有哪些可排序页面」的唯一清单；`normalizeSidebarOrder` 在读写两端都跑：保留认识的 id 并维持用户顺序、丢掉已不存在的 id、去重，最后把清单里有而记录里没有的页面补到末尾。
- 新版本新增页面时必须补在末尾，不能因为旧记录里没有它就不显示——用户会以为这个版本没有这个功能，而且完全无从排查。同理，降级运行或手改配置留下的未知 id 一律丢弃而不是原样渲染。
- 新增一个页面要同时改 `AppSettings::defaultSidebarOrder()`、`Sidebar.qml` 的 `entryPresentation` 和设置页的 `sidebarEntryNames`。只改一处会让那一页缺文案或缺入口，`QmlTest.sidebar_order` 的 `test_everyDefaultEntryHasPresentation` 负责在漏改时转红。
- 「设置」不是视图，固定钉在侧栏底部，不进顺序列表。顺序既然由用户决定，原先「时间视图」分组标题与分隔线就不再成立，已一并移除。
- 切页快捷键绑定的是视图而不是侧栏位置，重排不改变 ⌘1–⌘7 各自切到的页面。
- 设置页整份提交新顺序，不做相邻项就地交换：`sidebarOrder` 读出来的是副本，改副本不会回写，只会让界面与存储悄悄分家。
- 设置页用拖动排序，不提供 ↑ ↓ 按钮（2026-09-11 用户看过设计稿后选定：行更干净，接受键盘调不了顺序）。拖动期间完全不动模型——中途改模型会重建全部行，正在拖的那一行连同它的 `DragHandler` 一起被销毁；只记「谁在拖、落在第几位」，松手才整份提交。落点按指针所在行算，指针出界夹到首行或末行；拖到滚动区上下边缘自动滚动，滚动时用最后的指针位置重算落点。

## 专注页任务选择与「开始专注」的口径

- 「开始专注」在三处必须同口径：仪表盘按钮、专注页按钮、⌘↩ 与全局热键。取哪一条由
  `FocusView.autoStartCandidate()` 一处决定——已有有效 `selectedTaskId` 时优先用它
  （用户刚在今日页点过某条，按快捷键不该被换成别的任务），否则取 `getTodayTasks()` 里
  第一个未完成的（该查询已按未完成在前、当天 `display_order` 升序排好）。候选范围是**逻辑今日**，
  不是「全部未完成任务」。
- **已有选中项要先按编号回查仍然存在才用**（`selectedTaskStillExists()`）。选中项只在少数路径里清空，
  在今日页删掉任务不会清它；拿已删除的编号去启动，服务端 `INSERT … SELECT … WHERE t.id = :taskId`
  插入 0 行而失败。失效就清掉选中项、继续找今日候选，找不到才展开选择器。
- 「今天还没有可以开始的任务」这句提示**只在选择器确实展开时**出现（`shortcutOpenedSelector`）。
  取到了任务、只是启动失败时，失败原因由专注页的错误文字说明，不能被报成「没有任务」。
- 取不到可自动启动的任务时**展开选择器**，不按「今天有没有任务」分叉。
  「今日零任务」与「今日任务全部已完成」是两种不同的到达方式，按前者分叉会让后者
  掉进没有规则覆盖的空分支，表现为按了键什么都不发生。
- 选择器里已完成的任务排在末尾但**仍可选**——「今天排的都做完了，还想再练一轮」是常态。
  当前计时绑定的那条即使已完成、即使已不属于今天，也必须出现在候选里，否则从选择器
  走一圈回来会把归属静默改成别的任务（与补录候选「被编辑记录的原归属任务始终出现在候选中」同构）。
- 选择器**不提供「不关联任务」**：实时计时必须绑任务（`canStartFreeFocus` 要求 `selectedTaskId > 0`）。
  统计里的「未关联专注」来自补录与历史数据，不是实时路径。不要照搬 `ManualSessionDialog` 的
  `taskOptions`——它首项恒为「不关联任务」，候选来自历史服务并按所选日期就近排序，用途是补录。
- 选择器只在空闲时出现（没有进行中的会话、也不在主动休息里）。计时进行中任务由计时器说了算，
  换任务要走 `requestTaskSwitch` 的既有确认流程，标题退化为只读。
- 选择器里新建任务后要立刻启动它，因此必须拿到新任务的编号——走
  `TaskManager::createTask(...) -> int`（成功返回编号，失败返回 `-1`；四个 `addTask`
  重载都以它为实现）。**不允许按标题反查**：同一天允许同名任务，标题加 `display_order`
  不是唯一键，反查会把这段专注记到另一条任务上而用户看不出来；加一条「查不到就报错」
  也只防漏查、防不了误匹配。`createTask` 返回 `-1` 时不启动任何计时并报错。
  插入成功却读不出编号时照常发 `tasksChanged`（行确实写进去了），但仍返回 `-1`——
  **绝不返回一个猜来的编号**。
- 当前选中的任务被标记完成、或被改期离开今天，仍留在选择器候选里并保持选中
  （`FocusTaskPicker.candidates` 在今日列表里找不到它时补在最前）。
  专注页只在自己是当前页时响应 `tasksChanged`，切回本页时另有重读。

## 记一笔的键盘入口

- `gap.capture`（应用内）与 `global.captureGap`（全局）都落到
  `MainWindow.captureKnowledgeGapFromShortcut()`。它们是捕获动作不是切页动作，
  与 2026-09-03「切页快捷键只覆盖固定几页」那条决策无关（当时是 8 页，删掉目标页后是 ⌘1–⌘7）。
- **窗口未激活时不能直接开捕获框**：此时键盘焦点还在原来那个应用里，框开出来用户打的字会落到别处。
  先把请求记在 `pendingGapCapture` 并发 `windowActivationRequested`，由 `main.qml` 完成
  show/raise/requestActivate；等 `windowActive` 真的变真，`onWindowActiveChanged` 才打开框。
  窗口操作留在窗口那一层，`MainWindow` 只表达意图。
- **挂起的请求必须可过期、可取消**：`gapCaptureRequestTimeoutMs`（默认 3 秒）内等不到激活就作废，
  `cancelPendingGapCapture()` 可随时取消。系统若拒绝把窗口提到前台，不作废的请求会在
  用户下一次随手打开应用时突然弹出捕获框，可能已经隔了一小时。
- 捕获被阻断的条件是 `gapCaptureBlocked()`：弹窗占着焦点（`overlayHoldsFocus`）、正在录快捷键，
  或备份/恢复正处在数据库临界区（`backupOperationBlocksInput`）。三项与 `AppShortcuts.suspended`
  同一口径，必须在这一处一起判：全局热键不经过 `suspended`；`triggerShortcutAction` 入口的
  数据库守卫只管分发那一刻，管不到激活时才执行的挂起请求。捕获框挂在 overlay 上，
  会盖过恢复遮罩并接收键盘。
  **挂起的请求在激活后、执行前要再判一次**——挂起期间可能开了弹窗、进入了录制或开始了恢复。
  被挡住的请求直接作废，不留到下一次激活，阻断结束后也不补弹。
- **已知潜在风险（未复现、未修复）**：快捷键分发里另有三条经 `Qt.callLater` 延后执行的路径——
  新建任务、开始/暂停专注、结束专注。`triggerShortcutAction` 入口的数据库守卫只管分发那一刻，
  延后那一步执行前没有再判 `backupOperationBlocksInput`。恢复阻断目前只由用户在弹窗里确认后同步置真
  （自动备份不阻断输入），要撞上需要确认点击恰好落在分发与延后执行之间。
  **时间窗口短不等于事件顺序有保证**，不能记为已证明不可达。
- 在专注页、且专注页自己的入口可用（`FocusView.knowledgeGapEntryAvailable`）时，
  走专注页那个入口（带来源任务与科目）；其它页面走窗口级的无来源捕获。
- **主动休息时走窗口级、无来源捕获。** 专注页那颗钮在休息时隐藏，因为那段时间没有任务上下文；
  但没有上下文只意味着不附带任务和科目，不是禁止捕获的理由——休息时也可能想到知识缺口。
  快捷键读的是和按钮同一个可用条件，休息计时不受影响。

## 快捷键默认值的定法

- **默认键位的理由只有两条：交互约定与冲突检查。** 交互约定指「相邻键位不该对应产物完全不同
  的动作」（`gap.capture` 不取 ⌘⇧N，就因为它是「新建任务」⌘N 的近邻，而知识缺口的常态
  恰恰是还定不了什么时候处理，挨在一起诱导按错；⌘⇧K 在默认表里空着，K 取自 knowledge）。
- **某个键位被现有测试用着，不是改产品默认值的依据**——方向反了，该改的是测试。
  `ShortcutRegistryTests` 里「随便换一个键位」类用例统一用 `kSpareSequence`
  （`Ctrl+Alt+Shift+Y`）：三修饰符加字母，不在默认表里，也不会成为任何产品默认值，
  因为应用内默认一律 ⌘ 或 ⌘⇧ 打头。借用真键当样本，会让以后给新动作定默认键位时撞红这些用例，
  看起来却像「那个键不能用」。
- 冲突与默认值本身另有专门用例覆盖（`assignRejectsConflictWithAnotherActionInAnyScope`、
  `resetAllRestoresEveryDefault`），不靠样本键顺带验证。
- **键位规则只在 `ShortcutRegistry::resolveAll()` 一处落实**，读取、保存、恢复默认、从备份恢复、
  升级新增默认键都走它。此前冲突检测与「全局热键至少两个修饰键」只在设置页改键时执行：
  「恢复默认」能把两个动作放到同一组键上（Qt 判歧义，两个都不触发），被改过的备份能把 ⌘C
  注册成全局热键，新默认键 ⌘⇧K 会撞上老用户自定义的键。分配顺序：先分用户亲手选的键，
  再分出厂默认；同一轮按动作清单顺序先到先得。让路的动作带 `conflictTitle`，设置页显示
  「键位与「X」重复，暂未生效」，不能说成「已停用」；「恢复默认」遇到出厂键已被占用时拒绝并说明占用者。
  全局热键要两个强修饰键而应用内默认键都只带一个，所以全局覆盖值撞不上出厂默认，只可能撞覆盖值。

## 科目下拉的内联新建

- `AddTaskDialog` / `EditTaskDialog` 的科目下拉末尾挂一条编号为 `-2` 的哨兵
  「+ 新建科目…」。它**不是科目**：选中后立刻把下拉退回上一个真实项再开新建框，
  取消时下拉不能停在哨兵上。提交路径另有一道闸把 `-2` 收敛成 `-1`，防止哪条路径漏了退回。
- **恢复点记科目编号（`lastRealCategoryId`），不记下标。** 科目按 `display_order`、`name` 排序，
  增删、改名都会让已选科目换位置，旧下标可能指着别的科目、甚至正好指着哨兵本身。
  恢复点那个科目不在了就回到「不设置科目」/「未选」，绝不停在哨兵上。
- **每次打开把恢复点同步成这一次的初始选中**，不继承上一次打开时记下的科目。
  新建任务弹窗此前只在关闭时把下拉复位、恢复点没复位：上次存在「英语」下，这次点哨兵再取消，
  下拉会跳回用户这次根本没选过的「英语」。
- 内联新建只收名字，颜色按已有科目数量在 `ColorPicker` 那份暖色阶里顺位取——
  建任务建到一半想起要分个新科目，此刻要的是别打断，不是再做一次配色决策。改颜色仍走科目管理。
- 建完自动选中新科目；`CategoryManager::addCategory` **先发 `categoriesChanged` 再返回编号**，
  QML 替身必须按这个时序写（`tst_inline_category_sync`），顺序反过来会让「收到信号时新科目还查不到」
  这类问题在测试里消失。
- **弹窗开着时科目在别处变了，三个带科目下拉的弹窗都要跟着刷新**：`AddTaskDialog`、`EditTaskDialog`、
  `KnowledgeGapDialog` 都订阅 `categoriesChanged`，先记下当前选中的**科目编号**再重建下拉、
  按编号选回去；原科目被删了就回落到「不设置科目」（知识缺口为「不指定」），
  不能停在别的科目或哨兵上，更不能把被删的编号照样提交出去。
  是否订阅不看「现在有没有入口能在弹窗开着时改科目」——没找到入口不等于入口不存在，验收要的是行为本身。
  新建、编辑任务弹窗的门禁写在 `onCategoriesChanged` 处理函数里（`root.visible`），不用 `enabled` 绑定；
  关着时不刷，打开时本来就会刷。
  自己建科目时服务先发信号再返回编号：开着时的刷新先保住当前选中，`onCreated` 随后再选中新科目，
  两段的先后由 `tst_inline_category_sync` 按真实时序覆盖。
- 预设科目由 `DatabaseManager::insertPresetCategories()` 播种（5 条，`is_preset = 1`），
  每次打开库都会跑，靠 `display_order` 作稳定身份幂等（用户改名改色后不会再复制一行）。
  **内联新建不碰这条路径，也不放开预设科目删除**——后者是数据策略变更，涉及删除 SQL、
  `canDeleteCategory()`、界面按钮门禁，以及补种逻辑需要墓碑标记（否则删掉的下次启动会复活）。

## 本周计划的合计与键盘导航

- 每天给出「已排 N」（当天全部任务预计用时之和，完成与否都算——问的是「排了多少」，
  与今日任务页 `plannedMinutesToday` 同一口径），副标题给出本周合计。一条都没排时长的日子
  不显示「已排 0 分钟」，那不是信息是噪音。
- 已完成的任务沉到当天末尾，**同一完成状态内保持服务层给的原有顺序**
  （`display_order`、创建时间、编号）。用两趟稳定分区而不是 `sort`：加一个二次排序键
  就会悄悄改变同组内的相对位置。
- 外层 `ListView` 的 `model` 是 7（一项一天），任务在内层 `Repeater` 里，
  所以 `ListView.currentIndex` 选中的是**天**不是任务，不能拿来当游标。
  游标记的是**任务编号**：下标在任务增删、以及完成后沉底重排之后指向的就是另一条任务了。
  按编号记，完成一条之后焦点自然跟着它挪到当天末尾。
- 摊平序列 `flatTaskIds` 按「天序 + 天内序」生成，空日子不产生条目，↑↓ 因此天然跳过它们。
  到首尾就停，不循环——一路按下去从周日绕回周一会让人失去位置感。
- 删除后的落点逐级尝试，取第一个命中的：**当天后继 → 当天前驱 → 后续非空日首条 →
  前序非空日末条 → 清空**。中间两级最容易漏：删掉当天最后一条但当天还有前序任务时应落到前驱，
  删掉全周最后一条但前几天还有任务时应落到前序非空日末条。落点必须在**发出删除请求之前**算好，
  请求一发出宿主就把那一行从模型里藏起来了。
- 刷新后按编号恢复游标，目标任务已不在则清空，不留一个指向空气的游标。
  游标滚动定位先用 `positionViewAtIndex(dayIndex, ListView.Contain)`——外层是虚拟化列表，
  屏幕外的 delegate 根本没被创建，不能靠累加 delegate 高度定位。**只按天定位不够**：
  一天比视口高时 `Contain` 把这一天顶到视口上沿，当天靠后的任务仍在视口外
  （12 条的一天，第 12 条落在 562px 视口的 957px 处）。所以再按任务行在内容坐标里的下沿补一段日内偏移。
  只需往下补：`Contain` 之后比视口高的一天上沿贴着视口上沿、比视口矮的一天整个可见，行不会跑出上沿。
  `tst_week_logical_day` 用真实按键量行在视口里的位置，覆盖「一天超高」与「跨虚拟化的日子来回走」。
- 「已排」是否显示暴露为 `showsTotal`，副标题有 `objectName: weekSummaryText`：
  测试断言这两个，不断言会沿父链级联、离屏下不可靠的 `visible`。
- macOS 笔记本主键盘上写着 delete 的那颗发的是 `Key_Backspace`，删除必须同时接管它；
  只认 `Key_Delete` 等于这条通路在本应用唯一的目标平台上不存在。
- **键盘入口要主动交接。** 列表上的 `focus: true` 只在所在焦点域拿到焦点时才生效；
  鼠标点侧栏切页时，侧栏条目会把焦点留在自己身上（`Sidebar.qml` 为了让 Tab 从当前项继续），
  于是 ↑↓ 等按键全部落空。所以本页可见且激活时（`keyboardEntryReady`）把焦点交给列表；
  点任务行时游标落到这一行并交接焦点。输入框正在编辑、或弹窗占着焦点时不抢。
  点行的 `TapHandler` 挂在本页的 `TaskItem` 实例上，不改 `TaskItem` 本身（今日任务页也用它）；
  它与任务行自带的 `DragHandler` 共存，按住拖动仍由拖动接管，拖完不会被当成一次点击去改游标。
- **键盘相关的用例必须发真实点击与按键**（`tst_week_keyboard_entry`，`TestCase` 需 `visible: true`）。
  此前的用例全部直接调 `moveCursor`，游标逻辑是对的，却从没发现用户那条路径上按键根本进不来。
- **能不能从某条开始专注只有一个口径**：`canStartFocusFor(taskId)`——今天那一行、且没完成。
  键盘回车与行内「开始」按钮都读它，此前两边各写一份，回车漏判了已完成。
  完成后到列表重载之间（完成动画要播完，重载推迟约 850ms）模型里的 `completed` 还是旧值，
  所以用 `completionOverrides` 记下刚改过的完成态、重载后清空，否则回车能趁这个窗口启动刚完成的任务。

## 热力取档与专注历史月历的投入条

- **分钟数 → 档位只有一个函数**：`qml/HeatmapBands.js` 的 `bandForMinutes`。零投入单独返回 `NONE`，
  正投入按绝对分钟数分四档 `< 60 / 60–149 / 150–299 / ≥ 300`。不按「占当月最大值的比例」分——
  那会让整月都学得少的月份照样染出最深的一天。专注历史月历调用这个函数，不要另写一份阈值
  （原先目标详情热力图也共用它，已随目标页删除）。
- 调用方传 `seconds / 60`，**不要先取整**：30 秒取整成 0 会被画成零投入，同一格的时长文字却显示有记录。
  `bandForMinutes` 用 `!(value > 0)` 判零，NaN、null、非数字一律按零投入——
  写成 `value <= 0` 挡不住 NaN，它会一路漏到最深那档。
- 颜色只在 `Theme.qml`：`heatmapBandColors`（浅深各四档）与 `heatmapEmptyTrack`。
  **浅深两套方向相反**：浅底投入越多越深，深底投入越多越亮；把日间色阶直接搬到深底，
  最低档会是近白块、比高投入还抢眼。判据由 `tst_heatmap_bands` 写死：相邻两档 CIEDE2000 ≥ 7，
  空轨道在普通 / 选中 / 悬停三种格底上都 ≥ 5、与第 1 档 ≥ 5、且在普通格底上比第 1 档安静。
  调色前先跑它。
- **专注历史月历用格底投入条，不整格铺色。** 这页格子高约 78、宽随窗口变（1200 宽窗口下约 154），
  每格本来就有 1px 描边、有两行文字，而且选中与悬停改的就是底色。整格铺色会色块压过整页，
  并被选中态的 `accentSoft` 整个盖掉（4 档那天反而成了全月最浅的一格）。
  所以底色继续归选中 / 悬停 / 今日状态，投入强度只由格底 8px 色条表达；文字始终在中性底上，
  沿用 `ink` / `accentFillInk`，不需要逐档文字色。
- 四种格子：有投入 = 按档着色的条；零投入（含今日零投入）= 空轨道；未来 = 不画条；
  本月之外 = 什么都没有。未来按**逻辑今日**逐格判断（年月日拼整数比，不比 Date），
  翻到将来的月份整月都是未来，翻回过去整月都不是；跨过日界时，原先的「明天」立即开始画条。
- **空轨道不复用 `Theme.border`**：它压在选中底 `accentSoft` 上 ΔE00 只有 2.2（夜间 3.2），
  被选中的零投入日会被读成「没有轨道」即未来——本月内的未来日同样能点选，两态会同时出现。
  `heatmapEmptyTrack` 是热力专用令牌，不要为了它去改全局 `border` 或 `surfaceSunken`。
- **未来日期不降色**，保留 `Theme.ink`：降为 `inkMuted` 后夜间退得过深，像是不可操作，
  而这些日期实际能点击；未来已经由「不画投入条」表达，不需要再牺牲日期可读性。
- 格内日期与时长**靠顶排**，不铺满整格：`ColumnLayout` 铺满时会把两行纵向摊开，
  时长那行被推到格底贴住投入条，有无时长的格子日期高度也会跳。`tst_month_heatmap_bar`
  在卡片允许的最矮高度下断言两者之间留有间隙。

## 周复盘

入口在统计页「本周」范围，趋势图与科目饼图之间。统计判断全部在
`StatisticsService::getWeeklyReview(weekStart, logicalTodayIso)` 里完成，`WeeklyReviewCard.qml` 只按字段格式化与展示：
不算比例、不挑事实、不含阈值。基础内容来自已有专注记录，每日目标与预计用时都是可选模块。

- **周期由页面传入的逻辑今天判断。** 页面每次刷新只生成一个 `logicalTodayIso`（页面快照已按日界换算，
  用年、月、日拼 `yyyy-MM-dd`），同时传给 `getWeekComparison` 与 `getWeeklyReview`；导航与标题继续用这份快照，
  两边不会各读一次时钟而在日界附近分歧。服务收到的已是逻辑日期，**不能再减一次 `dayStartHour`**；
  专注记录按开始时间归属逻辑日的换算与此无关，照旧在查询里做。进入下周一逻辑日后本周才算结束。
- **当前周只看概览。** 不做周际比较、不生成事实；顶部三张周统计卡由 `getWeekComparison` 返回 `hasData = false`
  隐藏涨跌——进行中的周拿去比上一整周，窗口不一致。当前周的专注查询截到逻辑今天为止。
  已结束周保留整周比较，复盘卡不重复顶部已有的总量比较。「今日 vs 昨天」「本月 vs 上月」暂未改，见计划索引待评估事项。
- **统计页三张卡预留比较行高度**（`StatCard.reserveComparisonSpace`，默认关闭，仪表盘等处不受影响）：
  不预留时卡片在 126 与 104 之间跳，切换范围或翻周时下方图表跟着上下移动。
- **今日目标按日期留存。** 保存时除旧的一对键（`focus/dailyGoalDate` + `focus/dailyGoalMinutes`，旧版本只认它）外，
  再写 `focus/dailyGoalHistory/<yyyy-MM-dd>`；每个日期取最后成功保存的值，不记修改轨迹。只认 1～1440 的整数分钟，
  小数、越界、带符号或非数字一律按「没有有效目标」处理。读取时旧键对应的那一天以旧值为准（旧版本改过当天目标、
  或启动同步没写成功时，历史可能是过期值）；启动与 `reload()` 把合法旧键同步进历史，值一致时不写盘，失败只发
  `settingsWriteFailed`。保存另一天的目标时，旧键记着的那天若还没同步，同一次保存里一并补写。
  多键保存照 `saveScheduleSettings` 的模式：记下原值与存在性、只 sync 一次、失败恢复缓存再重建后端——
  QSettings 缓存由多个实例共享，只重建后端撤销不了失败写入。历史键在 `focus` 自有分组下随备份走，
  恢复时与专注记录取自同一快照；上线前与旧版本连续使用期间缺失的历史不可恢复，不推测补齐。
- **目标达成 K / N** 只统计已结束、且有有效目标的逻辑日，按原始专注秒数与「目标分钟 × 60」比较，达到即达标。
  今天无论是否达标都不进 K、N 与两项合计，单独显示进度；未来日期的目标不计入，也不撑起卡片。
- **预计用时对账只看同一批任务**：所选周计划日期内、`estimated_minutes > 0` 的任务。实际只算这些任务在所选逻辑周内的
  有效专注，按任务当前科目与计划一起归组（不看会话快照）。没填预计用时的任务、计划日期在别的周的任务、未关联任务的会话
  都不进来，否则只给部分任务填预计用时会把比值放大成几百。比例叫「投入／计划比」，按原始秒数算，可以超过 100%，
  不代表任务完成率；计划为零时比例为空。统计的是周内投入，不是任务全生命周期耗时。卡片不放统计范围说明句，
  块标题写「预计用时任务」，当前周标「进行中」（分母是整周计划、分子是已产生的投入）。
- **事实只给已结束周**，按 F1 → F2 → F3 取前两条，每类最多一句，不给建议。阈值集中定义在 `StatisticsService.cpp`
  顶部，判断一律整数交叉相乘，不走浮点：
  - F1 目标差额：有目标的日子里实际 < 目标 × 60%，取比例最低的一天，并列取较早日期。没有目标数据就跳过，不拿日均之类替代。
  - F2 科目变化：两周总投入各不少于 60 分钟，占比变化不少于 10 个百分点，且该科投入变化不少于 60 分钟（防小样本：
    两周各一小时时 10 个百分点只是 6 分钟）；取变化最大的科目，并列按名称。分母含未关联任务与未分类投入，
    但「未关联任务」「未分类」不能被点名。科目归类与 `getCategoryStats` 共用同一条 SQL，秒数与同页饼图同源。
  - F3 预计用时差额：科目计划不少于 60 分钟，且集合内实际 < 计划 × 60%，取短缺最多的科目，并列按名称；
    未命中时，若集合总投入落在计划的 85%～115%（含端点），补一句「总投入接近计划」，不宣称估算稳定。
- **事实是结构化数据**（`goalShortfall` / `subjectShareChange` / `estimateShortfall` / `estimateOnTrack`），
  QML 按类型套固定句式、时长一律走 `qml/Duration.js`；未登记的类型不渲染。服务里拼句子会带出另一套时长格式。
- **错误通过返回值传递。** 复盘专用查询不发 `operationFailed`，结果 `loadState = ready / error`；任一查询失败整份作废，
  不带半份统计。卡片在原位显示「周统计加载失败」及原因，空周（没有可展示的块）才整卡隐藏，错误态不能被当成空周藏起来。
  页面整体刷新抛异常、复盘接口缺失都按错误处理。数据库整体故障时顶部与卡片同时报错属预期。
- 历史结果随任务、目标、专注记录的修改重算，不存冻结快照。统计页监听 `dailyFocusGoalChanged` 刷新。

## 数据安全与跨层交互

- schema 版本以 `DatabaseManager::kCurrentSchemaVersion` 为准。迁移不能只信版本号，还要检查结构，补齐缺失的表或列；已有但不合法的课表结构须报错。空节次表重新打开时补默认节次，失败必须整体回滚。
- 课表主键必须具备 SQLite 自动生成整数编号的语义；启动与备份检查共用校验。v13 备份必须有合法课表表、约束和主键，旧版本备份允许缺表，由恢复后的迁移补齐。
- 旧备份兼容性按 schema 版本判断，不能把后续新增或懒建的表无条件加入所有版本的必需表清单。增加任务列时同步检查 `migrateToVersion5` 的整表重建语句与列清单，避免重建丢数据；迁移测试要覆盖带旧数据的数据库。
- 偏好只经 `BackupOperations::openSettings()` 打开，它关闭 QSettings 的回退：macOS 原生偏好开着回退时 `allKeys()` 会列出系统全局域的键（文本替换词典、语言、地区……），旧版因此在每份备份里夹带了这些个人信息，恢复失败回滚时还把它们钉进本应用的偏好域。备份只嵌入本应用拥有的分组；设置快照与写回只处理本应用分组加本机的 `backup/` 策略键，写回时不 `clear()` 整个域（Cocoa 自己记的窗口位置等键要留着）。启动时 `MacPreferencesCleanup` 清掉以前钉进来的、与全局域值完全相同的键，只做一次。
- 备份拒绝 Trigger、View、虚拟表等非预期数据库对象；v18 起库里自带维护同步版本的触发器，备份检查只按名字放行这一类（不比内容：改了同步表或触发器写法后，旧备份里的文本必然不同）；每次打开库时，在任何迁移写入之前先拆掉内容与本版本规范文本不一致的同步触发器，打开的最后一步再按规范重建，伪造的同名触发器没有机会执行。恢复设置仅写回 `AppSettings::ownedSettingGroups()` 声明的顶层分组，兼容快捷键等动态子键。新增设置分组必须同步所有权清单。恢复走 `AppSettings::reload()` 重建设置后端，新增带 NOTIFY 的属性必须在那里补发变更信号，否则恢复后 getter 已是新值、界面却停在旧值直到重启；`appSettingsReloadNotifiesEveryProperty` 按元对象逐个属性核对。
- 新恢复点创建并提交成功后再清理旧快照，失败不能提前消耗最后的恢复机会。清理统一走 `SnapshotRetention::prune()`：刚建好的那份无条件保留并占一个名额，其余按文件名里的时间戳倒序。曾按修改时间保留最近 N 份，系统时钟以前偏快时留下的「未来」快照会把刚写好的恢复前 / 迁移前快照挤到最后当场删掉。恢复失败需要回滚并重新打开数据库；数据库替换期间阻断界面操作、快捷键与直接动作分发。
- CSV 导出、备份和恢复的耗时工作放在工作线程。数据库连接不跨线程共享，导出线程使用独立只读连接；全部导出的多个文件读取同一事务快照。导出期间的关闭、取消、退出语义必须一致。
- 主连接的锁等待设置、后台连接与事务边界协同维护；不能用界面假成功掩盖写入失败。失败状态要保留可重试入口，与正常空数据区分。
- macOS 原生实现放在 `src/platform/macos`，iOS 专属实现放在 `src/platform/ios`，两个平台共用的 Apple 框架实现（系统通知后端）放在 `src/platform/apple`；业务服务依赖平台无关抽象。跨服务信号在组装层接线，避免目标服务与计时器形成循环依赖。
- 本机部署使用暂存包、旧包备份与原子切换，失败还原旧包。具体命令与二进制一致性校验见 [运行命令](运行命令.md)，协作约束见 [AGENTS.md](../AGENTS.md)。

## 设备间同步（050 第一期、051 第二期、052 备忘录）

- 范围：任务、科目、每日例行、专注与休息记录、课表项、知识缺口、目标倒计时、备忘录按条目同步；设置里同步逻辑日起点、番茄与休息时长（含长休息）、超长计时提醒、昵称、学期起始日与总周数、今日目标（按日期各一项）、课表节次（整张表算一项：改节次是整表删了重写，按条目同步会被删除优先打乱）。外观、提示音、窗口、自动开始、快速开始、侧栏、课表显示方式、快捷键各台设备各自设；计时中的状态（`active_focus_state`）、例行的「最后生成日期」、各表的 `updated_at` 只属于本机，对方新建的行插进本机时按此刻补 `updated_at`（备忘录例外：更新时间从内容版本推出，两台一致，见「备忘录」一节）。设置的读写在 `SyncedSettings`，一批写回多项时用 `WriteBackScope`，免得先写回的那项发出的信号让还没写回的被当成本机改动。结构、同步列清单与触发器集中在 `SyncSchema`，建库迁移、备份检查、`SyncStore` 共用这一份定义。
- 身份：每条记录一个 `sync_id`，本机自增编号不跨设备。预置科目按预置位置取 `preset-1`…`preset-5`；例行实例取「例行 sync_id + 日期」，两台设备各自生成的同一天实例是同一条。版本是「混合逻辑时间 + 设备标识」：本机写入由触发器按列记版本、进待发送队列；应用远端改动时在同一事务里置位 `sync_runtime.applying`，触发器全部跳过。
- 合并：按字段比较版本，新的赢；两边改的是不同字段都保留。输掉的一方如果是本机的修改、而对方改的时候没见过它（字段的 base 与版本对不上），就是同时修改，写进 `sync_conflict_log`，只存给人看的文字（哪条记录、哪一项、丢了什么、留下什么）。预置科目的出厂值、例行生成的默认值用最小版本，输给任何一次真实修改；版本相同而值不同时只在最小版本之间按值取舍，本机推出来的值（引用置空、合并后改指）不会被发回去。
- 删除优先：删除记录永远赢，之后收到的修改忽略并记日志。例外是例行「收回」（停用、把今天从重复日里去掉时收回没动过的当日实例）：记成 `reclaim`，重新启用后再生成的实例用真实版本取代它；对方收到收回时只删没动过的，本机已完成或专注过的留下并以新版本重发，对方据此补回。两边各有一条删除记录时取胜者（普通删除、合并压过收回，同类取新的）；本机的那条胜出时留在待发送里发出去，否则对方一直只有较弱的那条，当天重新生成的实例会让两边一边有、一边没有。
- 一条都不卡：每条远端记录各自一个保存点，失败只跳过那一条并记日志。引用的目标已被删除，按本机删除它时的做法处理（任务的科目连同科目名文本清空、专注记录的任务置空、例行解除后生成标记清零）；目标暂时没有（还没收到或被收回）的先落空值、记进 `sync_pending_refs`；收到对方的收回、删掉实例之前，指向它的引用（外键随后置空）同样记进去，两边记得一样。目标在本机出现（同步收到、本机自己重新生成，或到达时本来就有）就接回：每批应用完、每轮同步开始时各扫一遍，接回不算本机改动。发出记录时，等着接回的引用发它本来指向的身份，从快照起步的设备才接得回。
- 同名科目：改名先落临时名，整批应用完再定名，互换名字不会被误判。真撞名时自定义科目合并到 `sync_id` 较小的一方（预置科目总是留下），引用改指过去，合并以 `merge` 删除记录发出；两个预置科目撞名时后改的留名、另一个加「（2）」后缀。
- 排序：本批动过的日期出现重复或非正的排序号时，在同一事务里按完成状态、排序号、创建时间、`sync_id` 重排，作为本机改动发出；不走 v12 迁移路径，不产生迁移快照。
- 进行中的专注不同步：`FocusTimer` 启动时会删掉没被本机计时状态引用的未结束行，同步过去会被对方当孤儿删掉、删除再传回来。专注记录结束的那一刻才整条发布。
- 首次加入与恢复备份：iPad 首次加入完全以 Mac 为准（`replaceWithSnapshot`，调用前先自动备份）。恢复备份是全局回滚：本机纪元加一、设备标识保持恢复前的、发布全量快照；另一台读到纪元更高的快照时整体替换。纪元不同的增量批次整批拒绝。关着同步也一样：加入过同步文件夹的设备恢复备份，下次打开同步时另一台跟着回滚，所以恢复确认框按「加入过」而不是开关给出提醒。整体替换时快照里的每一项设置都写回本机。
- 通知：提交之后由 `SyncNotifier` 按改动过的表发信号——先逐条 `taskDeleted`（计时器解绑），再写回逻辑日起点，再刷新科目/例行、历史与任务列表；失败时一个信号都不发，绝不整库重新初始化。对方改的设置进库时，同一事务里记「待写回」标记，写回本机后核对值真的写成了才清掉；启动核对时有标记的以库为准写回，没有标记却不一致的是本机改了没记进库，以本机为准补记，不再一律改回库里的值。
- 例行生成：`materializeToday` 在今天的实例已经存在（例如另一台同步过来的）时不再生成第二条，生成戳照样推到今天；用户删掉的实例不复活。iPad 启动与跨日时同样生成。
- 批次格式：052 起改动批次的格式是 3，能读 1–3。旧版碰到不认识的表会跳过那条、照常推进读取进度，以后不再补读，所以新增同步表必须升格式。旧版读到更新格式的批次就停在那一批、不推进进度，并显示「需要更新这台设备上的应用」；它自己的改动照常写出，新版能读。只升级了一台时，新版的改动要等另一台也升级后才过去，不会被跳过。

## 外部 AI 接入

- 默认关闭，读取与写入分别授权；每次实际执行重查权限和会话（会话编号按 UUID 比较，不分大小写）。关闭接入同时撤销写权限，重新打开只恢复读取；加载配置时清掉“接入关着却仍保留写授权”的旧状态。仅主应用业务服务操作数据库，辅助程序只转发。
- 编辑/拖动期间阻止外部新写入；登记绑定发起 QObject，结束幂等释放，销毁兜底。拖动登记挂在发起拖动的那一行上：行在拖动中途被销毁（例如跨日重建列表）时随之释放，页面同时清掉拖动残留。编辑前同步登记并按编号重读，交互期间延后列表重建。新增弹窗不阻断。
- MCP 不替用户提交待删除项：列表排除待删任务，单查或目标写入返回忙碌；其他任务写入不影响原撤销条，历史统计不提前删除。
- 创建用当前会话内 UUID v4 去重；重放读原编号现状。已有任务按目标状态修改，目标已满足时不写库，否则核对状态令牌。只写被要求修改的字段：未传标题/预计分钟/备注/科目时保持历史数据，不把旧预计分钟夹紧，也不因上限出现之前的超长旧标题而拒绝别的修改。负的历史预计分钟对外按“未设置”报 0。
- 传输按背压排队：主应用等上一条结果发完才执行下一条请求；辅助程序 stdout 积压时停在消息边界，同一批里后面的请求先不解析（字节留着，读走后继续）。超长单条请求、重复请求编号只拒绝那一条，不结束辅助程序。辅助程序不设握手期限，空闲 30 秒释放连接、下次调用自动重连；连接满员时明确报 `connection_limit`。
- 查询失败通过返回值报告，不发页面共享的 `operationFailed`；错误信息写明对象（哪条任务、哪个科目）。写入被拒报“未被修改”；写入已生效却没能返回结果的所有情况都带 `write_committed`，不能让模型以为没改成。成功修改仍发正常刷新信号。接入反馈只在设置状态区展示（给人看的说明，不含内部来源标识），不抢焦点、不替换 Toast。
- `mcp/` 不进入备份设置组或本机键搬运名单，恢复完全保留本机授权，仅轮换会话、清理创建登记。详见 [MCP 接入说明](MCP接入.md)。

## 界面与验证约定

- 使用现有 `Theme.qml` 语义颜色与 Qt Quick Controls 风格；独立弹窗也须接管 `palette`，保证浅深主题中的正文、占位文字、选区及输入边界可读。
- 玻璃效果只用于导航、浮动工具栏、弹窗与重要控制，内容卡保持清晰；业务内容位于光学层之上，效果缺失或关闭时提供可读的半透明纯色降级。不可见时停止效果更新，动效支持 `reduceMotion`。
- 调低 `MultiEffect.blurMax` 会同时改变阴影外观，不能把它当成无副作用的性能参数。性能改动先提供测量，不能仅凭组件数量决定虚拟化或切换渲染实现。
- 非字面量 `text` 绑定必须显式声明 `textFormat`，避免任务标题等字符串被 AutoText 猜成富文本，由 `QmlTextFormatGate` 检查。
- `QmlLintGate` 负责静态告警；类型推导限制只允许在具体表达式旁注明原因并局部压制，不能全局放宽类别或数量。
- 每个 QML 测试条目通过 `FAIL_REGULAR_EXPRESSION` 拦截 `Unable to assign`、`TypeError`、`is not a function` 与 `Binding loop`。确需触发告警的用例只调整自身条目，保留其他检查。
- 运行时门禁只能覆盖实际执行的路径。弹窗测试需真正打开并执行交互，`tst_dialog_smoke.qml` 提供基础覆盖；不能把仅实例化组件当成完整覆盖。
- 注入的服务替身缺方法或属性时，先检查可调用性，再显式归一化布尔和数值；仅检查对象非空不能避免运行时类型错误。
- QML 里数值回退不能写成 `value || 默认值`：优先级「低」是 0、日界可以是 0 点，`||` 会把合法的 0 当成缺值。只在 `undefined`、`null` 或空串时才回退。测试替身不要同时声明 `signal fooChanged()` 与 `property foo`：属性自带同名变更信号，整个测试文件会编译失败。
- 焦点环只能由 `Control.visualFocus` 驱动，不能用 `activeFocus`：窗口切走再切回、弹窗关闭把焦点还回来时 `activeFocus` 同样从假变真，于是鼠标点过的那一项会亮起焦点环，和当前选中项一起出现两个框。需要焦点环的自绘条目（如侧栏条目）根用 `Control`，外观读数用 alias 留在条目上供调用方与测试读取。
- 页面级竖向滚动条统一用 `PageScrollBar`，一律贴窗口最右缘，竖向只覆盖真正滚动的那一段。玻璃框里的列表也照此处理：滚动条落在框外的页边上，不浮在框内、不压内容。仪表盘专注面板展开时窗口最右缘是专注面板，任务清单的滚动条居中落在两块面板之间的 16px 缝里；收起时（默认窗口宽度下专注面板本来就放不下）和其它页面一样贴窗口最右缘。仪表盘右侧不为展开把手预留布局通道：把手显形时只露出 22px，落在 24px 页边距里；它的感应区只到任务面板上沿为止，下面那段右缘归滚动条，否则想拖滚动条会先把把手招出来。
- 摆到滚动区外面的做法分两种。挂在 `ListView`/`Flickable` 上的滚动条可以声明在别处（框外那个 Item 里）并手写 `x`/`y`/`height`，附加对象只要它的 `parent` 不是那个列表就不会替它排版。挂在 `ScrollView` 上的不行：`ScrollView` 会把挂上来的滚动条收为自己的子项，而它又按自身边界裁剪子项——要让 `ScrollView` 本身用负的右边距（`Layout.rightMargin` 或 `anchors.rightMargin`）伸到目标位置，再用同样宽的 `rightPadding` 把内容收回原处。在 `ScrollView` 上换自定义滚动条时必须同时声明 `parent`、`x`、`y`、`height`（写法见 Qt 文档「Customizing ScrollView」），否则它缩成几像素停在左上角。不要绑 `effectiveScrollBarWidth` 来留通道——它随「内容是否超出一屏」变化，而内容高度又受可用宽度影响，会绕成绑定循环。
- 换掉 `contentItem` 的滚动条会丢掉 Basic 风格「放得下就隐藏」的逻辑（它写在自带滑块的透明度状态里），内容放得下时会画出一整条满高的滑块。`PageScrollBar` 已按 `size < 1` 补上；滚动区可能被隐藏而滚动条不是它的子项时，用 `scrollAreaVisible` 把可见性接进来。
- 玻璃框与玻璃卡统一用 `GlassPanel`：白色描边 `Theme.glassBorder`、`radiusLg` 圆角、顶部受光棱边、随主题的落影。页面左右下边距统一 24，装列表的玻璃框内边距 16。框里的内容做成 `GlassPanel` 的兄弟项叠在它上面，不要放进它的阴影图层：图层会把子项裁在框的边界里。任务卡（`TaskItem`）、今日专注的记录卡、知识缺口卡是内容卡而不是玻璃框，保留米色 `Theme.border` 描边：它们多半叠在同色的玻璃框上，白边会让卡片和框糊成一片。
- 日期一律用年、月、日三个整数拼 `yyyy-MM-dd`，不要把 `MonthGrid`、`QDate` 给的 `Date` 直接格式化：那条路带时区换算，可能整体差出一天。可选日期的字段用 `DatePill`（点开选、留空是常态），必填且需要手输或逐日调整的字段用 `DateInput`。
- 配色是否可用，判据是**对比度**与**色差**，不是亮度差。`0.299R + 0.587G + 0.114B`
  只说明两个色在明度上分开了，既不回答「相邻两级人眼分不分得出」，也不回答
  「上面的文字读不读得出来」——用它当唯一判据会漏掉「某一级的字根本看不清」
  和「最低一级和空值几乎同色」。承载文字的色块按 WCAG **4.5:1**（正文）核对，
  相邻级别的可辨识按 **CIEDE2000 ΔE00** 核对（≥5 才算不并排也看得出）。
- 禁区是**针对一组具体文字色算出来的**，不是色彩本身的性质。本项目的色块只在
  `Theme.inkStrong` / `Theme.surface`（浅色主题）与 `Theme.accentForeground` /
  `Theme.inkStrong`（深色主题）里二选一，在这组取值下，浅色主题相对亮度 0.17–0.33、
  深色主题 0.14–0.26 两种文字都到不了 4.5:1。**结论只到这里为止**：
  在当前文字色与暖色方案下，要同时满足对比度就得非等距取色。
  换一组文字色（例如给中间档单独配一个文字色）禁区会移动甚至消失，
  所以不要把它写成「多级色阶不可能等距」这种普遍命题。
- 自动验证使用离屏平台，不启动应用窗口；以状态等待代替猜测时长的固定睡眠，测试在初始化阶段复位数据库，避免单个断言失败污染后续用例。具体命令与测试约定见 [运行命令](运行命令.md)。
- `qmltestrunner` **按函数名字母序**跑用例，不按文件里的书写顺序。挂在整窗上的弹窗与展开态
  （捕获框、切换确认框、任务选择器等）必须在 `init` 里复位：某条用例展开后不收起，
  焦点就一直留在 overlay 里，后面按名字排在它之后的用例会被 `overlayHoldsFocus` 挡住而莫名变红。
  弹窗关闭有退出过渡，过渡期间焦点仍在 overlay 里，紧接着要触发快捷键的用例先等 `overlayHoldsFocus` 变假。


## 2026-09 审计修复补充

- 页面激活时的同步查询失败，必须在处理函数中按 `pageActive` 过滤；组合刷新只在整轮起点清错，后续成功查询不能抹掉前面的失败。
- 待启动任务在删除后清空选择，改期后保留选择；恢复备份前清空旧库任务上下文，即使新库存在同号任务也不自动关联。
- 有退出动画的保存弹窗，从 `aboutToHide` 起拒绝再次提交，下次打开时解除门禁。连续录入的弹窗仍允许明确的新一条提交。
- 科目删除需要确认，提示解除任务、例行、课表、知识缺口关联（任务由 `deleteCategory` 显式解除，其余三张表靠外键 `ON DELETE SET NULL`）；编辑错误在编辑面板内部显示。
- 任务与知识缺口转任务的备注上限统一为 2000 个 QChar；来源说明也占长度，超限整体拒绝，保留原文。
- 知识缺口搜索中的 `%`、`_`、`!` 按字面处理。
- 备份偏好只允许应用使用的布尔、整数、浮点数和字符串；先校验编码类型与长度，再解码。嵌套容器、用户自定义类型及额外尾部字节拒绝恢复。数据库对象类型由 SQLite 解析结果识别，不能按 SQL 文本前缀猜测。**新增设置项必须是标量**：白名单外的类型不是跳过那个键，而是整份备份判为不可信、拒绝恢复。侧栏顺序等列表语义的设置一律存成分隔字符串（`appearance/sidebarOrder` 就是逗号分隔）。若将来确有必要存 `QStringList` 或 `QVariantMap`，必须同时扩白名单并补上对应的长度校验，否则用户在那之后产生的每一份备份都恢复不回来。
- CSV 导出带 UTF-8 字节序标记；具有公式前缀的文本添加单引号，避免表格软件执行公式。单引号是 Excel 的文本转义约定，Numbers、Google Sheets 会把它当普通字符原样显示——这是为了不让导出文件在别人机器上执行公式而接受的代价，不是缺陷。
- 结束专注在所有入口同口径：只有结束番茄循环才 `resetPomodoroCount()`，自由专注与主动休息不清零连续番茄数。菜单栏「停止」是第三个入口（专注页、仪表盘之外），它的 `canStop` 对三种模式都为真，必须在 `stopFocus()` 之前记下模式再判断——`stopFocus()` 会把模式复位。
- 在今日任务、仪表盘或本周计划页亲手完成**正在计时的那个任务**（复选框或「完成」弹窗），完成写库成功后就在原页结束这段专注，走与仪表盘「结束」同一个入口（`MainWindow.endFocusInPlace`）：番茄循环的连续计数归零，超过提醒时长的自由专注照样转去专注页确认。判据是「这一下完成的任务就是计时器当前任务，并且有专注会话」，不是「任务已完成就停表」——已完成的任务可以再练一轮，那种计时不能打断；番茄休息阶段没有专注会话，休息照常。外部 AI 接入把任务标成完成不会结束专注。撤销只翻回完成态，已结束的专注不恢复。提示条只有一个槽，「不足 3 分钟未计入」和「结束失败」都并进完成撤销条的文案，不单独弹，免得顶掉撤销入口。完成动画的延迟刷新期间，`focusCompleted` 也不立即刷新列表。
- 写入表单在开始关闭时阻断后续提交（`submissionClosed`，`onAboutToShow` 解除、`onAboutToHide` 置位）。退出动画有 180~220ms，这期间弹窗仍然响应键盘，用户补按的回车会打进同一个表单，写出第二条记录。新增写入表单时同步在 `tests/qml/tst_dialog_close_guard.qml` 补一行。
- 撤销窗口内被隐藏的行，任务数与完成率按当前可见列表预览；专注时长等历史读数仍取已保存记录，不随撤销窗口回退。
- 周复盘「预计用时任务」块的显示分钟在对账集合内按余秒从大到小分配取整差额，各行之和必须等于合计，原始秒数不修改；比例与规则判断只用原始秒数。整体科目不做分配（卡片不列整体科目清单，F2 的时长按秒向下取整，与饼图逐项取整的数一致）。
- 仪表盘窄窗自动收起计时面板并改用两列统计卡，不覆盖用户的面板显示偏好；需要计时时通过右侧入口进入专注页。
- 暂停只压暗圆环绘图，不压暗内部计时文字；休息和完成读数使用可读的文字颜色令牌。
