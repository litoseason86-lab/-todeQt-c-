## 已补齐的验收遗漏：F-02跨重启关闭意图

此前仅完成：QSettings保存失败时，当前进程关闭同步、显示错误，用户可以重试。

此前缺口：错误及待重试标记只在内存中；新进程构造函数仍读取磁盘旧enabled=true。原settingsAccessErrorOnDisableStopsEngineAndRecoversOnRetry只证明同一进程解除故障后重试，不证明保存失败后直接重启。

修复前使用临时INI权限故障及两个独立进程验证，结果为：

```json
{"diskStillEnabled":true,"enabledAfterFailedDisable":false,"freshProcess":{"enabledOnFreshProcess":true,"problemOnFreshProcess":false},"problemAfterFailedDisable":true}
```

这证明旧实现关闭意图没有跨进程保留，新进程开关恢复开启且失去错误状态。初始探针没有初始化同步引擎，不能写成已发生云端传输或数据泄漏。只使用临时数据库和INI，编译产物已删除。初始源码及日志位于`.superpowers/audit-status/sync_disable_probe.cpp`、`disable-probe.log`。

060现已补齐真实跨进程回归：保留磁盘旧true，分别在偏好持续只读、权限恢复但尚未成功重试时启动独立进程，走构造、initialize及本地测试引擎。旧实现两项均断言失败；修复后enabled与running均为false。用户显式重开成功后，再次重启能正常开启。

关闭记录在数据库旁独立保存，优先于旧开启偏好，恢复数据库不覆盖。未知文件、超限、目录、符号链接及删除失败均阻断；手动备份不能覆盖该记录。11项新场景及目标保护均先红后绿。用户已确认“独立关闭日志；双通道都失败明确告警”：两者都无法保存时本次同步停止，但无法保证下次启动仍关闭，必须明确提示。该边界不再当作意外漏修，也不扩大成无条件持久化保证。详见[060验收报告](060-同步关闭意图跨进程保护验收报告.md)。
