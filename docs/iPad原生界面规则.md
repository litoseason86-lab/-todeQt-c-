# iPad 原生界面规则（055）

- iOS / iPadOS 最低 26。Mac 与 iPhone 伴侣页继续使用 QML；iPad 无本机偏好时默认使用 SwiftUI 原生界面，已有旧版偏好仍保留。
  开关优先级为强制 QML 参数、原生参数、开发环境变量、本机 `ipad/nativeUI`；具体参数见 [运行命令](运行命令.md)。
  原生设置「外观 → 界面」的「使用旧版界面（下次启动生效）」写 false；旧版 QML 设置「外观 → 界面」的
  「使用新版界面」写 true，仅 iPad 提供此入口。两端共用本机 `ipad/nativeUI`，不进入同步，当前窗口不立即替换。
  QML iPad 分支保留一个版本；强制参数仍可用于回退。包标识与数据格式不变。
- Qt 保留应用入口、场景和事件循环。原生根视图只在 Qt 的窗口场景连上后挂载：同场景新建一个原生主窗口，
  不加载 QML 时 Qt 的 QUIWindow 保持隐藏。不使用子控制器挂载，也不链接 Qt 私有窗口类。
- 生命周期顺序：主线程同步执行原生外壳登记的编辑保存回调，再结束计时/保存检查点、写出同步、最后关库。
  QML 路径调用原有 `flushMemoEdits`；原生路径调用 `flushNativeEdits` / `PTLifecycleBridge`。
  只有自动保存编辑会话（备忘录标题、正文）登记同步保存；干净会话离页注销，保存失败的脏草稿保留回调重试。
  UIKit 先结束输入法组合，再由编辑器把上屏文字交给 Store；组合中间文字不进入自动保存。
  有「保存」「完成」「开始」按钮的显式表单进后台不保存、不提交、不关闭，未确认草稿留在表单中，回前台照旧。
  本期不持久化显式表单草稿，系统杀进程后可能丢失；即时设置（如昵称）每次控件写入已同步保存，无待保存编辑会话。
- 原生视图位于 `src/ui/ipad/Sources/IPadUI`，展示状态位于 `IPadCore`。
  **Swift 只放展示与交互状态**；统计归属、计时结算、任务与缺口业务由现有 C++ 服务负责。
  Objective-C++ 桥接只投影类型、转发信号和约束主线程，数据部分仅依赖 Foundation 与 Qt，在 Mac 上测试。
  信号用每个桥接对象自己的 QObject 上下文接收，跨线程发射时排队回主线程，释放后自动断连，回调弱引用对象。
- 导航采用 `TabView.sidebarAdaptable`，宽窗口默认侧栏。头部四个摘要：今日未完成任务、专注读数、
  本周未完成任务、到期/逾期知识缺口；其余七项按本机侧栏顺序显示。废纸篓与设置在最后的固定分组，不能重排。
  窄窗口固定今日任务、专注计时、本周计划、仪表盘，加「更多」；更多里的其余页面沿用侧栏顺序，最后仍是废纸篓、设置。
  宽窗侧栏上向左横扫即收起到顶部标签栏（10-12 用户要求；手势挂在整条侧栏上，只认横扫，与列表手势同时识别），直接置 `sidebar.isHidden`，过渡动画由系统做。
  收起前后标签的可见性一律不变（见下文 055-R4 标签栏）：10-12 先后试过「按侧栏显隐切换今日任务、专注、本周的可见性」和「过渡结束后再切」，真机上分别出现第一次收起顶部标签停在侧栏大字号被裁、展开时列表闪出多余三行，所以改为固定可见性。
  13 页在 `PageRegistry` 注册真实页面，每个根级 Store 只装配一份，没有占位分支。
- 不显示跨页迷你计时条（底部附件位）：10-12 用户认为没用还挡内容，已去掉；计时在专注页和侧栏摘要块里看，⌘↩ 照常暂停/继续。
  通用提示条只画在当前显示那一页的底部安全区（窄窗「更多」根列表也画），让开标签栏，其它页不读提示条、不跟着重排；提示单槽，替换、超时或主动关闭通知旧调用方，
  点击动作不再触发退场回调。P4 撤销删除用退场回调提交待删项。
  旁白开启时，动作提示与共享删除槽的自动超时同步暂停；关闭旁白恢复完整窗口；新操作替换、手动关闭、备份、恢复、补录和退出仍可按既有规则提前提交。主动播报不强制移动焦点。
- 恢复备份期间由 `BackupService.operationBlocksUi` 驱动全屏遮罩；导航、计时、快捷键、捕获和提示动作全部停用。
  读取失败保留上一份有效摘要并显示重试，不把失败当成空数据。记一笔只收标题，经 `captureGap` 保存，失败保留输入，
  不打断当前计时；各页工具栏均可打开，只有专注页带当前任务/科目来源，其它页无来源。
  工具栏按钮锚定浮层，窄窗口由系统适配成面板。宽窗浮层定宽 420，输入区至少四行、打开即聚焦（10-13 用户反馈原浮层缩得很小记不了东西）；
  宽窄按打开它的按钮所在窗口判断——浮层内容自己的水平尺寸类别恒为 compact，按它判断会让宽窗也走整页分支、浮层缩到最小尺寸。
- 外接键盘：⌘1–⌘7 按侧栏前七项切页，⌘⇧K 记一笔；⌘N 到今日任务就地起一行新任务，⌘↩ 转发专注开始/暂停动作。
  选页保存到本机 `ipad/selectedPage`，不参与同步。
- 默认系统背景，强调色浅色 `#8d5f2b`、深色 `#e6b980`。本机 `ipad/useWallpaper` 打开时，
  工作区显示 `AppSettings.backgroundTheme` 的现有 Qt 图片，列表行用纸面底色；深色壁纸固定为深色。
  语义颜色用 iPad 颜色资源，浅深数值由 `IPadThemeGate` 与 `Theme.qml` 对齐。
  减少动态效果与降低透明度跟随系统，外壳没有自定义过渡动画，恢复遮罩在降低透明度时使用不透明纸面。
- 桥接回调采用每个 Store 独占适配器实例：各 QObject 连接接收同一 C++ 服务广播，不串接前任回调、不混用多观察者。
  `CoreBridges` 供共用动作与即时读取；页面订阅独立实例，释放或停页不会注销别人的信号。
  按逻辑今日读取的仪表盘、任务、计划、时间轴、课表、历史、统计、知识缺口、倒计时与废纸篓都订阅日界变化；隐藏页按各 Store 的活跃门禁延后重读。
- 外壳计时与统计分开刷新：tick、任务/运行状态/阶段/模式信号只读取轻量计时值对象；任务、记录、缺口、日界、外观与恢复状态失效时重读完整快照。
  轻量刷新保留统计摘要、恢复遮罩和之前的读取错误，不每秒重查统计。
- 界面响应（10-12 真机测速，测法见 [运行命令](运行命令.md)「测速」）：外壳状态按变化频率分项存放——外观、阻断遮罩、到期缺口数、
  有没有计时、计时读数、其余字段（`ShellStore.details`）——视图只读自己用到的项；整份 `snapshot` 只是拼回来的兼容入口，视图不读。
  外壳根视图只搭标签结构，不读选中页、计时、计数和提示条：侧栏摘要块、侧栏底栏、快捷键、壁纸与配色、恢复遮罩、选中页同步都是各自的小视图或修饰器；
  每页的外壳修饰只读外观，记一笔按钮、提示条、出错条各自成小视图。页面要跟随选中页用 `onShellSelectionChange`，不在页面 body 里读它。
  专注读数每秒变：今日任务、仪表盘、今日专注只读 `FocusStore.activeSession`（有没有会话、哪个任务、哪天几点开始），
  「专注中 mm:ss」和时间轴上进行中那一块各自单独读秒数。被多处读的状态不要用原地改字段的写法更新（`x.field = …` 每次都通知，
  不比较新旧值）；整项赋值时值没变不通知。改前计时每跳一秒主线程忙约 155 毫秒、切页约 175 毫秒，改后约 0 和 76 毫秒。
  根控制器固定 `headroomUsageLimit = .inactive`、着色模式为正常：iPadOS 27.0.1 弹出表单或浮层时系统会改这两项，SwiftUI 随之整棵重排，
  开、关各卡约 200 毫秒（记一笔浮层由 167 降到 31 毫秒）。系统表单弹出时背景缩放仍会让背后整页重排、文字重画（开约 250、关约 200 毫秒），
  没有公开开关，常用编辑改用行内或浮层才能避开。
  渲染约定（10-13 astra 优化，画面与交互不变）：只随局部状态变的部分拆成子视图自己读（今日任务的页头、目标卡、每一行、多选底栏，
  本周页头只读 `details.weekPendingCount`，统计的柱图与读数、环图与图例分开，专注历史当天明细）；同一轮布局里重复用到的结果只算一次
  （今日任务的未完成/已完成两段、课表每天的泳道位置），不跨刷新缓存；专注历史日期格、统计柱图按数据比较，没变就跳过重建；
  日期格式器按格式复用、Foundation 默认时区变了重建；主题颜色资源按需加载一次、仍按窗口特征解析最终颜色。
  10-13 无计时复测（对比交互对齐后）：首次切页最长平均 75→58 毫秒，表单开关最长平均 142→68；今日任务页收放侧栏（总忙约 230–260）、
  详情浮层首开（约 84）没降下来，今日任务页冷进入主线程累计约 840 毫秒（只有一段超过 50），未定位。
- 任务列表对齐提醒事项（10-12，今日任务、仪表盘、本周计划、搜索共用 `TaskRow`）：点标题就地改标题和备注（`InlineTaskEditor`，全应用同一时间只编辑一行，
  编辑期间持有交互令牌、列表刷新暂缓，结束时只交改过的字段；标题清空不算改；点别处、回车或做别的行操作都先保存）；ⓘ、左滑「详情」、长按「编辑详情」
  在宽窗从这一行弹出详情浮层，窄窗系统改成整页表单，点「完成」或点外面都保存，只有「取消」放弃；左滑「删除」可一滑到底，右滑「完成记录」保留；
  长按菜单是编辑详情、开始专注、完成并写记录、改期、复制到今天、删除，按住拖动排序。今日任务页去掉「未完成 / 已完成」切换：打勾后在原位置停留
  1.5 秒（连续打勾从最后一次起算、一起收；`TodayStore.lingering`）再收进列表下面可展开的「已完成 · N」组，展开状态同一次运行内记住；
  卡片底部「＋ 新任务」就地新建（建在逻辑今天、无科目，细节点 ⓘ 补），回车建好接着起下一行，空行回车、点别处、Esc 结束，有字的先建上；⌘N 同一入口。
  多选从右上「•••」→「选择任务」（本周计划、废纸篓是「选择」）进入，点行切换选中，底部浮出操作条：今日任务是完成、改期、删除，本周计划多「结转到今天」，
  废纸篓是恢复、彻底删除（仍先确认）。批量完成、批量删除由服务一个事务做（`TaskManager::setTasksCompleted`、`deleteTasks`，一条不行整批回滚）；
  批量完成一条提示带撤销，批量删除直接进废纸篓，提示给「查看」。今日专注点记录块与「补录」、目标倒计时新增与编辑、知识缺口「新增」也改成浮层。
  没有改的：备忘录（对齐的是「备忘录」App，删除一律先确认）；知识缺口列表长按补齐今天做、排期、解决、编辑、删除，删除仍先确认，列表不是系统列表所以没有左右滑；
  倒计时同理没有左滑；知识缺口的编辑 / 排期 / 解决、改期单条、完成并写记录、今日目标仍是表单。
  浮层只挂在要打开的那一行（每行常挂锚点会让整页重排变重）。10-13 真机：任务详情开约 100、关约 35 毫秒（原表单约 250 / 200），
  新建任务开约 65 毫秒，倒计时开约 85–100 毫秒；应用启动后第一次弹键盘约 400 毫秒是系统准备输入法的开销，之后约 70 毫秒。
- Swift 数据层在 Mac 用 `swift test`，包含在 `IPadSwiftTests`；桥接由 `PTShellBridgeTests` 等领域测试验证。
  SwiftUI 界面不启动模拟器、不做界面自动测试；侧栏/标签栏切换、分屏与键盘、拼音、壁纸、恢复遮罩必须在 iPad 轻量确认。

iPad 与 Mac 的主要呈现差异（业务口径共用 C++）：

| 页面 | iPad 呈现与交互 |
| --- | --- |
| 仪表盘、今日任务、专注计时 | 宽窄布局自适应、系统任务表单；滑动完成/删除、长按拖动；专注三段居中与细线圆环、计时中无操作自动隐藏控制、原生沉浸 |
| 本周计划、今日专注、课表 | 本周菜单/拖动改期及键盘；今日专注原生日期/记录表单；课表宽窗周网格、窄窗单日，时间/节次共用服务值 |
| 知识缺口、备忘录、倒计时 | 系统两栏/推入详情、常驻缺口操作；UIKit 纯文本与组合输入、自动保存；原生日期表单、倒计时主卡/列表 |
| 专注历史、数据统计 | 六周月历与服务投入档位；Swift Charts 可点选读数、旁白；周期与周复盘取服务结果 |
| 废纸篓、设置 | 原生系统确认与恢复反馈；设置宽窗两栏、窄窗子页；系统文件/文件夹选择，不提供 Mac 菜单栏、全局热键与外部 AI 接入 |

- 055-P3B 核心桥接按领域提供 Foundation 值对象、IPadCore 协议与 IPadUI 适配器。
  列表与报告读取携带 `valid/error`，失败不附半份数据；适配器转为 `throws`，页面保留上一份有效数据。
  设置快照只投影 QSettings 当前值；每日目标经独立日期接口读写。Swift 不拆 QVariant 字典、不重算业务口径。
- 写入用 `NSError` 转为 Swift `throws`，优先保留服务原文。调用期间同步失败归当前调用，背景失败单独回调，
  同一失败不重复显示。任务与历史编辑只交明确设置过的字段；nil 表示未改，清空归属使用显式枚举或 -1 哨兵。
  日期使用 `yyyy-MM-dd`，时刻统一使用不带时区的本地墙钟串（`yyyy-MM-ddTHH:mm:ss.SSS`），读回兼容旧的整秒或带时区串，缺失编号统一为 -1；宽整数越界拒绝，不截断编号。
- 编辑与拖动持有交互令牌；令牌内部 owner（登记所有者）为 QObject，显式结束或释放都会解除刷新冻结。
  逻辑今日只由 `LogicalDay` 与 `LogicalDayService` 提供，Swift 消费变化信号，不设置第二套日界计时器。
- 非单例服务在 `installNativeRoot()` 前按名字登记，登记处保存 `QPointer<QObject>` 弱引用并按类型读取，
  服务销毁自动失效。进 Swift 模块的公开头文件只含 Foundation，不出现 Qt/C++；支撑头在 modulemap 排除。
- 原生根通过 `CoreBridges` 环境持有共用桥接、`PendingDeletionStore` 与 `TaskActions`。
  任务与专注/休息记录删除走同一撤销槽；专注历史桥接不提供直接删除。撤销提示被其它提示替换时先提交，
  退场只收起自身提示，提交失败带原条目标题。完成、取消完成、删除与去专注统一经 TaskActions，
  专注业务经 `FocusFlowHook` 交给根级 `FocusStore`；完成正在计时的任务会结束对应会话，需要确认时切专注页。
  桥接数据与信号由 Mac 上的 `PTCoreBridgeTests` 验证；P3B 无可见页面变化。
- 同步日志与备份列表另有区分「空」和「读不出来」的读取接口：`SyncController::readSyncLog` / `readLogCount`（数据库没开或查询失败报 `Database`）、`BackupService::readBackups`（文件夹不存在算没有备份；在却读不了或不是文件夹报 `Storage`）。iPad 设置页用它们；旧的 `syncLog`、`logCount`、`listBackups` 失败时仍回落为空，Mac 页面照旧。
- 「已排」分钟由 `TaskManager::readPlannedMinutesByDay(start, days, excludedTaskId)` 按天给出（iPad 本周计划组头、今日页副标题）：口径与 Mac 页面里的加总一致——当天全部任务的预计用时之和，完成与否都算，负值按 0，撤销窗口里待删的那条不算。Swift 不自己加总。
- P4-1 的今日任务页由 `TodayStore` 消费逻辑日、任务、统计和缺口桥接：竖向滚动不触发排序，只有长按拖动结束才提交一次 `moveTaskBefore`；编辑或拖动期间冻结列表刷新，令牌释放后补读一次。读取失败保留上一份有效数据并显示重试原因，待删除任务从可见列表和排序候选中排除。
- P4-1 的专注页由根级常驻 `FocusStore` 投影 `FocusSessionController`：开始、暂停、继续、结束、任务/模式切换确认、超长自由专注确认、自动休息与自动下一个番茄只按 C++ 返回值做展示动作。`TaskActions` 完成任务后经 `FocusFlowHook` 结束对应会话；需要超长确认时切到专注页，不把确认路径伪装成已结束。圆环和自动衔接动画响应 `reduceMotion`，到点提醒预约失败和系统通知发送失败分别显示提示。
- P4-1 的仪表盘只读取统计服务给出的今日快照、连续天数和累计秒数，任务区保留服务顺序并取前 8 条；完成、删除、完成记录和进入专注统一走 `TaskActions`。仪表盘刷新开始时清空本次错误，任一路读取失败都保留该路旧数据并保留错误提示。由于桥接回调是单槽，仪表盘必须使用独立的任务、统计、设置适配器，不能覆盖其它 Store 的回调。
