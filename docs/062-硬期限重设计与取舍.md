# 062：硬期限重设计与取舍

日期：2026-10-17。状态：分阶段方向已获用户确认，尚未实现。对应总表 A021／A023。

用户确认：接受macOS独立执行器、iOS协作取消，双端统一中断后可恢复；超时优先保持一致性，必要时进入受限状态。完整存储隔离和绝对退出期限另行评估。具体预算与阶段协议仍需测量和设计，不把本次确认扩大为任意强退或数据丢失授权。

## 当前阻塞与影响

`BackupService::shutdown` 仍等待 worker 真实结束；恢复完成回调在主线程打开、迁移、验证数据库和写设置。`AppLifecycle::shutdownSteps` 的草稿、待删与计时落盘先于备份收尾。`SyncEngine` 等待线程池5秒后放弃回收不等于旧写者已停止。仅隔离备份计算不能证明整个应用限时退出。

必须分开三个指标：操作执行预算、用户取消后停止等待的响应预算、完整进程退出预算。现有120秒仅是协作执行预算。永久内核I/O无法用线程取消安全强制中断；发送终止信号成功也不等于系统已回收进程。

## 建议方案

| 方案 | 收益 | 代价与不可承诺项 |
|---|---|---|
| macOS独立备份执行器；iOS继续协作取消 | Mac主进程可限时放弃等待预检、导出等隔离工作；双端共用持久化恢复规则 | 平台保证不同；helper未确认结束前不能恢复同文件写入；iOS无永久I/O终止保证 |
| 全存储服务隔离与异步化 | 将主线程数据库和偏好阻塞从UI/退出控制路径移走 | 跨业务的大型架构改造，影响草稿、计时、错误传播和一致性；iOS隔离模型仍需单独设计 |
| 期限后强退优先 | 用户可尽早结束应用等待 | 可能丢失未落盘操作并留下待恢复状态；仍不能承诺操作系统永久阻塞下绝对期限回收 |

推荐第一步采用平台不同的执行器，统一“中断后可恢复、不误报成功”，优先数据一致性。超过预算后进入受限状态，不宣称安全取消，不开启下一写者。完整存储异步化另作后续设计，不能用新增helper关闭整个A023。

## 中断一致性协议

独立执行器通过受控IPC接收操作身份、阶段和受限路径，不复用MCP helper，不传QObject或数据库句柄。平台后端实现，业务经接口调用。权限、路径校验和白名单必须阻止任意文件代理行为。

恢复安装需持久化操作身份、源摘要、原库恢复点、目标设置与阶段；原库无写者且恢复点完整后才安装。至少覆盖提交前死亡、文件替换后应答丢失、数据库已替换而设置未应用、回滚中死亡、父进程先退出等截面。结果未知时依据日志和文件身份判断，不能当成“未提交”。数据库与偏好不是一个事务，重启先恢复决策，再开放业务及同步，并保留060关闭记录优先级。

QSaveFile的原子替换不等于断电后所有数据已持久落盘；刷盘、目录同步与真实文件系统条件需明确验证。不因使用rename就承诺断电零损失。

## 平台证据与待验证

059已有iOS通用子进程限制及Qt工具链探针记录；本次尚未重新核对Apple在线资料。App Extension不当作通用helper替代品。Mac签名沙盒、security-scoped访问、XPC或文件描述符传递需要官方资料和隔离样例验证，普通未签名进程探针不能代表全部分发形式。

本轮不部署或操作设备。先做代码设计、非界面隔离探针、阶段故障矩阵；签名沙盒和iPad生命周期单列设备门禁。

## 用户选择后才实施的部分

1. 是否接受Mac进程隔离、iOS协作取消的不同保证。
2. 期限后优先一致性并保持受限状态，还是接受未落盘操作丢失、要求尽快退出。
3. 分别设定操作、取消响应和退出预算；数值应参考正常大备份测量，不能任意给一个“绝对安全”的秒数。

在这些选择及必要平台证据完成前，A021／A023保持重设计中。
