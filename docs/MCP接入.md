# 外部 AI 接入（MCP）

番茄 Todo 提供本机 stdio MCP 接口。外部 AI 可读取任务、科目、专注统计和知识缺口；单独开启写权限后，可新建任务、编辑标题/科目/预计用时/备注、改期、设置完成或重新打开。

不提供删除、批量事务、排序、计时启停、知识缺口写入、任意 SQL、文件操作或命令执行。

## 启用与配置

1. 打开番茄 Todo，在「设置 → 数据与管理 → 外部 AI 接入」打开「允许外部 AI 接入」。默认关闭。
2. 需要 AI 修改任务时，再打开「允许 AI 修改任务」。操作不会逐条弹窗确认。
3. 点击「复制 MCP 辅助程序路径」，将它添加到支持本地 stdio 的客户端。部署后的配置示例：

```json
{
  "mcpServers": {
    "pomodoro": {
      "command": "/Applications/番茄Todo.app/Contents/MacOS/PomodoroTodoMcp",
      "args": []
    }
  }
}
```

配置不需要填凭据或模型密钥。辅助程序由 AI 客户端启动；它不会启动或前置番茄 Todo。番茄 Todo 未运行、接入关闭时，仍能完成初始化和发现全部 10 个工具；真实数据调用会说明不可用原因。应用上线后下一次调用会重新连接，无需依赖工具列表变更通知。辅助程序不设握手期限，客户端何时初始化都可以；客户端关闭标准输入它就退出，异常退出的原因写在 stderr。

设置区显示监听状态、当前本地连接数、正在进行的编辑/拖动/待删除/恢复/退出（写明是哪个页面的哪种操作），以及最近一次操作类型和结果。关闭接入会断开连接、使旧会话失效，并同时撤销写权限；重新打开后只恢复读取，需要 AI 修改任务时再单独打开写权限。写权限也可单独关闭。旧版本关闭接入并不撤销写权限；从旧版本升级上来时，首次启动会清掉“接入关着却仍保留写授权”的遗留状态。

## 权限与数据流向

客户端 → 包内辅助程序 → 本地 socket → 主应用业务服务 → 数据库。只有主应用操作业务数据，执行时逐次检查权限、会话和阻断状态。

本版信任边界是同一个 macOS 用户账户。同账户进程可能读取本地凭据，并非每个 AI 客户端独立授权；客户端报告的名字不用于鉴权。端点目录权限为 0700，凭据和 socket 为 0600，只接受同 UID 连接。

查询结果会交给你配置的 AI 客户端，客户端可能再发送给其模型服务。备注、任务标题和知识缺口等外部文字可能含提示注入指令；模型可能误信它们并修改任务。仅给可信客户端开放写权限。界面不记录完整请求内容，最近操作只显示类型、时间和结果。

接入策略保存在本机 `mcp/` 设置组，不进入备份。恢复备份保留本机授权，但会使旧会话失效。

## 工具与写入规则

| 工具 | 用途 |
| --- | --- |
| `pomodoro_get_status` | 连接状态、会话、逻辑今日、日界与阻断信息 |
| `pomodoro_list_categories` | 查询科目编号 |
| `pomodoro_list_tasks` | 按日期和完成状态查询任务 |
| `pomodoro_get_task` | 按编号读取完整任务及状态令牌 |
| `pomodoro_get_focus_summary` | 查询有效专注统计 |
| `pomodoro_list_knowledge_gaps` | 查询缺口，支持状态、科目、搜索和到期筛选 |
| `pomodoro_create_task` | 新建任务，支持当前会话内去重 |
| `pomodoro_update_task` | 修改标题、科目、预计分钟、备注 |
| `pomodoro_reschedule_task` | 调整日期 |
| `pomodoro_set_task_completed` | 设置完成或重新打开 |

写操作必须使用状态工具返回的 `app.app_session_id`（按 UUID 比较，十六进制大小写不限）。修改已有任务还需带最新 `expected_state_token`。不要按标题猜编号；同名任务可以存在。

工具清单带 MCP 注解：只读工具标 `readOnlyHint`，四个写工具标 `idempotentHint`，修改已有任务的三个写工具另标 `destructiveHint`，全部 `openWorldHint: false`。注解只供客户端决定展示与确认方式，授权仍由主应用逐次检查。初始化结果带 `instructions`，提示模型先调用状态工具、把用户文字当数据。

- 创建：每次有意新建生成一个新的随机 UUID v4；同一次创建重试沿用原键。格式正确不代表随机，不能反复复制同一个示例键。去重最多保留当前会话 10,000 次创建，不缓存用户文本。
- 创建重放：返回原编号和当前任务，或 `deleted` / `pending_delete`。这两种状态也表示原创建已成功，不能再建一条。创建成功后读取失败会给出 `created_task_id` 和 `creation_committed: true`，沿用原键取回结果。
- 目标状态重试：编辑、改期、完成状态已满足时直接返回 `changed: false`，不再次写库，也不重新排序。存在真实修改时必须通过状态令牌检查。
- 字段：缺省表示不改；JSON `null` 拒绝；`notes: ""` 清空备注，`estimated_minutes: 0` 清除预计用时，`category_id: 0` 清除科目。预计分钟只能为 0—1440 的整数，不能依靠服务夹紧。旧任务可能有超过 1440 的历史预计分钟，未请求修改它时保留；负的历史预计分钟按“未设置”报 0。只写被要求修改的字段：未请求改标题时不改写标题，2026-07-19 之前超过 100 字的旧标题不会挡住改备注、预计用时或科目。
- 不承诺跨主应用崩溃的恰好一次创建。会话改变后先查明结果，不能自动换新会话和新键重发。

所有业务错误均为 `isError: true`，文本包含完整 JSON 错误，不带另一种形状的 `structuredContent`。所有错误的 `retryable` 都为 `false`：关闭客户端自动原地重试，按 `next_action` 处理。`APP_BUSY` 中的编辑、拖动、待删除原因需要用户完成操作，等待时间不是新的授权。

错误信息写明对象，例如“任务 #12 不存在”“科目 #5 不存在”。写入被数据库拒绝时报“保存失败，任务 #N 未被修改”；写入已经生效、却没能把结果交出来时（重读失败、响应超出预算、库中数据超约定等），一律报“修改已保存，但未能返回最新数据”，`details` 带 `task_id` 与 `write_committed: true`，请重新读取核实，不要当作失败再改一次。库中数据本身超出输出约定时（例如手工改库留下的非法日期），`details.reason` 为 `stored_data_out_of_contract` 并列出字段，需在应用中修正数据，数据库本身可用。

## 查询范围与界面协调

- 任务和专注统计最多查询连续 31 个逻辑日。任务默认 50、最多 100 条，超过上限明确报错，请缩小范围或提高 limit。
- 缺口可用 `due_state` 和到期起止日期筛选；`unscheduled` 表示未排期。按 `after_id` 递增续查，`has_more` 和 `next_after_id` 表示下一页。续查不是固定快照：新条目编号更大，可能出现在后页；修改状态也可能改变筛选结果。
- 日期按应用的逻辑日界理解。当前逻辑日尚未结束，统计结果会标为部分数据；只统计已经记录的有效专注，正在计时部分不进入历史汇总。
- 用户编辑或拖动任务时阻止外部新写入，列表重建延后；打开编辑入口先按编号重读。新增任务弹窗不阻断。
- 撤销删除窗口内，任务列表隐藏该任务，单查与目标写入返回 `APP_BUSY`。AI 修改其他任务不会替用户提前提交删除，也不会顶掉撤销提示条。

## 部署、路径与故障处理

辅助程序固定在 `Contents/MacOS/PomodoroTodoMcp`，只链接 Qt Core/Network。运行不依赖 Node、Python 或开发 shell；本项目仍使用本机 Qt 6.10.3 安装及 rpath，并非可任意复制到其他电脑的独立发行包。

socket 位于应用数据目录的 `mcp/s`。macOS 路径按编码字节数最多 103 字节，用户名较长时可能超限；设置区会明确报路径错误，不会截断或偷偷换目录。请求最多 64 KiB，完整响应最多 1 MiB，最多 8 条本地连接，每连接最多排队 16 个请求。

- 超过 64 KiB 的单条请求、重复的在途请求编号：只拒绝那一条（编号为 null 的 `-32600`），辅助程序继续服务其他请求。
- 背压：主应用等上一条结果发完才执行下一条请求，并行的几条大结果按顺序送达，不会因为发送缓冲里叠了多条而断线。客户端暂时不读 stdout 时，辅助程序停在消息边界，不再解析同一批里后面的请求——已经读进来的字节留着，读走响应后自动继续，一条都不丢。缓冲上限按协议允许的最坏情况留足余量（最多 16 条在途结果各占一条消息上限，外加背压阈值）。
- 每个 AI 会话各拉起一个辅助程序；辅助程序空闲 30 秒会释放连接，下次调用自动重连。8 条连接都在使用时，状态工具报告 `unavailable_reason: connection_limit`，数据调用返回 `APP_UNAVAILABLE`（`details.reason` 同名），请关闭不用的 AI 会话后再试。

更新部署后，退出再打开主应用，并在客户端重连 MCP，才能让两个进程都加载新版本。关闭接入、恢复备份或主应用重启都会改变会话。`STATE_CONFLICT` 要重新读取任务；`PERMISSION_DENIED` 要检查写开关；`APP_UNAVAILABLE` 要先看 `details.reason`：`connection_limit` 是连接数满了，其余情况检查主应用、接入开关及私有协议版本。不要因为发现了写工具就认为已经有写权限。
