# 运行命令（VSCode 终端）

在项目根目录 `/Users/zerionlito/code/番茄todo` 下执行。配置必须使用目标 Qt SDK 自带的 `qt-cmake`。

> `<qt-cmake>` 替换成目标 Qt SDK 的完整工具路径。本机已验证路径为
> `/Users/zerionlito/Qt/6.10.3/macos/bin/qt-cmake`。当前 Homebrew Qt Quick 框架最低要求
> macOS 26，不用于正式部署。配置阶段会打印 `使用的 Qt: <版本> @ <路径>`，照着确认一次再往下走。
>
> **Mac 只用两个构建目录**：`~/pt-build`（部署）与 `~/pt-audit`（验证）；iOS 另用 `~/pt-ios`，永不部署（见下方「iOS 构建」）。
> 别按用途另建一次性目录——每个 300–450M，只增不减，此前在 `/tmp` 下攒到过 3.3G；
> 放在 `~` 之后更没有任何自动清理。需要隔离的场景用完当场删。
>
> **构建目录不要放在 `/tmp` 下。** macOS 的 `/tmp` 是指向 `/private/tmp` 的符号链接，
> moc 生成的相对包含（`../../../../Users/...`）按真实路径解析会落到 `/private/Users/...`，
> 找不到源码头文件。Qt 6.9 之前一直能编过，是因为它的 moc 调用里带 `-I/usr/local/include`，
> 那条搜索路径拼上同一串相对路径恰好回到 `/Users/...`——纯属偶然。
> Qt 6.10 换了 include 标志集（`-isystem`/`-iframework` 且带 `-isysroot`），
> 偶然性没了，整个构建直接失败。用 `~/pt-build` 这类没有符号链接的路径。

## 日常构建与部署（RelWithDebInfo）

构建完成后会自动把最新应用包同步到固定启动入口 `/Applications/番茄Todo.app`。

```bash
<qt-cmake> -B ~/pt-build -S . \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo -DPOMODORO_TODO_DEPLOY_LOCAL=ON
cmake --build ~/pt-build --target deploy-local-app -j8
```

部署脚本 `cmake/DeployLocalApp.cmake` 的顺序是：复制到暂存目录 → 校验主程序和 MCP 辅助程序存在且可执行 →
旧包改名备份 → 原子 rename 换上新包 → 清理备份并刷新 `lsregister`。任一步失败都会把旧包放回原位，
不存在「先删旧包再复制」的空窗期。

可选开关：

```bash
# 跳过自动部署（审计/CI/临时目录构建用，避免覆盖固定入口）
<qt-cmake> -B ~/pt-audit -S . \
      -DPOMODORO_TODO_DEPLOY_LOCAL=OFF

# 打开 QML 调试钩子（默认 OFF；只有要跑 qmlprofiler / QML 调试器时才需要）
<qt-cmake> -B ~/pt-build -S . \
      -DPOMODORO_TODO_ENABLE_QML_DEBUG=ON
```

> **不要在同一个构建目录里混用这两种配置。** `POMODORO_TODO_DEPLOY_LOCAL` 是 CMake cache 变量，
> 值会持久化在构建目录里：在 `~/pt-build` 先跑过一次 `=OFF`，之后不带该参数重新配置也不会恢复成 `ON`，
> `deploy-local-app` 目标不会被创建，部署会**静默失效**。约定：部署用 `~/pt-build`，审计/测试用 `~/pt-audit`。

部署后分别校验主程序和辅助程序一致：

```bash
shasum -a 256 ~/pt-build/PomodoroTodo.app/Contents/MacOS/PomodoroTodo \
  /Applications/番茄Todo.app/Contents/MacOS/PomodoroTodo
shasum -a 256 ~/pt-build/PomodoroTodo.app/Contents/MacOS/PomodoroTodoMcp \
  /Applications/番茄Todo.app/Contents/MacOS/PomodoroTodoMcp
```

每组两行摘要必须相同。构建和部署不会启动应用；若旧进程仍在运行，手动退出并重新打开后才能加载新版本。

iPad 版已随 050 转正，与 Mac 的云盘同步已随 050、051 完成，现状见 [plans/README](../plans/README.md)。iOS 构建只产出应用本体：

最低 iOS / iPadOS 版本为 26，iPhone 伴侣页与 iPad 原生外壳使用同一应用包。

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer

# 配置：iOS 套件是交叉编译的，必须用 QT_HOST_PATH 指向本机的 macOS 版 Qt
~/Qt/6.10.3/ios/bin/qt-cmake -S . -B ~/pt-ios -G Xcode -DQT_HOST_PATH=$HOME/Qt/6.10.3/macos

# 编译检查（不签名，不需要设备）
cmake --build ~/pt-ios --config Debug -- -sdk iphoneos CODE_SIGNING_ALLOWED=NO

# 签名编译（需要在 Xcode 登录 Apple ID；团队 ID 可用 defaults read com.apple.dt.Xcode | grep teamID 查）
cmake ~/pt-ios -DPOMODORO_TODO_IOS_DEVELOPMENT_TEAM=<团队 ID>
xcodebuild -project ~/pt-ios/PomodoroTodo.xcodeproj -scheme PomodoroTodo -configuration Debug \
      -destination id=<设备 UDID> -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
```

签名编译必须直接用 `xcodebuild` 并带 `-scheme`：`cmake --build` 不传 scheme，xcodebuild 会忽略目标设备，
免费个人团队登记不上设备，也就生成不了描述文件。

装到设备与查看（`xcrun devicectl list devices` 查 UDID；第一次安装后要在设备的「设置 → 通用 → VPN 与设备管理」信任开发者）：

```bash

xcrun devicectl device process launch --device <UDID> --console --terminate-existing com.zerionlito.pomodorotodo
xcrun devicectl device capture screenshot --device <UDID> --destination <截图路径>
```

获用户明确授权装机后，轻量确认顺序：

1. 正常启动确认进入原生界面（若之前明确选过旧版，先用旧版设置入口切回）；保留原应用数据与同步文件夹。

3. 开显式表单填一半，切后台再回前台：草稿还在且未提交；在备忘录改标题/正文后进后台：自动保存完成，再看另一台刷新。
4. 日常使用确认导航（含宽窗侧栏左滑收起）、专注页计时控制自动隐藏、键盘/拼音、窗口缩放、安全区和文件 App 操作；需要的详细项目见
   055-P5 的「真机确认清单」（计划已留档，`git show bfa3f6b:plans/055-P5-切换与回归.md`）。冷启动时间只在真机测，不启动模拟器。

Swift 编为两个独立静态库：`IPadCore` 只依赖 Foundation / Observation，`IPadUI` 依赖 SwiftUI / UIKit，
经 Objective-C 模块 `PTBridge` 调用桥接，不链接 Qt。新增 Swift 文件必须登记 CMake 的 iOS 源文件清单。
新增桥接头放 `src/platform/ios/bridge/`，模块用 umbrella 目录自动收集；iOS 的 Xcode 项目改动后须重新执行 `qt-cmake`。

混编约定（CMake 4.0.2 + Xcode 27 / Qt 6.10.3 已实测）：

- C 系语言的告警选项用 `COMPILE_LANGUAGE:C,CXX,OBJC,OBJCXX` 限定，避免 `-Wall` 进入 `OTHER_SWIFT_FLAGS`。
- 语言版本用 `XCODE_ATTRIBUTE_SWIFT_VERSION 6.0`，不用 `Swift_LANGUAGE_VERSION`，避免与工程默认版本冲突。
- 在 `find_package(Qt6)` 之前设置 `CMAKE_POLICY_DEFAULT_CMP0142 NEW`，避免链接时生成不存在的 Swift 搜索路径副本。
- 纯 Swift 库关闭 `AUTOMOC` / `AUTORCC`，避免空 moc 编译单元的 libtool 告警。

尚未找到有效关闭设置；项目没有 AppIntents 功能，不为消掉提示增加该框架依赖。此提示由元数据处理步骤产生，

### iPad 每 7 天重签覆盖安装

免费个人团队的描述文件只管 7 天。到期后应用打不开，但数据还在：重签之后覆盖安装，数据保留，同步自动接上。
**不要删掉 App 重装**——那会丢掉 iPad 上的数据，同步也要重新选文件夹、确认加入。

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer UDID=<设备 UDID>
rm -rf ~/pt-ios/Debug-iphoneos/PomodoroTodo.app \
  && xcodebuild -project ~/pt-ios/PomodoroTodo.xcodeproj -scheme PomodoroTodo -configuration Debug \
       -destination id=$UDID -allowProvisioningUpdates -allowProvisioningDeviceRegistration build \
  && codesign --verify --deep --strict ~/pt-ios/Debug-iphoneos/PomodoroTodo.app \
  && xcrun devicectl device install app --device $UDID ~/pt-ios/Debug-iphoneos/PomodoroTodo.app

# 新描述文件的到期时间
security cms -D -i ~/pt-ios/Debug-iphoneos/PomodoroTodo.app/embedded.mobileprovision \
  | plutil -extract ExpirationDate raw -
```

- 先删旧的 `.app` 再构建：二进制没变时，xcodebuild 只把新描述文件放进包里却不重新签名，
  `codesign --verify` 会报 `sealed resource is missing or invalid`，这样的包装机会被拒。
- 装的是 `~/pt-ios` 配置时的那份源码：先看 `~/pt-ios/CMakeCache.txt` 的 `CMAKE_HOME_DIRECTORY` 和当前分支对不对。
  库结构升过级的版本装上去就回不去（旧版本打不开新结构的库），别随手装实验分支的包。

## 测试

规模（2026-10-14 实测，Qt 6.10.3）：**132 个 ctest 条目，`ctest -j8` 约 31 秒**。
包含 C++ 与桥接测试目标、`tests/qml/` 对应的 `QmlTest.*` 条目、`IPadSwiftTests`，以及 8 条自动化脚本门禁：`QmlLintGate`、`QmlTextFormatGate`、`QmlHoverTransitionGate`、`IPadThemeGate`、`McpHelperLinkGate`、`McpBundleSmoke`、`DeployLocalAppTests`，以及 057 架构门禁 `ArchitectureGate` 与 `ArchitectureGateR8`。

测试运行约束与事实记录：
- `QmlTest.contrast_audit` 在 `-j8` 全套并行时偶发报对比度不足，单独跑全过（取色前固定等待，高负载时颜色过渡未完成）。
- PTCore 以 PUBLIC 方式链接 `Qt6::Gui` 后，11 个原本只依赖 Core/Network/Sql 的测试若继续使用 `QTEST_MAIN` 会隐式创建 `QGuiApplication`，无离屏环境时加载 cocoa 平台插件并干扰时序测试。以下目标统一使用 `QTEST_GUILESS_MAIN`，恢复基线的 `QCoreApplication`：`CoreLogicTests`、`RobustnessTests`、`CountdownServiceTests`、`KnowledgeGapServiceTests`、`ScheduleServiceTests`、`PlatformControlTests`、`TimingRobustnessTests`、`PhaseAlarmCoordinatorTests`、`SyncTests`、`TrashServiceTests`、`PendingDeletionTests`。
- `PlatformControlTests::silentInstanceConnectionsAreBoundedAndExpire` 的失败由上述测试入口变化引入，修复后带或不带 `QT_QPA_PLATFORM=offscreen` 均应通过；不再按“既有时序失败”处理。

另有一条**运行时**门禁不单独占条目：它以 `FAIL_REGULAR_EXPRESSION` 挂在每个 QML 测试条目上，
把 `Unable to assign` / `TypeError` / `is not a function` / `ReferenceError` / `RangeError` / `Binding loop` 判为失败。之所以不新建一条门禁——
串行重跑全部 QML 测试实测 63 秒（2026-09-14，当时 64 个文件），会让全量时间翻几倍；挂在已有条目上是零额外开销。
某条测试确实需要故意触发告警时，单独覆盖它这一项属性。详见 [界面与验证约定](业务规则.md#界面与验证约定)。

每个 `tst_*.qml` 对应一个独立 CTest 条目，可以并行运行。新增文件由 `CONFIGURE_DEPENDS` 自动收集；如果未被执行，重新配置构建目录。

例外是 `QmlTest.memo_view`：它由 `MemoQuickTests` 运行，不用 `qmltestrunner`。这个入口往 QML 引擎里注入两样东西：正式页面用的纯文本排版对象 `memoTextLayout`，以及 `inputMethodProbe`——从 C++ 给焦点输入框发 `QInputMethodEvent`，模拟 iPad 软键盘和拼音选字上屏（QML 测试只能发按键）。单独跑：
`QT_QPA_PLATFORM=offscreen QT_QUICK_CONTROLS_STYLE=Basic ~/pt-audit/MemoQuickTests -input tests/qml/tst_memo_view.qml`。

使用原生偏好的 `PomodoroTodoTests`、`KnowledgeGapServiceTests`、`TrashServiceTests` 和
`MacPreferencesCleanupTests` 由 CTest 自动套用 `tests/run_native_preferences_test.py`。
脚本在子进程退出后清空专用偏好域，删除空 plist，并确认连续一秒没有重新出现；清理失败也会使测试失败。

> QML 测试红线：
> - **不要断言 `item.visible === true`**。离屏环境下 `visible` 的级联判定不可靠，
>   改为断言业务属性、`opacity` 或宽高。需要表达「没有可说的」时，让文案返回空串再断言文案，
>   比靠 `visible` 藏起来更稳。
> - **专注记账与任务归属日期走逻辑日**（`dayStartHour`，默认 4 点）。用 `new Date()` 的物理日期写用例，
>   白天可能通过、凌晨 4 点前失败。课表使用自然星期，应按课表规则构造日期。
> - **输入要走真实路径，不要在辅助函数里手动补发 `textEdited()` 这类信号。** Qt 6.10 的 TextArea 收到输入法上屏的文字时不发 `textEdited`，
>   补发信号会把「用了它就不保存」的缺陷完全遮住（052 阶段 3 全量测试照样全绿）。要模拟输入法，用 `MemoQuickTests` 的 `inputMethodProbe`。
> - **`Popup` 的 `onClosed` 在离屏环境不投递**。要验证「关闭后重置」这类行为，
>   直接断言重置函数本身，不要绕 `close()`。
> - **`tryCompare` / `tryVerify` 的超时要给宽（3000ms 起），不要写 120–220ms。**
>   它们一旦条件成立就立即返回，放宽上限在通过时不花任何时间，只在真失败时多等一会儿；
>   写紧没有任何收益，只会在机器被并行任务抢占时把「渲染慢了」误判成「行为错了」。
>   QML 测试现在是 77 条并行的 ctest 条目，这一条直接决定会不会偶发红。
> - **等状态到位用 `tryVerify`，不要用 `wait(N)` 睡一个「大概够了」的时长。**
>   固定睡眠既慢又不保证到位：`tst_ui_optimization` 曾经 28 个用例各睡 220ms，
>   光 `init()` 就 6.1 秒，并行时照样超时。只有「证明某件事没发生」才需要真正的固定等待。
> - **量颜色、切主题的测试先打开 `Theme.reduceMotion`，结束时还原。** `Theme.reduceMotion` 只有真实入口
>   `main.qml` 会绑定，直接实例化 `MainWindow` 的测试里它一直是关的。切主题时文字和底色会用 120–280 毫秒渐变过去，
>   并行时渲染跟不上，量到的是渐变到一半的颜色。`tst_contrast_audit` 就这样在并行时偶发失败：
>   2026-10-02 用 8 路并行复现，24 次全部失败；打开之后 24 次全部通过。
>   所有颜色动画的时长都写成「reduceMotion 时为 0」，所以打开后最终颜色不变，只是不再有中间帧。
> - **批量改超时值时注意 `tryCompare` 的三参形式**（`tryCompare(obj, "prop", 期望值)`）。
>   用「取末尾数字当超时」的正则去改，会把**期望值**改掉而不是超时——
>   这个坑真踩过，一次静默改写了 12 处断言。只处理确实有第 4 个参数的调用。
> - **`qmltestrunner` 按函数名字母序跑用例，不按书写顺序。** 弹窗、选择器这类展开态必须在 `init()` 里复位，
>   否则某条用例留下的焦点会让排在它后面的用例莫名变红。详见[界面与验证约定](业务规则.md#界面与验证约定)。
> - **要发真实鼠标 / 按键或 `grabImage` 截图，`TestCase` 必须 `visible: true`。** 默认不可见时截出空图、
>   悬停与按键都进不去；键盘入口类用例（如 `tst_week_keyboard_entry`）只直接调函数会漏掉「按键根本进不来」。

## 常见问题

- **改了 QML 但界面像旧版**：先清 qmlcache 再启动：
  `rm -rf ~/Library/Caches/PomodoroTodo/PomodoroTodo/qmlcache`
- **构建完了 `/Applications/番茄Todo.app` 没更新**：多半是这个构建目录里 cache 还留着
  `POMODORO_TODO_DEPLOY_LOCAL=OFF`。用 `rg DEPLOY_LOCAL ~/pt-build/CMakeCache.txt` 确认，
  重新配置时显式传 `-DPOMODORO_TODO_DEPLOY_LOCAL=ON`，继续使用约定的 `~/pt-build` 目录。
- **可选 QML 静态检查**（覆盖含 `components/settings/` 在内的全部 QML）：
  ```bash
  find qml -type f -name '*.qml' -print0 | sort -z | \
    xargs -0 <Qt SDK>/bin/qmllint \
      --ignore-settings -I qml \
      --missing-property warning --use-proper-function warning \
      --max-warnings 0
  ```
  **它现在是门禁**：`f8e3120` 修复前，官方 Qt 6.10.3 实测基线为
  `missing-property` 5 条、`use-proper-function` 7 条，旧文档的 4/6 已经失真。
  当前 CTest 显式启用两类检查，已知静态推导限制只在具体表达式旁局部压制，
  因而本机 `QmlLintGate` 输出必须为 0。后续新增告警必须修复，或在具体位置写明原因；
  禁止增加全局允许数量或关闭整个 warning 类别。
  不要用 `pyside6-qmllint`——本机未安装，且它来自本项目明确不用于部署的 PySide6 工具链。
