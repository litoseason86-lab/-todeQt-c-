# 运行命令（VSCode 终端）

在项目根目录 `/Users/zerionlito/code/番茄todo` 下执行。配置必须使用目标 Qt SDK 自带的 `qt-cmake`。

> `<qt-cmake>` 替换成目标 Qt SDK 的完整工具路径。本机已验证路径为
> `/Users/zerionlito/Qt/6.10.3/macos/bin/qt-cmake`。当前 Homebrew Qt Quick 框架最低要求
> macOS 26，不用于正式部署。配置阶段会打印 `使用的 Qt: <版本> @ <路径>`，照着确认一次再往下走。
>
> **只用两个构建目录**：`~/pt-build`（部署）与 `~/pt-audit`（验证）。
> 别按用途另建一次性目录——每个 300–450M，只增不减，此前在 `/tmp` 下攒到过 3.3G；
> 放在 `~` 之后更没有任何自动清理。需要隔离的场景用完当场删。
>
> **构建目录不要放在 `/tmp` 下。** macOS 的 `/tmp` 是指向 `/private/tmp` 的符号链接，
> moc 生成的相对包含（`../../../../Users/...`）按真实路径解析会落到 `/private/Users/...`，
> 找不到源码头文件。Qt 6.9 之前一直能编过，是因为它的 moc 调用里带 `-I/usr/local/include`，
> 那条搜索路径拼上同一串相对路径恰好回到 `/Users/...`——纯属偶然。
> Qt 6.10 换了 include 标志集（`-isystem`/`-iframework` 且带 `-isysroot`），
> 偶然性没了，整个构建直接失败。用 `~/pt-build` 这类没有符号链接的路径。

## Debug 构建（日常开发）

构建完成后会自动把最新应用包同步到固定启动入口 `/Applications/番茄Todo.app`。

```bash
<qt-cmake> -B ~/pt-build -S .
cmake --build ~/pt-build -j8
```

部署脚本 `cmake/DeployLocalApp.cmake` 的顺序是：复制到暂存目录 → 校验主二进制存在 →
旧包改名备份 → 原子 rename 换上新包 → 清理备份并刷新 `lsregister`。任一步失败都会把旧包放回原位，
不存在「先删旧包再复制」的空窗期。

可选开关：

```bash
# 跳过自动部署（审计/CI/临时目录构建用，避免覆盖固定入口）
<qt-cmake> -B ~/pt-audit -S . \
      -DPOMODORO_TODO_DEPLOY_LOCAL=OFF

# 打开 QML 调试钩子（默认 OFF；只有要跑 qmlprofiler / QML 调试器时才需要）
<qt-cmake> -B ~/pt-build -S . \
      -DPOMODORO_TODO_ENABLE_QML_DEBUG=ON
```

> **不要在同一个构建目录里混用这两种配置。** `POMODORO_TODO_DEPLOY_LOCAL` 是 CMake cache 变量，
> 值会持久化在构建目录里：在 `~/pt-build` 先跑过一次 `=OFF`，之后不带该参数重新配置也不会恢复成 `ON`，
> `deploy-local-app` 目标不会被创建，部署会**静默失效**。约定：部署用 `~/pt-build`，审计/测试用 `~/pt-audit`。

## Release 构建

```bash
<qt-cmake> -B ~/pt-release -S . \
      -DCMAKE_BUILD_TYPE=Release -DPOMODORO_TODO_DEPLOY_LOCAL=OFF
cmake --build ~/pt-release -j8
```

产物：`~/pt-release/PomodoroTodo.app`。

## 测试

规模（2026-08-15 实测，Qt 6.10.3）：**63 个 ctest 条目全绿，`ctest -j8` 约 16 秒**。
16 个 C++ 目标共 386 个测试函数；`tests/qml/` 的 45 个 `tst_*.qml` **每个文件一条 ctest 条目**
（共 565 条断言函数）；另有 `QmlLintGate` 与 `QmlTextFormatGate` 两条静态门禁。

QML 测试此前合成 `PomodoroTodoQmlTests` 一条，单进程串行跑完 56 秒，占全量的四分之三，
`ctest -j` 对它完全无效。拆成一条一个文件后全量降到 16 秒，瓶颈变成最慢的单个文件
（`tst_ui_optimization`，约 16 秒）。**新增 `tst_*.qml` 会被 `CONFIGURE_DEPENDS` 自动收进来**，
不需要改 CMake；但如果发现新文件没被执行，重新 configure 一次。

```bash
# 全套
# 每个测试目标在 CMake 中另有 30/90/180 秒 watchdog；这里的 240 秒是旧构建缓存的最后护栏。
QT_QPA_PLATFORM=offscreen QT_QUICK_CONTROLS_STYLE=Basic \
  ctest --test-dir ~/pt-audit --output-on-failure --timeout 240

# 只跑单个测试目标（直接跑二进制时同样要带 offscreen，否则会拉起 cocoa 平台插件弹窗）
export QT_QPA_PLATFORM=offscreen QT_QUICK_CONTROLS_STYLE=Basic
~/pt-audit/PomodoroTodoTests        # 服务层主套件（177）
~/pt-audit/CoreLogicTests           # 核心逻辑边界补充（17）
~/pt-audit/RobustnessTests          # 健壮性与性能（11，含并发撞锁）
~/pt-audit/CountdownServiceTests    # 倒计时服务（16）
~/pt-audit/GoalServiceTests         # 长期目标服务（35）
~/pt-audit/BackupServiceTests       # 备份与恢复（24，约 8 秒，真实文件 I/O）
~/pt-audit/TimingRobustnessTests    # 计时健壮性（休眠/改钟）（10）
~/pt-audit/PlatformControlTests     # 菜单栏与通知（平台无关层）（17）
~/pt-audit/MacNotificationBackendTests  # 通知后端（macOS 原生层）（3）
~/pt-audit/ShortcutRegistryTests    # 快捷键注册表（默认/覆盖/冲突/单键/全局注册，用假后端）（18）
~/pt-audit/MacGlobalHotkeyTests     # 全局热键键码翻译（Carbon，不注册真实热键）（6）
~/pt-audit/FontAssetsTests          # 字体资源（4）
~/pt-audit/WallpaperAssetsTests     # 壁纸资源（1）
~/pt-audit/ShaderAssetsTests        # Shader 资源（1）
~/pt-audit/SoundAssetsTests         # 音效资源（4）
~/pt-audit/QmlResourceManifestTests # QML 资源清单守门（源文件与 qrc 一致性）（2）

# 只跑 QML 静态检查门禁（unqualified 与 layout-positioning 零容忍）
ctest --test-dir ~/pt-audit -R QmlLintGate --output-on-failure

# 文本格式门禁：非字面量的 text 绑定必须显式声明 textFormat（防 AutoText 富文本解析）
ctest --test-dir ~/pt-audit -R QmlTextFormatGate --output-on-failure
python3 tests/qml_text_format_gate.py qml   # 也可直接跑，会列出所有违规位置

# 只跑全部 QML 测试（45 条条目，可并行）
ctest --test-dir ~/pt-audit -R '^QmlTest\.' --output-on-failure -j8

# 只跑单个 QML 测试文件
ctest --test-dir ~/pt-audit -R '^QmlTest\.focus_view$' --output-on-failure

# 按名字过滤 C++ 用例（Qt Test 原生参数）
~/pt-audit/PomodoroTodoTests interruptedFocusRestoresPausedAndKeepsProgress
```

> QML 测试红线：
> - **不要断言 `item.visible === true`**。离屏环境下 `visible` 的级联判定不可靠，
>   改为断言业务属性、`opacity` 或宽高。需要表达「没有可说的」时，让文案返回空串再断言文案，
>   比靠 `visible` 藏起来更稳。
> - **日期一律走逻辑日**（`dayStartHour`，默认 4 点）。用 `new Date()` 的物理日期写用例，
>   白天跑碰巧过、凌晨 4 点前必红——已经有一条用例这样漏网过。
> - **`Popup` 的 `onClosed` 在离屏环境不投递**。要验证「关闭后重置」这类行为，
>   直接断言重置函数本身，不要绕 `close()`。
> - **`tryCompare` / `tryVerify` 的超时要给宽（3000ms 起），不要写 120–220ms。**
>   它们一旦条件成立就立即返回，放宽上限在通过时不花任何时间，只在真失败时多等一会儿；
>   写紧没有任何收益，只会在机器被并行任务抢占时把「渲染慢了」误判成「行为错了」。
>   QML 测试现在是 45 条并行的 ctest 条目，这一条直接决定会不会偶发红。
> - **等状态到位用 `tryVerify`，不要用 `wait(N)` 睡一个「大概够了」的时长。**
>   固定睡眠既慢又不保证到位：`tst_ui_optimization` 曾经 28 个用例各睡 220ms，
>   光 `init()` 就 6.1 秒，并行时照样超时。只有「证明某件事没发生」才需要真正的固定等待。
> - **批量改超时值时注意 `tryCompare` 的三参形式**（`tryCompare(obj, "prop", 期望值)`）。
>   用「取末尾数字当超时」的正则去改，会把**期望值**改掉而不是超时——
>   这个坑真踩过，一次静默改写了 12 处断言。只处理确实有第 4 个参数的调用。

## 常见问题

- **改了 QML 但界面像旧版**：先清 qmlcache 再启动：
  `rm -rf ~/Library/Caches/PomodoroTodo/PomodoroTodo/qmlcache`
- **构建完了 `/Applications/番茄Todo.app` 没更新**：多半是这个构建目录里 cache 还留着
  `POMODORO_TODO_DEPLOY_LOCAL=OFF`。用 `grep DEPLOY_LOCAL <builddir>/CMakeCache.txt` 确认，
  重新配置时显式传 `-DPOMODORO_TODO_DEPLOY_LOCAL=ON`，或换一个干净的构建目录。
- **可选 QML 静态检查**（覆盖含 `components/settings/` 在内的全部 QML）：
  ```bash
  <Qt SDK>/bin/qmllint -I qml \
    qml/*.qml qml/views/*.qml qml/components/*.qml qml/components/settings/*.qml
  ```
  **它现在是门禁**：ctest 条目 `QmlLintGate` 对 `unqualified` 与 `Quick.layout-positioning`
  零容忍（两者均已清零，2026-08-08 实测），只豁免 `missing-property`（4 条，工具推导限制）
  与 `use-proper-function`（6 条，项目既定的回调注入模式）。上面那条手工命令用于查看
  全部告警；判据以 `QmlLintGate` 为准。
  不要用 `pyside6-qmllint`——本机未安装，且它来自本项目明确不用于部署的 PySide6 工具链。
