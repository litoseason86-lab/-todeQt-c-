# 奖励机制实施方案（TRACK 100 重拆 × 当前代码现状）

2026-07-26。前一份《长期目标与奖励机制落地方案》交付了数据底座（阶段 1-2），
但**用户可感知的奖励为 0%**：`goalService` 在 QML 零引用、`milestoneReached` 零监听、
没有目标页、没有 100 格、没有弹窗。本方案只回答一个问题：**怎么把奖励做到用户脸上**。

---

## 一、重新理解：TRACK 100 的奖励为什么有效

不是罗列它有什么，而是它靠什么起作用。五条机制原理：

### 1. 奖励与动作零距离

打卡按钮就在进度画面旁边。手指按下 → 格子弹跳 → 音效 → 进度条回弹，
全部发生在**同一屏、同一秒**。行为心理学上即时性是强化的第一要素——延迟一秒都在打折。

**⚠ 这是我们与它最大的结构差异**：我们的「+1」发生在专注结束，用户此刻在专注页
（甚至沉浸全屏），目标页大概率没开。**照抄「把反馈画在目标页上」等于把奖励藏起来。**
所以我们的奖励回路必须是**事件驱动、全局送达**的：C++ 信号 → 全局层（toast / 弹窗），
目标页只是回味的地方，不是反馈的唯一现场。

### 2. 前瞻性诱因：奖励在到达之前就可见

- 第 25/50/75/100 格未点亮时就带金框 + ★ —— 用户随时看得见「下一个庆祝还差几格」。
- 「照此速度预计 N 天完成」—— goal-gradient 效应：离目标越近，投入越猛。
  这句话放在列表每一行，是全站最有说服力的一句文案。

### 3. 任意目标归一化成 100 格

`min(100, done/target*100)`，边界格按比例部分填充。作用有两个：
**每次推进必有可见增量**（目标 300 时一次推 1/3 格也看得见），
以及**沉没成本可视化**——62 个实心格子是「我已经投入这么多」的实体证据，放弃成本被画了出来。

### 4. 分层反馈，强度递进

| 层 | 触发 | 强度 |
|---|---|---|
| 即时 | 每次 +1 | 100ms 单音 + 格子 pop，轻到不打断 |
| 里程碑 | 跨 25/50/75% | 三音上行 + 撒花 + 弹窗，强制注意一次 |
| 达成 | 100% | 四音 + 弹窗 + 卡片永久转完成态 |
| 长期 | 完成目标数累积 | 等级 LV1-5（阈值 0/3/8/20/40，前密后疏） |

强度和稀有度成正比。每次都撒花等于从不撒花。

### 5. 全部是表征型奖励，零货币

没有积分、商店、兑换。声音、动画、印章、等级名——不可交易，所以没有通胀、
没有刷分动机、不需要经济平衡。且奖励状态几乎全派生（我们已抄对这条并修掉了它
undo 可刷撒花的 bug——位掩码只增不减）。

## 三、实施分期（按可感知程度排序，每期结束都能真机看见）

### 阶段 A：让功能存在 —— 目标列表页 + 侧栏入口

- `GoalsView.qml` + 侧栏「目标」项（置于「倒数」后）。
- 头部：筛选胶囊（进行中/已达成/全部）左，视图切换图标分段右。
- 列表版式（默认）：小圆环 + 标题 + 「62 / 100 番茄 · 照此速度还需 21 天」；
  网格版式：大圆环瓦片。`AppSettings.goalViewMode` 持久化。
- 新建/编辑表单：标题、科目（必选，服务端已强校验）、目标番茄数、起始日（默认今天，
  可填过去回填历史）、截止日（可选=长期）。
- 空态文案 + 新建入口。
- 验收：真机可增删改查、切换版式、重排；QML 测试断言业务属性（不断言 visible）。

### 阶段 B：奖励的载体 —— 详情页 100 格

- 进度条卡片 + 100 格网格（10×10、限宽 360、里程碑格 `Theme.accent` 描边、
  边界格宽度部分填充）+ 「照此速度还需 N 天」+ 月历热力（复用 MonthGoalView 数据渲染，
  数据源换成该目标所绑科目的专注记录）。
- 验收：目标 300 番茄时完成 1 个番茄可见 1/3 格增量；四个里程碑格在未达时可见描边。

### 阶段 C：奖励的送达 —— 全局反馈回路（本方案的核心）

1. **即时层**：`focusCompleted` 推进了某目标时，全局 Toast 显示
   「英语精读 +1 · 63/100」。轻、3 秒自散、不打断。沉浸模式下同样显示（toast 不算打断）。
   需要 `GoalService` 新增信号 `goalProgressed(goalId, title, done, target)`
   （在 `refreshMilestones` 里顺带发，零额外查询）。
2. **里程碑/达成层**：`milestoneReached` → MainWindow 全局弹窗（素版，25/50/75 与 100 两种文案）
   + `CompletionParticles` 定向迸发。沉浸模式：压弹窗，只留音效，退出沉浸后补一条 toast。
3. **动效**：`reduceMotion` 时无粒子、弹窗直显。
- 验收：目标页**关闭**的状态下完成一个跨里程碑的番茄，弹窗照常出现（这正是与
  TRACK 100 的结构差异被正确处理的证据）。

### 阶段 D：长期层 —— 统计页等级与已达成

- 统计页底部：「已达成 N 项」折叠列表（色点+标题+日期）+ 等级徽标
  （阈值抄 0/3/8/20/40，名称按暖色语汇重写）。
- 验收：完成第 1/3/8 个目标各触发一次等级变化显示。

各期独立可交付；A→B→C 顺序固定（C 的弹窗按钮「查看目标」要跳详情页），D 可并行。

## 四、开放决策（待审核）

1. **即时层的载体**：全局 toast（推荐，理由见 §一.1）/ 只在详情页在场时做格子动效 /
   两者都做（toast 全局 + 在场时格子 pop）。
2. **里程碑音效来源**：(a) 新增两个短音频资源（三音/四音上行，需制作）；
   (b) 复用现有 `phase-complete.wav`（零成本，但庆祝感与普通阶段完成无区分）；
   (c) 第一版无音效，只有视觉。
3. **阶段 D 是否纳入本轮**：纳入（四期一起排）/ 推迟（先交付 A-C 验证留存效果）。

## 五、风险与红线

- 弹窗时机：`refreshMilestones` 由 `focusCompleted` 同步驱动，弹窗必须 `Qt.callLater`
  级别解耦，不能阻塞 FocusTimer 的收尾链路。
- QML 测试沙盒红线：不断言 `visible === true`；动效断言走属性/`opacity`。
- 里程碑格描边只用描边，不加 ★（审美红线：先做最素版）。
- 所有新增查询走既有 `getGoals()/getGoal()`，不引第二套聚合口径。
