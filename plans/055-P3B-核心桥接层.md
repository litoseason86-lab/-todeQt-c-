## 背景

- P3A 搭好了外壳和一条外壳桥接 `PTShellBridge`，定下了这些写法：
  - 桥接对象只能在主线程创建；
  - 用自己持有的 `QObject` 作信号接收上下文，释放时自动断连；
  - 回调块里弱引用自身；
  - 读取结果带 `valid` 和 `error`，把读取失败和空数据分开；
  - Swift 侧协议放在 IPadCore，适配器放在 IPadUI，适配器把 Objective-C 值对象逐字段拷进 Swift 结构体。
- 总计划「桥接层」要求一个领域一个桥接类，返回带类型的值对象，不在 Swift 里拆字典。另外：
  - 编辑只交改过的字段；
  - 交互期间冻结刷新（`TaskInteractionCoordinator`）；
  - 失败照服务原样上报。
- 阶段 2 第 1 条已合入：`PendingDeletion`（`src/services/PendingDeletion.h`）负责单槽撤销删除的计时、提交、撤销，以及「被别处删掉就退场」，在 `main.cpp` 里创建。
- 页面分工：
  - 任务、科目、统计、专注历史、逻辑日、设置在 P4 的多份计划里都要用，放在本计划；
  - 专注控制器（P4-1）、课表（P4-2）、知识缺口 / 备忘录 / 倒计时（P4-3）、废纸篓 / 同步 / 备份 / 导出 / 例行（P4-4）各自在 P4 里做。

## 设计

### 头文件与模块

- `module.modulemap` 用 `umbrella "."`，bridge 目录下所有 `.h` 都会进 Swift 模块 `PTBridge`，子目录也包括在内。
  - 进模块的头文件只能写 Foundation 的 Objective-C，不能出现 C++ 和 Qt。
  - `PTBridgeSupport.h` 是给 `.mm` 用的 C++ 头文件，在 modulemap 里用 `exclude header "PTBridgeSupport.h"` 排除，旁边写注释说明原因。
  - 漏了这一步，iOS 编译时 Swift 导入模块会失败。所以每步都要做 iOS 不签名编译。
- 值对象：
  - 只读属性，初始化方法放在 `.mm` 的类扩展里，Swift 看不到；
  - 编号用 `NSInteger`，「没有」统一用 -1，不用 `NSNumber` 可空；
  - 日期用 ISO 日期串 `yyyy-MM-dd`，时刻按 `PTBridgeSupport` 定下的那一种。
- 读取结果：列表与报告型读取都带 `valid` 和 `error`。实现上可以用泛型结果类，也可以每个领域一个结果类，全桥统一一种。
- 写入：
  - Objective-C 签名用 `error:(NSError **)error`，Swift 侧是 `throws`；
  - 错误信息优先取调用期间服务发出的 `operationFailed` 或 `lastError()`，没有时用一句通用文案；
  - 返回编号的写入（新建、补录）失败时抛错，不返回 -1 让 Swift 自己判断。
- 背景失败：不是由某次调用引起的 `operationFailed`，比如同步线程排队回来的那种，走 `onFailure`。

### 改动表（只交改过的字段）

- 任务：`PTTaskChanges` 用「设了才有」的写法。例如 `setTitle:` 之后 `hasTitle` 为真；可改字段以 `updateTaskChanges` 认的键为准，执行时去 `TaskManager.cpp` 查。
  - 桥接只把设过的键放进 `QVariantMap`。
  - 「清空科目」「清空备注」要能和「没改」区分开。
- 专注历史：同理，有 `PTSessionChanges`，对应 `updateSessionFields` 和 `updateRestSessionFields`。
- Swift 侧对应的值类型用可选字段。适配器只转发非 nil 的字段；「清空」用显式的枚举或哨兵值表达，不用 nil 混用。

### 交互登记

- `beginEdit` 和 `beginDrag` 返回一个令牌对象 `PTInteractionToken`，令牌内部持有一个 `QObject` 作为登记的 owner。
  - 令牌 `end` 或被释放时，owner 跟着销毁，协调者靠 `destroyed` 自动结束登记。这和 QML 页面销毁时自动结束是同一个语义。
  - `beginEdit` 成功时带回服务读到的最新任务值对象；失败时抛错，错误文案取协调者的 `lastError`。
- Swift 侧：令牌包成一个 `final class`，Store 持有它就表示交互还在进行，置空就是结束。

### 撤销删除 Store（`PendingDeletionStore`）

照 Mac `MainWindow.qml` 的接线写。阶段 2 第 1 条已把业务部分移进 C++，这里只管提示条：

1. **请求删除任务**：
   - 先交给桥接 `requestTask`，失败直接返回 false；
   - 成功后显示提示「已删除「标题」」加「撤销」按钮。例行生成的任务文案不同，照 `MainWindow.qml` 的 `requestDeleteTask`，用 `isRoutineGeneratedTask` 判断。
   - 「撤销」调 `cancel`。
2. **请求删除专注 / 休息记录**：同理，缺省标题用「专注记录」。
3. **C++ 发 `retired`**：只收起属于这次删除的那条提示，别的提示不动。
4. **C++ 发 `commitFailed(title)`**：显示「删除「标题」失败，请重试」。
5. **外壳要显示别的提示、把撤销条顶掉时**：先 `commit`。用 `ShellStore.showToast` 的 `onRetired` 回调实现。点击「撤销」时不再提交，`ShellStore` 已保证点击动作不触发退场回调。
6. **页面要进入「先提交」的流程时**：补录、改记录、备份、恢复都属于这类，调 `commitIfNeeded() -> Bool`，失败就不继续。
7. **哪一行处于待删状态**：Store 暴露 `pendingTaskId` / `pendingSessionId`，各页据此隐藏那一行。

`swift test` 用例照 `tests/qml/tst_focus_start_flow.qml` 里改写后的删除接线用例，一一对应，在报告里列对照：

- 请求后出现撤销条；
- 撤销会调 `cancel`；
- `retired` 只收起自己那条；
- 新提示顶掉撤销条时先提交；
- 提交失败时提示文案带标题；
- 例行任务的文案；
- 请求失败时不出提示。

### 任务动作（`TaskActions`）与专注钩子（`FocusFlowHook`）

Mac 上，今日任务、本周计划、仪表盘三页的「开始专注」「完成」「删除」都交给 `MainWindow` 的同一组函数：`startFocusForTask`、`handleTaskCompletedByUser`、`requestDeleteTask`。iPad 上由 `TaskActions` 承担这个角色，三页都只调用它。

- `FocusFlowHook`（IPadCore 协议，`@MainActor`）只有两个方法：
  - `taskCompleted(taskId:) -> TaskCompletionFocusOutcome`：返回 `none`、`ended(discarded: Bool)`、`failed`、`needsConfirmation` 之一，语义对应 P2A 的 `FocusSessionController::handleTaskCompleted` / `endCurrent` 的结果；
  - `openTask(taskId:title:)`：按 P2A 的 `planTaskEntry` 分流。
  
  P4-1 的专注 Store 实现它。P4-1 合入前钩子为 nil：完成时不结束专注，「去专注页」只切页。这个状态只出现在默认关闭的原生界面里。
- 完成：
  1. 调任务桥接完成；失败显示服务的错误，后面不做。
  2. 完成成功后问钩子。提示文案照 `MainWindow.qml` 的 `handleTaskCompletedByUser`，一字不改：
     - 「已完成「标题」」；
     - 结尾加「，专注已结束」「，专注不足 3 分钟，未计入记录」「，但结束专注失败，计时仍在继续」之一；
     - `needsConfirmation` 不加结尾，并切到专注页。
  3. 提示带「撤销」，点了就取消完成。行为照 `showCompletionUndoToast`。
- 去专注页打开某任务：`ShellStore` 切到专注页，再调钩子的 `openTask`。`ShellStore` 现在没有切页以外的入口；需要的话加一个只读的 `focusHook` 持有点，只加不改。
- 删除：转给 `PendingDeletionStore`。
- `swift test`：
  - 用替身钩子覆盖四种结果的文案与切页；
  - 撤销完成；
  - 完成失败时不问钩子；
  - 钩子为 nil 时的退化行为。

### 信号与线程

- 桥接一律照 `PTShellBridge` 的写法：主线程创建，自有 `QObject` 作接收上下文，用 `AutoConnection`。
- 跨线程发出的信号排队回到主线程，适配器里用 `MainActor.assumeIsolated` 进入主 actor。
- 每个桥接都要测三件事：转发、工作线程发的信号回到主线程、释放后不再回调。工作线程和释放这两条可以只挑代表性信号。
