## 问题与诊断

用户反馈：Mac 与 iPad 数据不一致，点「立即同步」后大约 5 分钟另一台才看到。

2026-11-07 15:33 只读核对 Mac 一侧：

- Mac 库 `sync_outbox` 0 条、`sync_conflict_log` 0 条；`cursor/<iPad>` = `0:248`，与 iCloud 文件夹里 iPad 最新一批（`0000-00000248`）一致；iPad 的游标文件记着已读到 Mac 第 93 批，也是 Mac 的最新一批。
- 结论：从 Mac 能看到的范围内，两台最终是追平的，没有丢改动，也没有合并错误。问题在**到达慢**。iPad 上若有还没传到 Mac 的改动，Mac 这一侧看不到，不能据此断言。

慢在 iCloud 云盘这一段，应用控制不了：

1. 点「立即同步」时，`SyncEngine::syncNow` 当场就写出、读取（攒批与扫描的间隔都会跳过）。
2. 写出的文件要等 Mac 的 iCloud 后台进程上传；iPad 要等系统刷新这个文件夹的目录才看得见。`IosSyncFolder::list` 用的是普通目录枚举（`src/platform/ios/IosSyncFolder.mm:191`），系统刷新之前列出来的一直是旧目录。
3. 读到还没下载的文件时，协调读取要等下载；超过 90 秒（`stallTimeoutMs`）算这一轮出错，重试间隔从 30 秒翻倍到最长 5 分钟（`retryMaxMs`）。
4. 049 实测的 2–3 秒是理想情况，不是上限。

## 目标与验收

- 一台设备改动后，另一台（前台或 Mac 常驻）**10 秒内**看到；正常网络下预期 2–5 秒。
- 同步核心（合并、删除优先、游标、快照、清理、恢复纪元）**一行不改**；批次格式不升（仍是 4），数据库 schema 不升。
- 服务器只存密文：服务器磁盘、日志、内存里都没有任务、备忘录等明文，也拿不到解密密钥。
- 服务器上的东西都能从 Mac 重建：服务器丢失或损坏，不丢任何数据。
- 能切回 iCloud 云盘；iCloud 那套代码保留。

## 由主会话按惯例定下的细节

| 事项 | 做法与理由 |
| --- | --- |
| 接入方式 | 新增 `SyncFolder` 的一种实现 `RemoteSyncFolder`：文件布局与 iCloud 文件夹完全相同，只是存到服务器上。同步核心只通过 `SyncFolder` 的列、读、写、删访问文件夹，所以不用改。 |
| 变化通知 | 长轮询：设备挂一个最长 25 秒的等待请求，另一台一写入，服务器立即返回，本机马上同步一轮。比 WebSocket 更适合 Python 标准库实现，经代理和 Nginx 也稳。 |
| HTTP 实现 | 在 `src/platform/apple` 用 NSURLSession 实现（Mac 与 iPad 共用），经 `src/services` 里的接口调用。NSURLSession 自动跟随系统代理（Clash），iOS 上不用另外装 Qt 的 TLS 插件，取消也是线程安全的。 |
| 加密实现 | 接口在 `src/services`，实现在 `src/platform/apple`，用 CommonCrypto：AES-256-CBC 加密，再用 HMAC-SHA256 校验（先加密后校验）。Apple 的 C 接口里没有公开的 AES-GCM（CryptoKit 只有 Swift 版，Mac 目标没有 Swift）。 |
| 密钥保存 | 存在 QSettings 的 `sync/` 组，不进钥匙串。理由：端到端加密防的是服务器，本机的库本身就是明文；而 Mac 版本地部署的签名每次构建都会变，用钥匙串的话每次部署都会弹授权框。`sync/` 组本来就不进备份，恢复备份也不会改它。 |
| 配对 | Mac 建好同步空间后显示配对码，点「复制」后在 iPad 上粘贴（同一 Apple ID 下有通用剪贴板）。配对码含服务器地址、空间编号和 32 字节密钥。 |
| 建空间的权限 | 建空间要带「注册口令」：部署时在服务器上生成，存在 litozerion 的 `.private/accounts.md`，Mac 建空间时输一次。防止别人找到地址后建空间把磁盘写满。 |
| 公开仓库 | 仓库里不出现域名、IP 和任何口令；服务器地址只在配对码和本机设置里。部署配置的模板用占位符，实际配置放 litozerion（不在公开仓库）。 |

## 设计

### 服务器（`server/pt_sync_server.py`，只用 Python 标准库）

- 一个「同步空间」对应 iCloud 方案里的一个同步文件夹。磁盘布局：`<StateDirectory>/spaces/<空间编号>/` 下原样存放文件。另有 `meta.json`，记令牌的 SHA-256 和版本号 `rev`。
- 接口（除建空间外都用 `Authorization: Bearer <访问令牌>`）：
  - `POST /v1/spaces`：带 `X-PT-Enroll: <注册口令>`，请求体为 `{space, tokenSha256}`。已存在返回 409。
  - `GET /v1/spaces/<id>/tree`：一次返回全部文件路径与大小，再加 `rev`。客户端每轮开始时调用这一个请求，列目录都从这里取，不再一层层发请求。
  - `GET|PUT|DELETE /v1/spaces/<id>/files/<相对路径>`：PUT 先写临时文件、`fsync`、再改名，最后 `fsync` 目录，对方永远读不到写了一半的文件；PUT 和 DELETE 都让 `rev` 加一。DELETE 删不存在的文件也返回成功。
  - `GET /v1/spaces/<id>/watch?rev=N`：`rev` 已大于 N 时立即返回，否则最多等 25 秒。
- 路径校验：每一段只允许 `[A-Za-z0-9._-]`，不得出现 `..`，不得以 `/` 开头，最多 4 层。单个文件上限 70 MiB（快照 64 MiB 加上加密开销），整个空间上限 512 MiB，超了返回 507。
- 令牌比较用 `hmac.compare_digest`；日志不记请求体、不记令牌，查询串只留 `rev`。
- Nginx：`client_max_body_size 72m`；watch 路由 `proxy_read_timeout 40s`、`proxy_buffering off`；建空间路由单独限速。

### 客户端

- `src/services/SyncHttpClient.h`：同步的阻塞请求接口（方法、地址、请求头、请求体、超时），可从另一个线程 `cancelAll()`。
- `src/platform/apple/AppleSyncHttpClient.mm`：用 NSURLSession 实现，每个请求用信号量等完成。
- `src/services/SyncCipher.h` + `src/platform/apple/AppleSyncCipher.mm`：
  - 密钥：配对密钥经 HKDF-SHA256（salt 为空间编号，info 分别取 `auth`、`enc`、`mac`）派生出三把互相独立的密钥：访问令牌、加密密钥、校验密钥。服务器只拿到访问令牌的哈希，推不出另外两把。
  - 文件格式：`"PTE1"` + 16 字节随机 IV + 密文 + 32 字节校验值。
  - 校验值 = HMAC(校验密钥, `"PTE1"` ‖ 路径长度 ‖ 相对路径 ‖ IV ‖ 密文)。把路径算进去，是为了防止服务器把一个文件挪到别的路径冒充别的批次。
  - 校验失败报 `Io` 并写明「同步文件校验不通过」，不按坏数据跳过。
- `src/services/RemoteSyncFolder.{h,cpp}`：实现 `SyncFolder`。
  - `open()` 拉取 `tree` 并缓存；`list()` 从缓存里取；`write`、`remove` 成功后同步更新缓存。
  - `uploadProblem()` 返回空：写成功就是已经在服务器上了。
  - 错误归类：401/403 → `Unavailable`（「配对已失效」）；文件 404 → `NotFound`；空间 404 → `open()` 里按「空间里没有标记文件」处理，交给引擎走现有的 `FolderMissing` 逻辑；413/507 → `NoSpace`；网络错误、超时、5xx → `Io`。
- `src/services/SyncServerWatcher.{h,cpp}`：
  - 在自己的线程里循环发 watch 请求；`rev` 变了就用跨线程排队信号通知主线程，由 `SyncController` 调 `syncNow()`。
  - 出错时退避重试，5 秒翻倍到 60 秒，不改引擎状态。
  - iPad 只在前台挂着（跟 `setForeground` 走），Mac 一直挂着。
- 服务器方式的引擎节拍（`SyncEngine::Options`，按方式选择）：

  | 选项 | 取值 |
  | --- | --- |
  | `publishIntervalMs` | 2000 |
  | `scanIntervalMs` | 60000（只作通知丢失时的兜底） |
  | `retryMinMs` / `retryMaxMs` | 5000 / 60000 |
  | `stallTimeoutMs` | 30000 |

  iCloud 方式的取值不变。

### 控制器与切换（`SyncController`）

- `sync/` 组新增四个键：`transport`（`icloud` 或 `server`）、`server/url`、`server/space`、`server/secret`。`Platform` 新增 HTTP 客户端与加密实现的工厂。
- Mac 切到服务器：
  1. 先检查本机状态是「已同步」、待发送为 0。
  2. 输入注册口令，生成空间编号与密钥，在服务器上建空间。
  3. 忘掉原文件夹，走现有的 `createFolder`：新的文件夹身份，`requestFullSnapshot`。
  4. 把 iCloud 里的「番茄Todo同步」改名为「番茄Todo同步-旧-<UTC 时刻>」，并删掉里面的标记文件。这样 iPad 那边马上显示「同步文件夹不见了」，不会继续往没人读的地方写；即使误选了旧文件夹，也只会被认成「不是同步文件夹」。
  5. 显示配对码。
- iPad 输入配对码：
  1. 解析并校验，能访问空间之后换成 `RemoteSyncFolder`。
  2. 标记文件里的文件夹身份不同，引擎进入现有的 `NeedsConfirmation`；确认后先自动备份，再用 Mac 的快照替换本机数据。
  3. 本机若还有没发出的改动，确认框里写明条数，并说明这些改动只留在自动备份里。只提示，不拦：那时旧文件夹已经被 Mac 改名，拦住就永远加入不了。
- 切回 iCloud：
  - Mac 在 iCloud 云盘新建「番茄Todo同步」（新身份，走 `createFolder`）。
  - iPad 清掉书签，重新选文件夹并确认加入。
  - 服务器上的旧空间留着不动，日后用服务器上的管理命令删除。
- 要先核实的风险：Mac 换文件夹后，旧文件夹留下的 `cursor/<iPad>`、`peer_seen/*`、`outbound` 在新文件夹里继续用，iPad 加入后批次序号必须能接上。阶段 4 先写用例证明「两台都带着旧进度换到新空间后，后续改动双向互通」，再接界面。

## 阶段与验收

每个阶段结束：在 `~/pt-audit` 构建并跑全量 `ctest`；涉及 Swift 或桥接层的，加跑 `~/pt-ios` 不签名编译和 `swift test`。主会话读 `git diff` 和原始日志，亲自验收。

### 阶段 1：服务器（本地）

- `server/pt_sync_server.py`、`server/tests/test_pt_sync_server.py`（unittest）。
- `server/deploy/` 放三个占位符模板：systemd 单元（照 `daily-todo.service` 的加固项）、Nginx server 块与片段、注册口令生成命令。
- 用例覆盖：
  - 建空间：口令不对返回 403，重复建返回 409。
  - 令牌错误返回 401。
  - 路径穿越（`..`、绝对路径、空段、非法字符）一律拒绝。
  - 写入是原子的：写到一半让进程中断，旧文件仍完整。
  - 超过单文件、整个空间的上限时拒绝，且已有文件不受影响。
  - watch：已过期的 `rev` 立即返回；另一个线程写入后，等待中的请求在 1 秒内返回；超时返回原 `rev`。
- 在 `cmake/PomodoroTodoTests.cmake` 登记 `SyncServerUnitTests`，用 `python3 -I -m unittest` 运行。

### 阶段 2：加密与远端文件夹

- 新增 `SyncHttpClient`、`SyncCipher`、`RemoteSyncFolder`，以及两个 Apple 实现。按 AGENTS.md 登记源文件、测试目标，更新架构门禁的包含白名单。
- `RemoteSyncFolderTests`：测试里在 `127.0.0.1` 的随机端口启动本地服务器（HTTP，测试专用开关），覆盖：
  - `SyncFolder` 的语义与 `LocalSyncFolder` 一致：列目录、读不存在的文件、覆盖写、删除不存在的文件。
  - 换一把密钥读同一个文件，校验失败。
  - 改动密文中的一个字节，校验失败。
  - 服务器把 A 路径的文件复制到 B 路径，读 B 时校验失败。
  - 服务器关掉 → `Io`；令牌错误 → `Unavailable`；空间写满 → `NoSpace`。
  - 读取卡在服务器端时 `cancelPendingIo()` 能让读取立即返回。

## 不做

- 不做多台服务器互备：服务器只是中转，可以从 Mac 重建。
