## 背景

强化阶段需要一个长期存在、每天都会改的地方，记各科"现在学到哪了"。现有功能都不合适：
任务是当天要做的事，做完就勾掉；知识缺口是要补的问题，解决了就关掉；它们都不是一直在变的进度。

进度只用文字记（比如"36 讲第 8 讲做完，1000 题做到第 3 章"），App 不把它算成百分比或进度条。
这和「不记题量 / 正确率，全应用只用分钟这一把尺子」的决定一致。

## 范围

**做：**

- 侧栏新增「备忘录」页。Mac 和 iPad 是同一套界面（iPad 本来就用完整界面，只有手机用伴侣页）。
- 每条备忘有标题、正文、科目（可以不选）、同一科目内的顺序和更新时间。
- 分类：「全部」加上写过备忘的科目；「未分类」只在有未分类的备忘时出现。
- Mac 和 iPad 之间同步，冲突规则和现有同步一样：不同字段都保留，同一字段以后改的为准，删除优先，输掉的值记进同步日志。
- 备份和恢复带上备忘录。

**第一版不做：** 历史版本、搜索、导出、给外部 AI 读写、切页快捷键（沿用"切页快捷键只给 8 个页面"的决定）、
进度百分比或进度条、iPad 竖屏单栏模式、分类过多时折叠成「更多」、富文本（只做纯文本）。

## 界面（定稿）

- 页头只有标题「备忘录」和「新建」。下面一个玻璃框（`GlassPanel`）装下两栏，中间一条 `borderSubtle` 细线。
- **左栏**宽 256：顶部是分类胶囊，下面是列表。
  - 胶囊样式与仪表盘的筛选胶囊一致：选中的是 `accentFill` 底、`accentFillInk` 字，没选中的只有描边。
  - 胶囊只给「全部」和写过备忘的科目，按科目管理里的顺序排；放不下就换行，不做横向滑动。
  - 每个胶囊最宽约 7 个字（`Theme.fontSm * 7 + space16`），超出部分省略；Mac 上鼠标停留时显示全名，无障碍名称也用全名。
  - 「全部」按科目分组，组头写「科目 · 条数」。名字太长时只省略名字，条数一直保留。选了某一科就不再显示组头。
  - 每行显示：科目色点、标题、更新时间，下面一行是正文的第一行。选中行的样式和设置页左侧导航一样。
  - 列表用可滚动的 `ListView`。不要把 `ColumnLayout` 直接放进 `RowLayout`：内容一多，它报上去的最小高度会把整行撑出框，设计稿里踩过这个坑。
- **右栏**是纸面编辑卡（`surfaceRaised` 底，不做玻璃）：
  - 左上角是科目选择，最宽 220，名字太长时省略；右上角是更新时间和「删除」。
  - 下面是标题和正文，点一下就能改。
- **空状态**：一条备忘都没有时，只显示一行弱色文字，和知识缺口页的做法一样。
- **iPad**：竖屏也保持两栏。侧栏展开时编辑区比较窄，可以收起侧栏。触屏上按钮常显，不依赖悬停；
  拖动排序要先长按；屏幕键盘弹出时，正在编辑的那一行要在键盘上方。

## 设计

### 数据（数据库 v20）

新表 `memos`：

| 列 | 说明 |
| --- | --- |
| `id` | 自增整数主键 |
| `title` | 标题，可以为空；为空时列表里用正文第一行顶替 |
| `body` | 正文，纯文本 |
| `category_id` | 科目，`REFERENCES categories(id) ON DELETE SET NULL`，和知识缺口一样：删掉科目，备忘归到「未分类」 |
| `sort_order` | 同一科目内的顺序 |
| `created_at` / `updated_at` | 创建时间和更新时间 |

再加上同步迁移补齐的 `sync_id` 等列。

- 长度：标题最多 60 字，正文最多 10000 字。超长时拒绝保存并说明原因，不悄悄截断（业务规则里已有这一条）。
- 新建的备忘排在这一科的最后，列表自动滚到它；换科目后排到新科目的最后。
- 迁移照 v19 的做法：先建表；同步结构由那一步可以重复执行的同步迁移按清单补齐（加身份列、回填、入队、触发器）；
  最后把版本号推到 20，让旧版应用拒绝打开新库。升到 v20 后不能回退。
- 启动检查和备份检查共用的外键契约里加上 `memos`。

### 同步

- 把 `memos` 登记进同步表清单。同步字段：标题、正文、科目（引用科目）、顺序、创建时间。
- **更新时间**：`updated_at` 仍然不作为同步字段，免得两台改了同一条的不同地方时，同步日志里多出一条「更新时间」冲突。
  但两台显示的更新时间要一致：收到对方的修改时，把本机的 `updated_at` 设成那次修改在对方设备上发生的时刻
  （同步记录里本来就带着每个字段的修改时刻）。具体做法在阶段 2 定，目标是不新增同步列。
- **排序归一**：同步之后，同一科目内如果出现相同的顺序号，按「顺序号、创建时间、sync_id」重新编号，和任务、倒计时的做法一样。
- **同步文件格式从 2 升到 3**，能读 1 到 3。这是这次必须做的：现在的同步遇到不认识的表时，会把那条记录跳过、照常往下读，
  以后也不会再补。不升格式的话，先装新版的那台写的备忘录，永远到不了还没更新的那台。升格式之后，旧版读到格式 3 的文件会停下来等更新，不跳过任何内容。
- **删科目**：两台各自把这一科的备忘置为未分类。现有"删科目时刷新相关页面"的地方加上备忘录。
- **正在编辑时收到对方的修改**：编辑框里还没改过，就直接显示新内容；已经改了但还没保存，就不覆盖编辑框。
  保存时按"同一字段以后改的为准"处理，输掉的那一版记进同步日志，可以从日志里找回。

### 自动保存与删除

- 停止输入约 1 秒后保存；切换到别的备忘、切到别的页面、iPad 切到后台、退出应用前，都会立即保存。
- 新建后标题和正文都没写就离开，这条自动丢弃，不留下空白备忘。
- 保存失败时，编辑区上方用提示条说明原因，内容留在编辑框里，不会丢。
- 「删除」要二次确认，和知识缺口一致。
- 键盘可以用上下方向键切换选中的备忘。调整顺序只能拖动，和侧栏顺序的取舍一致。
- 拖动只在同一科目内有效；「全部」里也只能在组内拖。要换科目，用编辑区左上角的科目选择。

### 接线

- C++ 新增 `MemoService`（单例，放在 `src/services`）：提供读取列表、新建、修改标题/正文/科目、删除、排序；
  发出 `memosChanged` 和 `operationFailed` 信号。
- `main.cpp` 注册 `memoService`；`main.qml` 把它传给 `MainWindow` 的 `memoServiceRef`；页面是 `qml/views/MemoView.qml`。
- 侧栏新入口 `memo`：文字「备忘录」，标记字「备」。老用户保存过侧栏顺序的，`AppSettings::normalizeSidebarOrder` 会把它补在最后。
- 科目新增、改名、改颜色、删除时页面跟着刷新（`categoriesChanged`）。
- 对比度门禁的页面清单加上 `memo`。

### 备份与恢复

- 备份是整库快照，自然带上备忘录。
- 恢复检查：v20 及以后的备份要求有 `memos` 表（结构和外键都要对）；更早的备份不要求，恢复后由迁移建一张空表。

## 验收

- **数据**：新建、修改、删除、排序；删掉科目后备忘变成未分类；超长被拒绝而不是被截断；v19 的库升到 v20 后数据完整。

  删科目；排序撞号；旧版读到格式 3 会停下，且不会往前移动读取进度；更新后补齐。
- **备份**：v19 的备份能恢复到 v20；v20 的备份连同备忘录一起恢复；缺少 `memos` 表的 v20 备份被拒绝。

- **真机（日常使用）**：Mac 和 iPad 上用拼音新建、修改备忘，另一台能看到；iPad 浮动键盘、停靠键盘下光标不被挡；

## 风险

- **两台没联网时都改了同一条的正文**：以后改的那版为准，另一版进同步日志，要手动从日志里找回。第一版不做文本合并。
- **只升级了一台（10-03 阶段 5 前的状态，已解除）**：Mac 先升到 v20，iPad 当时还是 v19。Mac 写出格式 3 之后 iPad 会停下等更新，
  Mac 的所有改动（不只是备忘录）都要等阶段 5 装好后才到 iPad；iPad 自己的改动照常传到 Mac。不跳过、不丢。
  iPad 超过 14 天没更新读取进度时，Mac 会把它当作不再使用、清理已有快照兜底的旧批次；iPad 回来后从快照合并追上，是合并，不是整库替换。
- **iPad 竖屏两栏偏窄**：侧栏展开时编辑区约 268 宽，可以收起侧栏。以后需要再做单栏。
- **iPad 签名**：阶段 5 换了新描述文件，10-10 21:37 到期。之后重签只能从这个分支（或合入后的 `main`）构建 v20，不能再装 `main` 上的 v19。
