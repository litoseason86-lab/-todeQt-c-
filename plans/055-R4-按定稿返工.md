# 055-R4：iPad 原生界面按定稿返工（主会话自己做）

2026-10-11 用户在 iPad 上装 `459db2e`（F2、R1–R3 全部合入）后整体否决：窄窗点底部标签栏仍崩溃，宽窗设置页左栏点了不切换，各页与设计稿第 3 版相差甚远。用户要求不再分发，由主会话自己核验并返工。

## 目标与验收

- 13 页宽、窄两种尺寸在 iPad 上的实际截图，与定稿（`.superpowers/ipad-055/round3/project/*.dc.html`，按 `canvas.json` 尺寸用无头 Chrome 渲染）并排对照：结构、元素取舍、文案、配色、卡片与控件样式一致。
- 窄窗点底部标签栏、宽窄来回切换不崩；宽窗设置左栏点哪组就显示哪组。
- 业务规则仍在 C++ 与 Store，不动数据库、同步与备份格式；Mac 与 iPhone 伴侣页不变。
- 全量 ctest、`swift test`、iOS `--clean-first` 不签名编译通过，零新增告警。
- 交给用户前，主会话自己在真机截图上过完每一页。

## 核验方法

- 调试巡检：应用带 `--ipad-ui-tour` 启动时，在 1210×834（宽）与 375×834（窄）两个窗口里依次切到每一页截图，存进应用的 `Documents/ui-tour/`；`devicectl` 拉回 Mac 对照。只读页面，不写数据（选中页偏好结束后还原）。
- 加 `--ipad-ui-tour-taps` 时，在窄窗口里逐个触发底部标签按钮，复现并验证标签栏崩溃。
- 崩溃以 iPad 上的崩溃日志为准（`devicectl device info files --domain-type systemCrashLogs`）。

## 根因（已查实）

- 窄窗崩溃：崩溃日志为 `-[UITabBarController _viewControllerForTabBarItem:]` 断言，点到的标签在控制器里找不到页面；10-10 与 10-11 同一处。现行外壳的标签标题、放置位置、显隐都随窗口宽窄变化。
- 设置左栏：宽窗用 `List(selection:)` 放在 `HStack` 里，点按不改选中。
- 观感：计划写了「控件以系统组件为准」，各页多用系统默认的菜单选择器、带分隔线的列表与 Form，与定稿的白卡片、胶囊按钮、混排数字差得远。

## 步骤

1. 巡检工具；装机拿到现状截图与崩溃复现。
2. 修窄窗崩溃与设置左栏切换，巡检确认。
3. 按定稿 CSS 做公共组件（页头、卡片、胶囊按钮、列表行、分段胶囊、数字排版）。
4. 逐页返工：外壳 → 今日任务 → 仪表盘 → 专注 → 今日专注与补录 → 本周 → 课表 → 知识缺口 → 备忘录 → 倒计时 → 专注历史 → 数据统计 → 废纸篓 → 设置。每页巡检截图对照通过再做下一页。
5. 全量验证，装机交用户。
