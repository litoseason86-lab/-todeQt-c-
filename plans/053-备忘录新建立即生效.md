## 一、需求目标

用户原话（2026-10-06）：点「新建 → 新建备忘录」之后，左侧对应分类下面应该直接出现一条新建的备忘，创建在点菜单项的那一刻就完成，不是填好内容才完成；「新建分类」同样，点下去分类就出现在上面的分类胶囊里，不用填写内容之后才创建。

现状的问题：两项都只开一份界面草稿，写下第一个字、自动保存后才写库。所以点完新建，列表里看不到新的一条（截图里编辑卡显示「未分类 / 标题」，左边列表没变），新分类的胶囊也要等写了字才出现。

### 验收条件

1. 点「新建 → 新建备忘录」：立即在数据库建一条标题、正文都为空的备忘（只调一次 `createMemo("", "", 科目)`），科目跟着当前筛选（「全部」「未分类」下是未分类）。它马上出现在列表里该组的最后，被选中并滚进可视区，光标在标题框里、不画焦点环；不打字也不会消失。
2. 点「新建 → 新建分类…」：挑一个还没写过备忘的科目（或「新建科目…」输入名字确认）的那一刻，在这一科立即建一条空备忘。上面的分类胶囊里马上多出这个科目，列表里出现这一组和这一条并选中；正筛着别的科目时筛选回到「全部」（沿用现有规则）。
3. 之后打字只更新这一条（`updateMemo` 只带改过的字段），不会再新建第二条。
4. 列表里标题和正文第一行都是空白的备忘显示「新备忘录」，不是一行空白；删除确认框里同样写「新备忘录」。数据库里的标题仍是空的。
5. 新建前先保存当前这条；当前这条保存失败（例如正文超长）时不新建，内容和提示留着。新建本身失败（数据库未打开、科目已被另一台删掉等）：显示服务给的原因，选中项和筛选都不变。
6. 空备忘和普通备忘一样：离开不丢弃，删除要确认，确认后删掉这条记录。
7. 「另存为新备忘」（另一台删掉了正在改的那条）照旧能用；保存失败时文字和「另存为新备忘」「放弃修改」两个出口都还在。
8. 业务规则文档的「备忘录」一节改成新行为；全量离屏回归通过，Mac 全量构建 0 告警，iOS 不签名编译通过。

## 四、实现方案

### 4.1 新建：`createNewMemo(categoryId)`（替换 `startDraft`）

「新建备忘录」、挑好科目、建好科目三处都调它。参数省略时科目取 `Math.max(0, root.filterCategoryId)`。顺序：

1. `if (!root.saveNow()) return false;`：先保存当前这条，失败就不新建（内容和提示留着）。
2. 没有服务就返回 false。
3. `root.setError("")`，`root.saving = true`，`var id = memoServiceRef.createMemo("", "", target)`，`root.saving = false`。
   `saving` 为真时 `memosChanged` 触发的 `reload()` 会直接返回，`operationFailed` 照常写进提示；和 `writeEdits` 现在的写法一致。
4. 失败（`!(id > 0)`）：提示为空时补「新建备忘录失败。」；选中项、筛选、编辑区都不动；返回 false。
5. 成功：正筛着别的科目（`filterCategoryId >= 0 && filterCategoryId !== target`）时改成 -1；`selectedId = id`；
   **先**用 `readEditor({title: "", body: "", categoryId: target, updatedAt: ""})` 把编辑区装成这条空备忘（基准值也是空），**再** `reload()`。
   - 顺序不能反。`reload()` 读失败时直接返回，编辑区会留着上一条的内容，而 `selectedId` 已经是新编号，上一条的内容就会被当成新备忘的写进去。
     反过来先 `reload()`、失败后再 `readEditor`，又会把 `reload()` 刚设的读取失败提示和「重试」清掉：`readEditor` 无条件 `setError("")`（第 162 行）。
   - 读成功时，`reload()` 发现编辑区不脏，会用库里的这一条再装一次（内容相同、带上更新时间），同时重建胶囊和列表。
   - 读失败时，编辑区是空的新备忘，读取失败的提示带「重试」；点「重试」重读成功后，列表出现这一条且仍选中它，不会再调一次 `createMemo`。
6. `revealSelected()`，然后 `titleInput.forceActiveFocus(Qt.OtherFocusReason)`（光标进标题、不画焦点环，同现在的 `startDraft`），返回 true。

「另一台已删除」状态（`remoteDeleted`）：有未保存的修改时 `saveNow()` 返回 false，不新建，文字和两个出口都留着。
用户把文字改回原样（不脏）时 `saveNow()` 返回 true，新建照常进行，`readEditor` 会清掉 `remoteDeleted`。
这和现在在这种状态下点别的备忘一样：没改过的内容不受保护，删除前的内容在同步日志里能找回。不额外加拦截。

调用点：`newMenu.onFinished` 的 `"memo"` 分支；`subjectPicker.onFinished` 的科目分支；`categoryPrompt.onCreated`（保留先 `reload()`，再 `createNewMemo(categoryId)`）。注释改成「点下即建」的说法。

### 4.2 去掉草稿状态

新建不再经过草稿，`drafting` 只剩「另存为新备忘」在用。把那条路径改成直接新建（4.3），删除整个草稿状态：

- 删除属性 `drafting`、`draftReturnId` 和函数 `discardDraft()`、`startDraft()`；`clearEditor()` 里对这两个属性的赋值一并删掉。
- `hasEditor: selectedId > 0`；`libraryEmpty: allMemos.length === 0`。另一台删掉正在改的那条时，`selectedId` 仍是原编号，编辑卡照常显示，和现在一样。
- `writeEdits()`：删掉 `drafting` 的新建分支和「空草稿跳过」，只走 `updateMemo`；`moved` 只看 `changes.categoryId !== undefined`；删掉「编号 0 换成存下的编号」。
- `requestDelete()`：`pendingId = selectedId`；`confirmDelete()`：删掉编号 0 的分支，`id <= 0` 直接返回的保护保留。
- `selectMemo()`、`requestMoveCategory()`、`moveCategoryPopup.onPicked`、行的 `selected` 去掉 `drafting` 条件。
- `reload()`：删掉末尾 `if (root.drafting) {...}` 分支；`dropMissingEditorCategory()` 保留，仍给另一台已删除的那条用，注释删掉草稿的说法。
- `categoryOptions()`：去掉 `id === root.editorCategoryId ||`（只为草稿存在）。现在编辑区里的备忘都已在库里，它的科目本来就算「写过备忘」。
  唯一的例外是「另一台已删除」状态：被删的那条可能是这一科最后一条，这时这一科会出现在「新建分类」的可挑列表里。
  挑它就是在这一科新建（要先过 `saveNow()`，见 4.1 末尾），结果正确，不用特殊处理。同步改 `memoCategoryOptions` 上面的注释。
- 清理所有提到「草稿」的注释，改成现在的行为，保持中文注释。

### 4.3 「另存为新备忘」直接新建

`saveDeletedAsNew()` 改为：

1. 不在另一台已删除的状态，或没有服务，就返回。
2. 提交输入法组合（`inputMethodRef.commit()`），停掉 `saveTimer`。
3. 正文超长：提示「正文超出 %1 字，没有保存。」，返回（同 `writeEdits`）。
4. `saving = true`，`createMemo(editorTitle, editorBody, editorCategoryId)`，`saving = false`。
5. 失败：提示为空时补「保存失败，编辑内容仍保留在这里。」；`remoteDeleted` 仍为真，文字和两个按钮都留着，可以再点一次。
6. 成功：`remoteDeleted = false`，`selectedId = 新编号`，基准值设为当前编辑内容，`reload()`，`revealSelected()`。

`dropMissingEditorCategory()` 已经在进入删除状态和之后每次 `reload()` 时把不存在的科目改成未分类，所以这里存得下。

### 4.4 空标题的显示

- 列表行标题：`row.memoTitle.trim().length > 0 ? row.memoTitle : qsTr("新备忘录")`，`Accessible.name` 用同一个值。用同一个辅助函数或只读属性，不要复制两份判断。字色、字重和普通标题一样。
- 删除确认框：`requestDelete()` 算出的 `pendingTitle` 为空时写「新备忘录」，和列表一致。
- 摘要行、组头、编辑区不变：编辑区标题框仍显示占位「标题」。服务的 `displayTitle` 不改。

### 4.5 不变的部分

分类模型（分类就是写过备忘的科目）、`subjectPicker` 和 `NewCategoryPrompt` 的交互、「新建」菜单的两项和文字、新建后筛选回到「全部」的规则、自动保存时机、改分类入口、同步格式都不变。

## 六、边界与异常

| 情况 | 期望 |
| --- | --- |
| 「全部」或「未分类」下新建 | 建在未分类；「未分类」胶囊出现（原来没有时），列表里「未分类」组末尾多一条 |
| 筛着科目 2 时「新建备忘录」 | 建在科目 2，筛选不变 |
| 筛着科目 2 时「新建分类」挑科目 3 | 建在科目 3，筛选回到「全部」，胶囊 3 出现 |
| 一条备忘都没有时新建 | 左栏和分隔线出现，列表一条，编辑卡显示 |
| 连点两次「新建备忘录」 | 建两条空备忘（每次点击都算一次新建）；不去合并或删掉前一条 |
| 当前这条有未保存的修改 | 先保存（只发改过的字段），再新建 |
| 当前这条保存失败（正文超长、写库失败） | 不新建，提示和内容留着 |
| `createMemo` 失败 | 显示原因（服务的 `operationFailed`，没有就用兜底文字），选中、筛选、编辑区不变，不多出列表行 |
| 新建科目成功但建备忘失败 | 科目留在科目管理里（和现在不写字就离开一样），没有胶囊，显示原因 |
| 建好后 `reload()` 读取失败 | 编辑区是空的新备忘（编号是新的），读取失败的提示和「重试」都在；不能把上一条的内容带进新备忘。重试成功后列表出现这一条、仍选中它，不再新建 |
| 新建后什么都不写就切走、切页、退出 | 这条空备忘留着，不写库（不脏） |
| 空备忘被删除 | 确认框写「新备忘录」，确认后 `deleteMemo(编号)` |
| 另一台已删除、本机有未保存修改时点新建 | `saveNow()` 失败，不新建（同现在） |
| 另一台已删除、用户已把文字改回原样时点新建 | 照常新建，同现在在这种状态下点别的备忘（见 4.1 末尾） |
| 「另存为新备忘」失败 | 留在已删除状态，文字和两个按钮还在 |
| 同步 | 空备忘立即写库并进入同步队列，按现有同步节奏发到另一台，不用等打字。原来「免得另一台先收到空备忘再收到删除」的考虑，按用户要求放弃，文档写明 |

`docs/业务规则.md`「备忘录」一节：第 94 行改成「挑好或建好的那一刻在这一科建一条空备忘，分类胶囊马上出现」，删掉「新分类在写下第一条后才留下……」；第 96 行改成「点新建立即写库建一条空备忘（标题、正文都空），列表里显示『新备忘录』；离开不丢弃，删除照常确认。空备忘立即进入同步队列，按现有同步节奏发到另一台」。不要写成「立刻出现在另一台」，同步有自己的周期。其余条目只改和草稿相关的措辞，比如第 102 行的标签列表加上「新备忘录」。
