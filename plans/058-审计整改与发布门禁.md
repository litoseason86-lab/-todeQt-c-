## 审计结论

当前没有证据支持 P0：没有发现必现崩溃、即时全库损毁或核心安全突破。当前 `main` 的既有动态基线记录为 `~/pt-audit` 构建成功、CTest `132/132` 通过；这证明现有测试契约通过，不等于真实 iCloud、双设备并发恢复、VoiceOver、Dynamic Type 或 Instruments 性能已验证。

必须作为发布门禁处理的两项是：

1. `SyncController::finishRestore()` 在 `beginEpochAfterRestore()` 失败后仍执行 `startEngine()`，形成恢复成功但新纪元未建立时继续同步的 fail-open 路径。
2. `SyncController::setEnabledState()` 在 `QSettings::sync()` 后不检查 `status()`。写入失败时当前进程可能仍显示关闭，但持久状态未改变；如果随后退出，重启读到旧值并开启同步是可能结果。写入彻底失败时，任何仅存在于内存的“关闭意图”都无法保证跨进程保留，验收必须明确这条物理边界，不能承诺存储不可写时仍能持久化。

近期 P2 是快照和同步状态机：

- `acceptFolder()` 写书签和路径后不检查持久化结果就切换运行态；
- `exportSnapshot()` 跨多张表读取，没有整体只读事务，`SELECT` 或 `readRecord()` 失败时仍返回部分快照；
- 高 epoch 快照解析失败后进入 `WaitingForSnapshot`，当前路径没有明确的换候选、重写请求或有界重试；
- `MainWindow.qml` 的 `Qt.callLater()` 回调只在分发时检查备份恢复阻断状态，执行时没有二次检查。
- `LocalSyncFolder::read()` 和 iOS `IosSyncFolder::read()` 没有按文件类型设置应用层大小上限，JSON 解析前可把整个输入读入内存。
- `BackupService::prepareForShutdown()` 对活动 `QFutureWatcher` 调用无超时的 `waitForFinished()`；后台备份 worker 若永久阻塞，退出也会无界等待。

其余审计结论经过复核后的边界如下：

- “磁盘满/I/O 错误导致单条回滚后整批提交并永久不一致”被过度推断。毒丸记录跳过是现有设计，`badRecordIsSkippedWithoutBlockingBatch` 已通过；本计划不把它改成整批回滚。需要补的是按错误类型区分可重试本机故障与不可重试数据错误，不能破坏毒丸隔离。
- 普通损坏批次永久丢失、Gap 请求每轮重复写、MCP 连接永久占满、例行删除无撤销、Loader Binding 必然失效等说法没有被现有代码/测试支持，不纳入修复范围。
- 两设备离线并发恢复产生相同 epoch 的因果推导成立，但尚未在真实双设备时序中动态复现；列为 P2 设计风险，不能写成已发生的数据丢失。
- 夏令时文件名排序最多是 P3：当前创建出来的 `keepPath` 受无条件保护；例行删除“当天实例不进废纸篓”是已写入业务规则的设计取舍。

### 阶段 1 补充验收：恢复失败的安全分类

主审核对发现，`restoreCompleted(false, message)` 同时覆盖恢复未开始、安全回滚与回滚失败，不能单凭该布尔值解除同步阻断。本项列入阶段 1，尚未实施或验收：

- 保留界面既有 `restoreCompleted` 通知；新增仅面向同步装配的 `restoreSyncCompleted(bool success, bool safeToResume)`。仅实际通过准备回调的恢复操作发送，忙碌拒绝和准备拒绝不得结束正在执行的另一项恢复。该内部通知先于界面通知发送，不从全局 busy 标记推断某次请求是否获得准入。
- `SharedApp` 改用该内部通知调用 `finishRestore(success, safeToResume)`，移除旧完成信号的同步连接。失败且安全恢复原状态才恢复先前日志；失败且无法确认原状态时保留当前 prepared 日志、阻断同步，要求重新执行恢复。直接调用控制器的已有测试可沿用默认 `safeToResume=true`；真实装配必须显式传递判定结果。
- 同步恢复的回滚结果以 `restoreFromPreRestoreSnapshot()` 实际返回值为准；异步恢复以实际 `rolledBack` 为准。安装失败而原库未换，仅在重新打开原库成功时判定可恢复运行；不得从错误文案推断状态。

```cpp
// 发送与接收共用同一字节预算；先拒绝超限内容，避免本机确认发布后对端却一律拒读。
SyncFolder::Error writeWithinBudget(SyncFolder& folder, const QString& path, const QByteArray& bytes)
{
    const qint64 maxBytes = SyncFiles::maxBudgetForPath(path);
    if (maxBytes <= 0) {
        return {SyncFolder::ErrorKind::Io, QStringLiteral("不支持的同步文件路径：%1").arg(path)};
    }
    if (bytes.size() > maxBytes) {
        return {SyncFolder::ErrorKind::Io,
                QStringLiteral("同步文件大小超出预算上限，未写出：%1（%2 > %3 字节）")
                    .arg(path).arg(bytes.size()).arg(maxBytes)};
    }
    SyncFolder::Error error;
    if (!folder.write(path, bytes, &error) && error.ok()) {
        return {SyncFolder::ErrorKind::Io, QStringLiteral("写入同步文件失败：%1").arg(path)};
    }
    return error;
}
```

四个替换点：

- `createMarker`：直接返回 `writeWithinBudget(*m_folder, SyncFiles::markerFileName(), SyncFiles::encodeMarker(marker))`，删除旧的局部 error 和直接 write。

- `writeSnapshot`：路径和位置不变，改为 `result.error = writeWithinBudget(*m_folder, result.path, SyncFiles::encodeSnapshot(snapshot))`。
- `writeCursor`：直接返回 `writeWithinBudget(*m_folder, joinPath(SyncFiles::deviceDirectory(cursor.device), SyncFiles::cursorFileName()), SyncFiles::encodeCursor(cursor))`。

    case ...13: return .footnote
    case ...15: return .subheadline
    case ...17: return .body
    case ...20: return .title3

private struct ScaledSystemFont: ViewModifier {
    @ScaledMetric private var size: CGFloat
    let weight: Font.Weight
    let design: Font.Design

    init(size: CGFloat, weight: Font.Weight, design: Font.Design) {

    func body(content: Content) -> some View {
        content.font(.system(size: size, weight: weight, design: design))
    }

```cpp
void PendingDeletion::setAutomaticCommitSuspended(bool suspended)
{
    if (m_automaticCommitSuspended == suspended) {
        return;
    }
    m_automaticCommitSuspended = suspended;
    if (suspended) {
        m_timer.stop();
    } else if (active()) {
        // 恢复完整撤销窗口，不能让读屏结束后的剩余时间短到无法操作；沿用这次请求的时长。
        m_timer.start(m_activeDelayMs);
    }
}
```

在 requestTask/requestSession 原来 `m_timer.start(m_delayMs)` 的两处分别替换为：

```cpp
m_activeDelayMs = m_delayMs;
if (!m_automaticCommitSuspended) {

}
```

3. ShellStore 增加以下字段和方法；系统状态由 UI 提供，Core 不导入 UIKit：

```swift
@ObservationIgnored public var onAccessibilityTimeoutSuspensionChanged: ((Bool) -> Void)?
@ObservationIgnored private var voiceOverEnabled: Bool?
@ObservationIgnored private var toastDurationMilliseconds: UInt64 = 5000

public func setVoiceOverEnabled(_ enabled: Bool) {
    guard voiceOverEnabled != enabled else { return }
    voiceOverEnabled = enabled
    onAccessibilityTimeoutSuspensionChanged?(enabled)
    scheduleToastTimeout()
}

// 读屏时保留带动作的提示，避免尚未到达撤销按钮就自动提交；纯信息提示仍按原时长退出。
private func scheduleToastTimeout() {
    toastTask?.cancel()
    toastTask = nil
    guard let current = toast,
          !(voiceOverEnabled == true && current.actionTitle != nil && toastAction != nil) else { return }
    let id = current.id
    let duration = toastDurationMilliseconds
    toastTask = Task { [weak self] in
        do { try await Task.sleep(for: .milliseconds(duration)) }
        catch { return }
        guard self?.toast?.id == id else { return }
        self?.retireToast()
    }
}
```

showToast 保留 retireToast、UUID 和动作回调赋值，记录传入 durationMilliseconds 到 toastDurationMilliseconds，然后调用 scheduleToastTimeout，替换原来直接建立 Task 的部分。retireToast/triggerToastAction 不改，提示被替换或手动关闭仍触发原退场，点击动作不触发退场。
